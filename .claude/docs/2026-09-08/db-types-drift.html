먼저 알아둘 것

이 문서의 결론이 기대는 사실 셋. 코드·스펙에 없던 것이라 먼저 깐다.

타입은 실행되지 않는다. TypeScript 는 코드를 실행하기 전에 검사만 하고, 검사가 끝나면 타입 정보를 전부 지운 뒤 JavaScript 로 바꿔 돌린다. 그래서 타입 파일이 틀려도 프로그램은 그냥 돈다. 틀린 것을 알려주는 시점이 커밋 전뿐이다.

타입 파일은 손으로 쓰는 게 아니다. src/types/database.ts 2208줄은 Supabase 가 실제 DB 를 읽어 자동으로 만든 것이다. 사람이 고치면 다음에 다시 만들 때 지워진다. 그래서 "고친다"가 아니라 "다시 만든다"가 맞는 동작이다.

연결하지 않으면 아무 일도 안 한다. 타입 파일이 있는 것과 그것을 DB 접속에 물리는 것은 별개다. 물리지 않으면 파일은 그냥 문서로 남고, 쿼리는 검사 없이 통과한다. 이번에 발견한 것이 이 상태였다.

묻지 않고 정했다. 되돌리기가 비쌈 이상인 항목은 오너 확인 칸을 비워 뒀다.

C 는 별도 슬라이스로 잡는 편이 낫다. 31개 중 몇 개가 진짜 버그인지 아직 안 세어 봤고, 고치는 중에 동작이 바뀌면 오너 확인이 필요한 것이 섞여 나올 수 있다.

5

알고만 있으면 되는 것

가정틀리면 무엇이 깨지나확인 방법
개발 DB 스키마가 live 보다 앞서 있다 타입에는 있는데 live 에 없는 함수를 부르면 배포 후 실행 중에 실패한다. 지금 take_expire_due 가 그 상태다 마이그레이션을 live 에 올린 뒤 pnpm db:types 재실행
어긋남 검사는 표만 본다 컬럼을 추가·삭제하는 마이그레이션은 안 잡힌다. alter table add column 은 표 이름이 안 바뀌기 때문 컬럼 대조까지 넣으려면 검사를 늘려야 한다
타입 파일을 손으로 고치지 않는다 고쳐도 다음 pnpm db:types 에서 지워진다 검사가 자동 생성 표식을 확인한다
server-only 는 이미 package.json 에 올라갔다 의존성만 있고 admin.ts 의 import 는 아직 미커밋이다. 그 상태로는 아무것도 막지 않는다 같이 커밋하면 해소된다

지뢰

  • 이번 세션의 변경이 다른 커밋에 딸려 올라갔다. server-only 가 8a11209f(결제 게이트 검사) 에 섞여 들어갔고, lock 파일이 빠져 dev 배포가 ERR_PNPM_OUTDATED_LOCKFILE 로 깨졌다. ae904ca6 에서 고쳤다. git add -A 로 묶으면 같은 일이 또 난다.
  • vitest.config.ts 에 server-only 를 빈 파일로 바꾸는 줄을 넣었다. 테스트에서만 적용되고 실제 빌드는 그대로 막는다. 이 줄을 지우면 서버 모듈을 쓰는 테스트가 전부 실패한다.
  • 타입 파일 2208줄 중 실제로 쓰이는 것은 아직 없다. 결정 2 에서 A 를 고르면 계속 그 상태로 남는다.

근거로 쓴 것 — 커밋 ae904ca6 기준. 미커밋 변경 7개: CLAUDE.md, package.json, src/lib/supabase/admin.ts, src/types/database.ts, vitest.config.ts, tests/ops/db-types-drift.test.ts(새 파일), tests/permission/server-only-key-boundary.test.ts(새 파일), scripts/db-types.mjs(새 파일).

이 문서가 하지 않는 것 — 인물 이미지가 있는 프로젝트의 목록 화면을 보지 않았다. 확인한 것은 이미지가 없는 계정 한 곳뿐이고, 거기서는 A 와 B 의 결과가 같다. 타입 오류 31개 중 30개는 종류만 세었고 개별 판정하지 않았다. live DB 스키마를 조회하지 않았다. 썸네일 버그가 언제 들어왔는지 git 이력을 추적하지 않았다.
