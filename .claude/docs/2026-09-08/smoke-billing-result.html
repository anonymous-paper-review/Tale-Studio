돈 드는 검사 — Orca 실측

실결제 자동화를 시도했고, 어디까지 되고 어디서 막히는지 확인했다.

단계Orca 로 되나실측
로그인 · 페이지 열기○기존 smoke 방식 그대로
"Take 충전" 버튼 누르기△orca click 은 React onClick 을 안 부른다(서버 호출 0건). orca eval 로 button.click() 하면 된다
Paddle 결제창 열림○iframe 1개 · window.Paddle 로드 확인
결제창 안 요소 읽기○접근성 트리에 iframe 내부가 잡힌다 — 이메일·국가·계속·카드번호 전부 ref 로 보인다
결제창 안 버튼 누르기○"계속" 클릭으로 카드 입력 단계까지 진입
카드번호 입력✗여기서 막힌다. orca fill 이 "Filled" 를 반환하는데 값이 안 들어간다. 포커스만 옮겨간다

왜 안 되나

Paddle 카드 입력란은 결제창 iframe 안의 또 다른 iframe이다(카드 정보가 우리 페이지에 닿지 않게 하는 구조 — PCI 범위를 밖으로 빼는 그 장치다). 접근성 트리에는 보이지만 값을 넣는 경로는 막혀 있다. 어제 사람 손으로 한 것은 다른 브라우저 도구였고, 그건 자동화 스크립트로 못 옮긴다.

ref 가 화면이 다시 그려질 때마다 밀리는 것도 확인했다 — "계속" 을 누르자 유효기간 칸이 e62 에서 e59 로 바뀌었다. 스냅샷과 입력 사이에 클릭이 하나라도 있으면 엉뚱한 칸에 들어간다.

다음 수

  • 웹훅을 직접 쏘는 방식. 실제 결제창 대신 우리가 서명한 알림을 dev 로 보내 적립 → 영상 생성 → 차감까지 돈다. 결제창 자체는 못 보지만 그 뒤 전부를 본다. 어제 이미 이 방식으로 8건을 돌린 실적이 있다.
  • 결제창은 사람이. 라이브 키 전환 직후 한 번만 손으로. 어차피 그때는 실 카드라 자동화 금지 대상이다.

둘을 합치면 "결제창이 뜨고 카드가 통과하는가"만 사람 몫으로 남고 나머지는 자동이다. 오너 판단이 필요하다.
