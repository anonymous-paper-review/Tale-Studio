src/lib/ops-alert.ts:28-46export async function sendOpsAlert(alert: OpsAlert): Promise<void> {
  const url = process.env.DISCORD_ALERT_WEBHOOK_URL
  const line = `${LEVEL_PREFIX[alert.level]} [tale · ${environmentLabel()}] ${alert.title}`
  const content = clip(alert.body ? `${line}\n${alert.body}` : line)
  if (!url) {

    return
  }

    if (!res.ok) console.error('[ops-alert] discord responded', res.status)
  } catch (err) {
    console.error('[ops-alert] send failed', err instanceof Error ? err.message : err)
  }
}

확인한 것 / 안 한 것

왼쪽은 실제로 돌렸다. 오른쪽은 안 돌렸거나 흉내로만 봤다.

돌린 것

  • 단위 23건 tests/paddle-webhook.test.ts, 메모리 장부. 테스트 이름이 곧 약속 문장이다(pnpm test:ledger 로 같은 목록이 나온다):
    1. Paddle이 보낸 것이 아니면(서명이 틀리면) 받지 않고 장부에 아무것도 넣지 않는다
    2. 서명이 맞아도 5분 넘게 지난 알림은 받지 않는다(재전송 공격 방어)
    3. 같은 알림이 몇 번 와도 Take는 한 번만 들어가고 플랜도 한 번만 바뀐다
    4. 받은 알림 원문은 처리 성공·실패와 무관하게 전부 남는다
    5. 알림 처리 중 오류가 나면 Paddle에 "실패"로 답해 다시 보내게 하고, 재전송에서 처리되면 "성공"이다
    6. 알림에 어느 워크스페이스 결제인지 표시가 없으면 넣지 않고 원문만 남긴다
    7. 알림에 적힌 상품이 우리 상품 목록에 없으면 넣지 않고 원문만 남긴다
    8. 팩 결제 알림이 오면 그 팩의 Take가 결제일부터 12개월 유효로 들어간다
    9. 무료 워크스페이스에 이미 충전 기록이 있는데 팩 결제 알림이 또 오면 Take는 들어가되 경보가 울린다
    10. 구독 첫 결제 알림이 오면 플랜이 그 플랜으로 바뀌고 포함 Take가 결제 주기 끝까지 유효로 들어간다
    11. 갱신 결제 알림이 오면 그 주기 포함 Take가 다시 들어간다
    12. 구독을 취소해도 낸 기간이 끝날 때까지는 플랜과 Take가 유지되고, 끝나면 무료로 돌아간다
    13. 갱신 결제가 실패하면 그 즉시 무료 플랜으로 돌아가고 그 주기 Take는 들어가지 않으며, 재시도가 성공하면 다시 그 플랜으로 돌아가고 Take가 들어간다
    14. 플랜이 바뀌었다는 알림이 오면 플랜 표시를 바꾼다. 이미 들어간 Take와 충전 Take는 건드리지 않는다
    15. 환불 알림이 오면 그 결제로 들어간 Take를 회수한다. 이미 써서 모자라면 잔액이 음수가 된다
    16. 부분 환불이면 환불 금액 비율만큼 회수한다
    17. 부분 환불이 여러 번 와도 회수 합은 그 결제로 들어간 양을 넘지 않는다
    18. 같은 환불 알림이 두 번 와도 회수는 한 번이다
    19. 아직 승인되지 않은 환불 요청은 회수하지 않는다
    20. 카드사 분쟁(차지백) 알림도 환불과 똑같이 처리한다
    21. 처리 실패·워크스페이스 없음·상품 매핑 없음·갱신 결제 실패는 경보로 간다
    22. 알 수 없는 종류의 알림은 원문만 남기고 성공으로 답한다
