## 2. 내 이미지 한도 6개 — 거절 안내가 뜨고, 끝나면 다시 되는가 (필수)

1. Director 스토리보드에서 서로 다른 샷 7개의 "실사 생성"을 **빠르게 연속으로** 누른다(일괄 말고 개별 버튼).
2. 7번째에서 토스트: **"이미지는 동시에 6개까지 생성할 수 있어요. 진행 중인 생성이 끝나면 다시 시도해 주세요."**
3. 그 뒤 아무것도 자동으로 일어나지 않는다(자동 재시도 없음). 7번째 샷은 그대로 비어 있다.
4. 앞의 것 하나가 완료된 뒤 7번째를 다시 누르면 시작된다.

통과: 2·3·4 전부. 실패: 7개가 다 시작됨(한도 안 걸림) / 토스트에 "자동으로" 문구 / 다시 눌러도 안 됨.

## 3. 내 영상 한도 3개 + 일괄 이어가기 (필수)

**3-A 개별**
1. 영상 "생성"을 서로 다른 샷 4개에 연속으로 누른다.
2. 4번째에서 토스트: **"영상은 동시에 3개까지 생성할 수 있어요. 진행 중인 생성이 끝나면 다시 시도해 주세요."**
3. 하나 끝난 뒤 4번째를 다시 누르면 시작.

**3-B 일괄 (9/9 결정 ① — 창 닫아도 계속)**
1. 영상 없는 샷이 5개 이상인 상태에서 "전체 영상 생성"을 누른다.
2. 3개가 먼저 돌고, 하나 끝나면 4번째가 **자동으로** 시작된다(이건 내 한도 안에서 이어가는 것이라 정상).
3. 도는 중에 브라우저 탭을 닫았다가 2분 뒤 다시 연다 → 진행 표시가 복원되고 계속 돈다.

통과: 3-A 2·3, 3-B 2·3·4. 실패: 3-B에서 3개 뒤에 멈추고 안 이어감 / 탭 닫았더니 멈춤.

## 4. 모두의 자리가 찼을 때 (선택 — dev에서만 가능)

dev 프리뷰의 전체 칸 수는 Vercel의 **dev 환경 `FAL_KEYS`** 합계다(운영 68과 다르다. 9/1 문서 기준 10칸). 그 수를 넘기면:

- 토스트: **"지금 생성 자리가 모두 사용 중이에요. 잠시 뒤에 다시 시도해 주세요."** (자동 시작 문구 없음)
- 영상 일괄이 돌던 중이면 멈추고 같은 토스트. 하나 끝나도 자동으로 안 이어감. "전체 영상 생성"을 다시 누르면 남은 것부터 새로 나간다.

한 계정으로는 내 한도(9) 때문에 10칸을 못 채운다. 두 번째 계정(오너 구글 계정 — 관리자라 개인 한도 없음)으로 이미지 여러 장을 동시에 돌려 채우면 된다. 안 해도 운영 반영 판단에는 지장 없다 — 이 축은 개발 DB 실제 동시 실험(13연결)으로 이미 확인했다(`db-results.json`: 67→68 유지).

## 5. 30분 뒤 확인 (필수)

모든 테스트가 끝나고 30분 뒤, `/queue` 화면과 DB에서 미완료 작업 수를 확인한다. 화면에서 사라졌다는 이유만으로 완료했다고 판단하지 않는다. 남은 작업은 제공자가 계속 생성 중인지, 조회가 끊겼는지, 접수 번호를 받지 못했는지 구분해 기록한다.

2026-09-14 오너 결정: 접수 여부가 불명확한 예약과 사용량은 확인될 때까지 유지한다. 10분이 지났다는 이유만으로 실패 처리하거나 사용량을 돌려주지 않는다. 실제 완료·명시적 실패 처리는 유지한다. 별개로 용량 계산의 기존 30분 창은 이번 수정에서 바꾸지 않았다.
