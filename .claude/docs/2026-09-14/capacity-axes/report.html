서버에서 user_image 축의 generation_submit_rejected_quota 4건을 확인했고, 화면에서는 아래 문구를 DOM으로 관찰했다. 이 자료만으로 거절이 정확히 7·8·9번째 요청과 대응하는지, 거절 뒤 자동 재시도가 0건인지 확인할 수 없다.

화면 토스트 (DOM 텍스트 관찰)이미지는 동시에 6개까지 생성할 수 있어요. 진행 중인 생성이 끝나면 다시 시도해 주세요.

서버가 남긴 거절 기록 — 개인 이미지 축과 한도 값은 확인되지만 개별 요청 순번은 확인되지 않는다.

4. 모두의 자리가 찼을 때

안 함(선택)

기준: dev 전체 칸을 넘기면 "지금 생성 자리가 모두 사용 중이에요" 안내.

전체 칸 초과 브라우저 시험은 하지 않았다. 확인된 FAL 구성은 dev 1계정·10칸, 운영 2계정·34+34칸이며 legacy 키는 실제로 공유된다.

5. 끝난 뒤 멈춘 카드가 없는가

부분 확인

기준: "생성 중"에 멈춘 것 0개인지 확인한다. 30분 대기 후 재확인하는 시험은 이번에 하지 않았다.

최종 큐 화면에서 "진행 중 0"만 확인했다. 따라서 30분 경과 뒤에도 멈춘 카드가 없었다고 판정할 수 없다.
