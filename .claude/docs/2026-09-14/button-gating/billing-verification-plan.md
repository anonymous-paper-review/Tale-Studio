# Director 중복 차감 검증

기능과 과금 정책은 바꾸지 않고 실제 PostgreSQL에서 요청 반복과 동시 요청의 결과를 확인한다.
개발 DB의 무작위 임시 스키마만 쓰며, 고객 데이터·운영 DB·외부 유료 생성 API에는 쓰지 않는다.
원본 SQL 함수는 스키마와 전역 잠금 이름만 격리용으로 치환해 실행한다.
차감은 원장 행 수가 아니라 해당 작업의 음수 합계로 판단한다.

## 같이 정한 것

- 같은 영상 생성 요청을 다시 보내면 기존 작업을 재사용한다.
- 같은 기존 영상을 동시에 다시 만들면 진행 중인 시도는 하나만 허용한다.
- 같은 일괄 항목을 다시 제출하면 기존 작업을 재사용한다.
- 일반 계정에 잔액보다 큰 사용량을 요구하면 차감하지 않는다.

## 혼자 정한 것

| 검증 동작 | 왜 | 버린 선택지 | 되돌리기 |
|---|---|---|---|
| 같은 작업 차감을 두 번 요청하면 실제 차감 합계를 기록한다 | 원장 자체의 반복 방어를 확인한다 | 원장 행 수만으로 중복 판단 | 쉬움 |
| 다른 요청키로 같은 샷의 새 테이크를 동시에 예약하면 작업 수를 기록한다 | 다른 탭의 독립 요청이 중복 의미로 막히는지 확인한다 | 순차 요청만 확인 | 쉬움 |
| 지급분 두 곳에서 한 번 차감하면 합계가 요청량과 같은지 확인한다 | 정상 분할 차감을 이중 차감으로 오판하지 않는다 | 차감 행이 둘이면 곧 중복이라고 판단 | 쉬움 |

새 정책 결정이나 제품 코드 변경은 없다. 취약점 관측은 결과 JSON과 한국어 보고에 남긴다.
