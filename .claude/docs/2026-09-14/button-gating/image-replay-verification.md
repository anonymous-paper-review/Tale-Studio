# 이미지 요청 재사용과 프로젝트 전환 회귀 검증

## 같이 정한 것

- 기존 일괄 이미지 작업을 기다리면 요청한 샷의 이미지만 반영하고 완료를 알린다.
  - 왜: 일괄 작업의 대표 이미지는 첫 샷이므로 다른 샷에 그대로 쓰면 잘못된 그림을 보여준다.
- 재사용한 이미지 작업의 샷 결과를 읽지 못하면 예전 이미지를 완료 결과로 알리지 않는다.
  - 왜: 새 조회가 실패했는데 로컬에 남은 예전 이미지만 보고 완료라고 할 수 없다.
- 재사용한 이미지 작업의 샷이 아직 완료되지 않았으면 다른 샷의 이미지를 대신 쓰지 않는다.
  - 왜: 일괄 대표 이미지만 있어도 대상 샷의 저장 결과를 확인해야 한다.
- 수동 이미지 생성 중 프로젝트를 바꾸면 이전 이미지의 업로드를 새 프로젝트에 요청하지 않는다.
  - 왜: 생성 응답을 기다리는 동안 사용자가 다른 프로젝트로 이동할 수 있다.

혼자 정한 제품 정책은 없다. 결과 확인에 실패하면 기존 불확실 상태와 상태 확인 동작을 사용한다.

## 수정 전후

위 네 문장으로 테스트를 먼저 추가했다. 수정 전 기존 다섯 테스트는 통과했고 새 네 테스트는 모두 실패했다.

- 다른 샷의 이미지 URL이 반환됐다.
- 저장 결과를 읽을 수 없어도 완료로 반환됐다.
- 대상 샷이 미완료여도 완료로 반환됐다.
- 프로젝트 변경 후 이미지 업로드가 한 번 발생했다.

수정 후 기존 기대값을 바꾸지 않고 아홉 테스트 모두 통과했다. 작업 상태·API 예약·공통 폴링을 포함한 관련 네 파일의 43개 테스트도 통과했다.

실제 유료 생성과 배포는 하지 않았다. 스크린샷과 전체 통합 검증은 상위 작업에서 수행한다.
