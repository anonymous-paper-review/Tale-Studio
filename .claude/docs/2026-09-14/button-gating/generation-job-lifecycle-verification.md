# 생성 작업 반환·삭제 경합 검증 결과

완료 영상의 차감액은 늦은 실패·삭제 요청으로 반환하지 않는다. 진행 중인 작업을 반환할 때에는 차감이 없는 작업도 먼저 종료하므로, 반환 뒤 늦은 완료나 차감을 받지 않는다. 삭제는 종료·반환·삭제를 한 트랜잭션으로 실행한다.

실제 개발 PostgreSQL의 임시 공간에서 새 동작 14개가 모두 통과했다. 기존 170000 반환 함수와 기존의 분리된 반환·삭제 순서에서는 같은 기대 7개가 실패했고 7개가 통과했다. 새 반환 함수로 기존 차감·반환 테스트 20개도 변경 없이 모두 통과했다.

| 경합 | 보완 전 | 보완 후 |
| --- | --- | --- |
| 영상 완료 후 늦은 반환 | 5 Take 반환 | 반환 0, 완료 기록·차감 유지 |
| 반환과 별도 DELETE 사이 늦은 차감 | 작업 삭제 뒤 미반환 5가 남음 | 삭제 후 차감 거절, 미반환 0 |
| 완료 확정과 삭제 경쟁 | 완료 기록 삭제·5 반환 | 삭제 거절, 완료 기록·차감 유지 |
| 진행 중 작업 반환 후 늦은 완료 | 완료 상태로 변경됨 | 실패 상태 유지, 늦은 완료 거절 |
| 차감 없이 반환한 작업의 늦은 차감 | 진행·완료 경로가 열려 있음 | 작업 종료 후 차감 거절 |

완료가 먼저 잠근 경우와 반환·삭제가 먼저 잠근 경우를 각각 확인했다. 차감이 먼저 잠근 작업은 차감 확정 후 전액 반환하고 삭제했다. 삭제가 먼저 잠근 작업의 차감은 삭제 확정 후 거절했다. 대기·실패·취소 작업, 차감 없는 이미지 작업, 이미 없는 작업의 삭제도 통과했다.

삭제 RPC는 실제 삭제했거나 이미 없으면 `true`, 완료 기록을 유지하면 `false`를 돌려준다. 서비스 역할에만 실행 권한을 부여한다. 기존 반환 총액·분할 지급분·환불·만료 계산은 유지한다. 기존 고객 원장은 자동으로 보정하지 않는다.

검증은 고객 데이터가 없는 합성 작업·원장으로 수행했다. 보완 전 삭제 검증은 기존 경로의 실제 반환 SQL과 별도 DELETE 사이에 차감을 넣었다. 보완 후에는 원자적 삭제 RPC를 실행했다. 늦은 완료는 기존 완료 경로와 같은 `status='queued'` 조건부 UPDATE로 검사했으며 유료 제공자나 API는 호출하지 않았다. 세 실행 모두 임시 스키마 제거와 public 함수 28개의 지문 불변을 확인했다. public·운영 데이터 쓰기는 0이다.

증거는 `generation-job-lifecycle.before.json`, `generation-job-lifecycle.after.json`, `take-hold-idempotency.lifecycle.json`에 보존했다. 기존 170000 검증 결과와 테스트 기대는 수정하지 않았다. 새 TS/MJS 파일 ESLint와 전체 TypeScript 검사도 통과했다.

```sh
node tests/manual/generation-job-lifecycle.verify.mjs --baseline
node tests/manual/generation-job-lifecycle.verify.mjs
node tests/manual/take-hold-idempotency.verify.mjs --lifecycle
```

첫 명령은 이전 동작의 문제를 증명하므로 실패 종료가 정상이다. 실제 public 함수에는 아직 적용하지 않았다.
