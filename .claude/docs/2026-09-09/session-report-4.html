채팅 안정성: 다음 구현 계획

1

현재 상태와 다음 차이

항목현재다음 구현
사용 가능한 기능프롬프트와 JSON 명령 목록에 분산되어 있다. 웹 검색 도구는 이미 있다.프로젝트 상태와 가능한 앱 조작을 조회하고, UI와 같은 실행 함수를 도구로 제공한다.
실행LLM 응답의 JSON을 앱이 처리한다. 언어 변경은 저장 결과까지 확인한다.앱이 도구 호출을 검증·실행하고 성공·실패·승인 필요·부분 성공을 돌려준다.
실패 후 행동대사 언어 저장 실패를 알리는 단계까지 구현했다. 모델이 그 결과를 받고 다시 계획하지는 않는다.LLM이 실제 결과를 읽고 다음 조회·입력 수정·재시도를 선택한다. 앱은 허용된 범위와 상한을 지킨다.
완료모델의 일반 답변과 일부 실행 결과가 함께 보인다.실행 요청의 완료 표시는 실제 변경·저장 확인에 연결한다. 미완료 대상과 이유도 남긴다.
요청 이해→상태·가능한 기능 조회→도구 실행→결과 확인→완료 / 복구 / 질문 / 중단

복구가 필요하면 실제 오류와 최신 상태를 모델에게 전달해 다음 행동을 고른다. 같은 요청의 남은 목표를 유지한다. 단순 성공은 추가 추론 없이 저장된 결과로 안내할 수 있다.

2

바로 할 작업

순서구현 범위완료 시 확인할 것
1 · 공통 실행 계약도구 이름·대상·입력 검증·승인 조건·실행 결과를 한 경로로 연결한다. UI와 채팅은 같은 도메인 실행 함수를 사용한다. 기존 코드는 재사용한다.명령 선택 실패, 실행 실패, 결과 안내 실패를 서로 구분할 수 있다.
2 · tool call + 반복현재 모델·SDK에 앱 조작 도구와 결과 반환을 연결한다. 실행 오류를 모델에게 전달하고, 허용된 후속 행동을 수행한다.첫 시도가 틀려도 한 요청 안에서 재조회·수정·재시도할 수 있다.
3 · 작은 교차 단계 검증Producer 설정 조회·변경과 Writer 대사 조회·편집을 첫 대상으로 삼는다. 기능을 늘리기 전에 공통 복구 방식이 두 단계에서 작동하는지 확인한다.잘못된 언어 판단, 잘못된 대사 대상, 일시 저장 실패를 주입해 복구를 확인한다. 이미지·영상 생성 불필요.
4 · 나머지 UI 연결최초 113개 기능표를 UI 실행 함수·채팅 도구·검증 상태로 매핑한다. 단계 담당이 미노출 조작을 병렬로 연결한다.지원하는 기능을 도구가 없어 못 하는 항목이 명확해지고, 연결한 항목의 실제 결과가 UI와 같다.
5 · 생성 작업 확장Artist·Director 생성은 기존 작업 ID·승인·비용·완료 조회에 연결한다. 기존 미디어로 검증 후 대표 생성만 실행한다.접수와 완료를 구분하고, 응답 유실 시 상태를 조회하며, 같은 요청을 중복 발주하지 않는다.

기존 개별 버그 목록은 유지한다. 해당 실행 함수를 도구로 연결할 때 필요한 수정부터 묶는다. 전 기능을 연결하기 전에도 3번 결과를 먼저 검수할 수 있게 한다.

3

실패별 다음 행동

발생 상황채팅이 할 일중단·질문 기준
지원 기능인데 “못 한다”고 답함가능한 기능과 현재 상태를 조회해 근거를 확인하고, 실행 가능한 경로로 재판단한다. 근거 없는 미지원 판정을 실행 결과로 확정하지 않는다.조회 후에도 대상·의도가 모호하면 한 가지 필요한 정보를 묻는다. 모든 자연어 거절의 자동 교정을 보장하지는 않는다.
도구 미선택·잘못된 입력작업 요청에 실행 명령이 없거나 입력 검증에 실패하면 구체적인 누락·허용값을 돌려줘 계획을 수정한다. 일반 대화·질문은 실행을 강제하지 않는다.복구 상한에 도달하면 미완료 사실과 필요한 정보를 남긴다.
샷·인물 대상 불일치최신 목록을 다시 조회하고 사용자의 원래 요청과 맞는 대상을 찾는다.후보가 여러 개면 임의 선택하지 않고 묻는다.
저장 일시 실패재시도 가능한 오류를 구분해 같은 작업 식별자로 제한 재시도한다. 저장 결과를 다시 확인한다.권한 부족·입력 오류는 같은 요청을 그대로 반복하지 않는다.
저장·생성 응답 유실먼저 해당 작업의 저장·접수 상태를 조회한다. 이미 적용·접수된 작업은 이어서 결과를 확인한다.상태를 확정할 수 없으면 미확인으로 남긴다. 유료 작업을 새 요청으로 재발주하지 않는다.
일부 작업만 성공완료·실패·아직 안 한 대상을 기록하고 남은 대상만 처리한다.새 대상·모델·수량·비용으로 바뀌면 기존 승인을 재사용하지 않는다.
선행 이미지·설정 부족무엇이 필요한지 확인하고 가능한 해결 순서를 제시한다. 이미 요청 범위 안인 안전한 준비 작업은 이어서 수행한다.추가 유료 생성·명시적 확정이 필요하면 해당 승인에서 기다린다.
실행 경로 자체가 없음어느 부분을 못 했는지와 가능한 기능·UI 경로를 안내한다. 해당 항목은 도구 연결 작업으로 남긴다.모델에게 프롬프트를 반복한다고 없는 제품 기능이 생기는 것은 아니다.
4

안정성의 완료 기준

구분통과 기준검증 방법
성공 판단저장·실행 결과가 없는 작업을 완료로 표시하지 않는다.가짜 성공 발화·빈 도구 호출·저장값 불일치를 주입한다.
복구잘못된 인자·낡은 대상·일시 저장 실패에서 올바른 다음 행동으로 진행한다.결정적 실패 주입 + 실제 LLM 표현 변형을 분리해 확인한다.
중복·부분 성공재시도해도 성공한 변경·접수된 생성을 중복 실행하지 않는다. 남은 대상을 확인할 수 있다.응답 유실·부분 성공·다시 접속한 상황을 검증한다.
승인·중단승인 범위를 유지하고, 사용자 취소·프로젝트 전환·실행 상한에서 중단한다.승인 전후 변경, 요청 중 취소, 프로젝트 전환을 검증한다.
실제 이해도첫 성공률과 복구 후 성공률, 잘못된 완료·불가 안내, 필요한 질문, 지연·비용을 따로 기록한다.첫 표본 제안: 대표 발화 10개 × 3회. 같은 빌드·초기 상태로 비교. 목표 수치는 초기 측정 후 확정한다.

보장할 대상은 결과 확인·승인·중복 방지·중단 절차다. 사용자의 모든 표현을 정확히 이해하거나 모든 외부 장애를 해결한다는 보장은 하지 않는다. 자동 복구 가능한 범위를 테스트와 실제 발화로 넓힌다.

5

시작 범위와 오너 역할

항목제안
첫 구현의 상한일반 편집은 요청당 모델 판단 최대 4회·총 60초, 같은 실패의 복구 시도 최대 2회를 시작값으로 제안한다. 처음의 상태 조회와 도구 실행을 포함한다. 실제 지연을 보고 조정하며, 아직 제품 기본값으로 확정된 수치는 아니다.
장기 생성60초 안에 영상을 완성시키려는 제한이 아니다. 승인된 생성은 작업 ID로 추적하고 “접수됨/진행 중/완료”로 구분한다. 모델이 기다리며 계속 호출되지 않는다.
tool call 채택앱 조작을 네이티브 tool call로 연결하는 방식을 추천한다. 기존 JSON 명령의 실행 함수를 재사용하고, 결과를 모델에 돌려주는 반복을 함께 구현한다. 모델 교체나 Agent SDK 도입을 선행 조건으로 두지 않는다.
에이전트 역할도구 연결·실패 주입·회귀 검사·실제 LLM 평가·DB/화면 확인·보고를 담당한다.
오너 역할평소 표현, 기대한 결과, 허용할 대안의 예시를 제공한다. 구현 설명이나 수동 장애 재현을 맡길 필요는 없다. 첫 교차 단계 표본에서 의도 이해와 질문의 적절성을 확인한다.

근거: 현재 src/lib/claude.ts는 웹 검색을 제외한 앱 조작용 tool loop를 제공하지 않고 텍스트를 반환한다. Producer 라우트는 변경 JSON을 추출해 클라이언트로 반환한다. 1차 수정은 대사 언어의 저장 확인까지다. src/lib/llm.ts의 기존 모델 연동과 도메인 실행 코드를 재사용한다.

도구 실행 결과를 모델에 보내 최종 답변 또는 추가 도구 호출을 받는 표준 흐름은 OpenAI 공식 Function calling 문서로 대조했다. 이 문서의 앱 적용 방식·순서·상한은 이번 제안이며, Codex나 Claude Code의 내부 구현을 그대로 설명한 것은 아니다.

이번 문서는 다음 구현의 범위와 완료 기준을 보완했다. 제품 코드·테스트·DB 변경 및 신규 LLM·이미지·영상 실행은 하지 않았다.
