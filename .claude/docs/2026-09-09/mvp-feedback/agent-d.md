# 진행 상태·숫자·화면 통합 보고

**초안과 후반 작업의 진행 범위를 나누고, 중앙과 채팅이 같은 상태 사본을 읽도록 수정했다. 현재 작업 범위에 맞지 않는 예상 시간 숫자는 숨겼다. 미확인 완료 배지는 의미를 표시하고, 현재 단계에서 숨기며, 같은 작업의 중복 완료 기록을 한 번만 센다. 색과 메뉴 외형은 검수 후보를 적용했다.**

작업일은 2026-09-09~10 KST다. 기존 미커밋 작업을 보존했다. 운영 배포는 수행하지 않았다.

## 지킨 약속과 이유

| 한국어 약속 | 왜 |
|---|---|
| 씬 스토리 초안을 기다릴 때는 초안까지의 진행을 보여주고, 검토 중에는 확정을 기다린다고 알려준다. | 초안 완료와 전체 Writer 완료가 달라 서로 다른 범위를 같은 진행률로 읽지 않게 한다. |
| 같은 작업의 중앙 진행 표시와 채팅 진행 표시는 같은 단계와 진행 상태를 보여준다. | 별도 조회가 서로 다른 시점의 상태를 표시하는 문제를 막는다. |
| 예상 시간을 표시하면 무엇이 끝날 때까지의 시간인지 함께 알려준다. | 전체 실행·승인 대기를 포함한 옛 추정치를 현재 구간의 남은 시간으로 쓸 수 없다. 이번에는 해당 숫자를 제거했다. |
| 진행 표시가 거의 끝난 것처럼 보이는데 실제로 큰 작업이 남는 경우, 남은 작업을 명확히 알려준다. | 단순 단계 개수는 시간 비율이 아니다. 현재 작업과 이미지 생성의 별도 진행을 알린다. |
| 다시 시작한 작업의 첫 상태 확인에 실패해도 다음 확인을 계속한다. | 실패했던 실행을 재개한 직후 한 번의 네트워크 오류로 갱신이 영구 중단되면 안 된다. |
| 왼쪽 단계 배지는 아직 확인하지 않은 새 완료 수임을 알 수 있게 표시한다. | 배지 숫자만으로 전체 작업 수·오류 수를 구별할 수 없다. |
| 같은 생성 작업의 완료 기록이 반복돼도 배지에는 한 번만 반영한다. | 겹친 완료 기록 때문에 확인할 결과 수가 부풀면 안 된다. 실제 중복 발주 차단과는 별도다. |

## 변경과 검증

- 초안은 4단계, 후반은 현재 기본 엔진의 11단계를 사용한다. 병합 실행에서 생략된 선행 단계도 현재 단계로 충족 여부를 계산한다. 완료·검토 대기 이외에는 진행률을 100%로 표시하지 않는다. 새 정확도 기준이나 시간 보정식을 임의로 만들지 않았다.
- 프로젝트별 상태 구독은 한 요청·한 타이머를 공유한다. 마지막 화면 구독이 끝나면 요청·타이머·복귀 이벤트를 정리한다. 기존 조회 제한 15초, 정체 판단 180초, 재개 확인 60초는 유지했다. 검토 대기에는 자동 재개하지 않는다.
- 두 실제 화면의 표시와 막대 너비가 50%로 일치함을 1511×728 및 755×728에서 확인했다. 검토 대기에는 진행 중 막대가 없고 최종 저장에서는 ‘단계 10/11’과 저장 중 설명을 표시했다.
- 채팅 왕복 검수에서는 대화 ID·순서·완료 안내 1개가 유지되고 읽던 스크롤 위치가 그대로였다. Artist 승인 카드의 두 대상은 Writer 채팅에서도 보였고, 보류 목록을 펼쳐 다시 열 수 있었다.
- 배지에는 ‘아직 확인하지 않은 완료 9개’를 제공하며 해당 단계 선택 후 사라졌다. 원래 운영에서 활성 탭에 9가 남은 최초 조건은 별도 조사 대기다.
- 현재 테마의 primary를 회백색 후보로, Help를 보조 메뉴로 바꿨다. 메뉴의 크기·간격·모서리를 맞췄다. 아이콘은 기존 Lucide 체계를 유지했으며 새 라이브러리를 추가하지 않았다. 최종 색·외형 판단은 오너 검수 대상이다.

## 증거와 제한

- 결정적 회귀: `tests/writer/progress-scope.test.ts` 4개, `tests/writer/status-sharing.test.ts` 4개, `tests/job/completion-badge-feedback.test.ts` 2개. 최신 묶음 결과는 `root-targeted.txt`다.
- 최초 빨강 및 후속 결함의 빨강: `d-red.txt`, `d-retry-red.txt`, `d-merged-red.txt`, `badge-red.txt`. 초록은 `d-green.txt`, `badge-green.txt` 및 최종 통합 결과와 함께 읽는다.
- 화면 실행: `browser-run.txt`, `browser-evidence.json`, `scripts/check-mvp-feedback-ui.mjs`, `tests/fixtures/mvp-feedback-page.tsx`.
- 로컬 검수는 실제 화면·store·상호작용을 사용하지만 응답과 이미지는 고정 자료다. 이동은 라우터 호출을 가로채는 검수 환경이다. 전체 운영 라우팅이나 실제 유료 이미지 품질을 통과시켰다는 의미가 아니다.
- `before-*`는 **색·메뉴 변경 전** 화면이며 진행 계산은 이미 수정된 시점이다. 진행률 원본의 전후 비교 자료로 쓰지 않는다. `appearance-*`의 이미지는 구별하기 위한 테스트 도형이다.
- 운영의 초안 약 61초와 전체 약 625초, 실제 러프 중복 접수는 `agent-c-history.md`에 별도로 기록했다. 이 조회는 수정 배포의 검증이 아니다.
- `pnpm`이 설치 상태를 맞추려고 재설치를 시도하다 비대화형 환경에서 실패해, 설치된 TypeScript·ESLint·Vitest 실행 파일로 같은 검사를 수행했다. 의존성을 다시 설치하거나 추가하지 않았다.

## 혼자 정한 것

구현 선택은 상태 구독 공유, 부적합한 기존 남은 시간 숨김, 단계별 표시 범위 분리, 회백색 후보와 메뉴 치수 정리다. 최종 색, ETA 허용 오차·표본 기준, 자동 복구 상한 수치를 승인된 정책으로 만들지 않았다.

## 전체 소스 lint 후 보완

전체 src ESLint에서 기존 진행창의 저장 위치 복원이 effect 안에서 즉시 상태를 바꿔 오류1개가 발생했다. 변경 전 브라우저에서 저장 좌표12/24 복원을 확인한 뒤, 첫 브라우저 프레임에서 복원하고 이탈 시 예약을 해제하도록 좁게 수정했다. 변경 후에도12/24 복원 확인, 해당 파일 lint 오류0(`position-browser.txt`, `position-eslint.txt`). Sidebar의 사용하지 않는 store import도 제거했다. 저장 위치·드래그 계약은 바꾸지 않았다.
