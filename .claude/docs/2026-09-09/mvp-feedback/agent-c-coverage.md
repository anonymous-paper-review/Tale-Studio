# 두 인물 요청의 명령 누락 보완 보고

**두 인물을 명시해 새 모습을 추가해 달라고 했는데 한 명의 제안만 받은 경우, 빠진 인물을 마지막 답변에서 미처리로 알리도록 수정했습니다. 받은 제안은 보존하고 누락된 생성 작업을 추측해서 추가하지 않습니다. 실제 Artist 채팅 경로의 새 검증 16개를 포함해 관련 80개 검증이 통과했습니다.**

작업일: 2026-09-10 00:04~00:13 KST. MVP-26의 남은 입력 대조 경계를 담당했으며, A가 작성 중인 `global-chat-store.ts`는 수정하지 않았습니다.

## 기존에 완료된 동작과 남아 있던 문제

A 수정은 **응답으로 받은** 여러 새 모습 제안을 승인 목록에 모두 보존하고, 항목별 시작·완료·실패를 알려줍니다. 하지만 모델이 처음부터 쿄타로 한 명만 반환하면 코마츠는 승인 목록에 한 번도 들어가지 않습니다. 원래 요청과 반환 목록을 비교하지 않으므로 실행 실패 보고에도 도달하지 않았습니다.

기존 Artist 파서는 반환된 JSON만 구조 검사합니다. `extractAppearanceCreations`는 필수값이 없는 항목도 제외하지만, 그 인물이 원래 요청에 있었는지 알 수 없습니다. 해당 라우트는 원래 사용자 문장과 검증된 제안 배열을 동시에 가지고 있어, 이 경계에서 등록 이름을 대조할 수 있습니다. 실제 원 사건에서 모델이 한 명만 반환했는지는 여전히 원본 응답이 없어 확정하지 않습니다.

## 이번 변경

- 질문·인용·제외·비교가 없는 **한국어 새 모습 추가 명령형**에 한정해 확인합니다. ‘모습/외형/버전’을 언급하고 ‘추가해줘/생성해줘/만들어줘’ 등의 명령으로 끝나는 문장이 대상입니다. 기존 공용 의도 판별기에 이 유형은 없어, 범용 의도 추론을 추가하지 않고 좁은 조건만 둡니다.
- 이미 소유권을 확인한 현재 프로젝트에서 인물 ID와 이름만 조회합니다. 모델에 전체 목록을 다시 전달하거나 새 호출을 하지 않습니다.
- 정확한 등록 이름이 둘 이상 현재 문장에 명시됐을 때 반환된 새 모습 제안 ID와 비교합니다. 한국어 조사를 허용하되 ‘코마’를 ‘코마츠’로 읽는 부분 일치, 동명이인의 ID 추정은 하지 않습니다.
- 문장에 언급된 이름과 실제 제안 대상을 구분해 알립니다. **새 생성 명령·승인 대상·작업 ID를 만들어내지 않습니다.** 받은 제안 수와 내용은 그대로입니다.
- 모델이 먼저 ‘두 사람 모두 완성했어요’라고 말해도 누락 안내가 답변 **마지막**에 남습니다. 이 응답은 전체 생성 완료가 아니며 제안은 승인 뒤에 시작한다는 점을 명시합니다.
- 등록 목록 조회가 실패하면 받은 제안을 유지하며 누락 여부를 확인하지 못했다고 알립니다. 조회 실패를 이유로 기존 제안을 조용히 버리거나 모두 완료했다고 보고하지 않습니다.

## 실제 제안 문구

입력: ‘쿄타로와 코마츠의 잠옷입은 모습도 추가해줘’.
모델 반환: 쿄타로의 `createAppearance` 제안 1개만 있음.

> 아직 전체 생성이 완료된 것은 아니에요. 코마츠: 미처리. 요청에 이름이 언급됐지만, 사용할 수 있는 새 모습 제안을 받지 못해 시작하지 않았어요. 전달된 제안도 승인 뒤에만 시작해요.

등록 인물 대조가 실패한 경우:

> 받은 제안은 승인할 수 있도록 유지했지만, 인물 누락 여부를 확인하지 못했어요. 이 응답이 전체 생성 완료를 뜻하지는 않아요.

두 문구는 번역 사전에 등록했고 선택된 콘텐츠 언어로 표시합니다. 이 자료는 실제 API 응답 문구를 고정한 증거이며, 스크린샷 검수는 주 담당자의 통합 화면 자료를 따릅니다.
