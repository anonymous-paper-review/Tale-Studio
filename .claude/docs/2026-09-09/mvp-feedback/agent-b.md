# 배경 모습 개선 보고 — MVP-22·23·24

**배경 모습 3개 항목의 입력·상태 결함을 수정했고 신규 회귀 11개가 통과했다. 실제 밤 이미지 품질과 운영 당시 사건 원인은 원본 자료가 없어 검수 대기로 남긴다. 채팅과 화면의 동일 조건 생성 입력 자체는 같았다.**

## 실행 범위와 약속

- 같은 모습의 같은 조건으로 생성하면 채팅과 UI가 같은 대상과 생성 입력을 사용한다.
  - 왜: UI 재생성을 다시 눌러야 한다는 피드백에서 입력 경로 차이와 모델 출력 편차를 구분한다.
- 새 모습에서 지정한 시간대와 조명은 기존 모습의 같은 조건보다 우선해 생성 입력에 반영된다.
  - 왜: 밤·달빛 설명과 낮·햇빛 조건이 함께 들어가 요청을 흐릴 수 있다.
- 새 모습의 탭에서는 그 모습의 생성 상태와 저장된 이미지를 보여준다.
  - 왜: 기본 이미지를 새 모습의 결과로 오해하거나 새 탭의 접수 상태를 알 수 없는 일을 막는다.
- 다른 모습이 먼저 완성되어도 각 모습의 이미지와 생성 상태가 섞이지 않는다.
  - 왜: 같은 장소의 다른 모습 요청이 서로 막히거나 완료 순서에 따라 다른 탭을 덮으면 안 된다.
- 새로고침해도 선택한 모습과 그 모습의 저장된 이미지가 다시 열린다.
  - 왜: 새 모습 선택을 잃고 기본 모습으로 돌아가 생성 실패처럼 보이는 일을 막는다.
- 새로고침 중 진행 중인 모습은 기존 작업을 이어 확인하고 완료 이미지를 보여준다.
  - 왜: 새 작업을 발주하지 않고 이미 접수된 배경 작업의 결과를 확인한다.
- 새 모습이 저장되고 생성되면 모습 이름과 작업 접수·완료 기록을 함께 전달한다.
  - 왜: 승인된 여러 요청에서 행 저장과 이미지 완료를 구분하고 남은 대상만 복구한다.

## 추가 담당 — MVP-18 러프 진행 수 구분

**러프 보드 상단에 보드 전체·완료·생성 중·대기·실패를 샷 단위로 분리했다. 47샷 자료에서 8→5→4 생성 중 변화와 재시도 시 전체 수 유지 회귀 4개가 통과했다. 운영 화면의 14가 어느 표시였는지는 아직 미확정이다.**

상단 액션 영역의 생성 중 숫자 한 개를 헤더 바로 아래의 줄바꿈 가능한 상태 요약으로 옮겼다. 총수는 최근 생성 묶음 크기가 아니라 현재 보드에 있는 고유 샷 수다. 한 샷은 다섯 수치 중 전체에 한 번 포함되고, 나머지 네 상태 중 하나에만 속한다. 재시도 중인 실패 샷은 현재 생성 중으로 이동한다. 동시 생성 설정은 바꾸지 않았다.

| 표시 | 단위와 근거 |
| --- | --- |
| 보드 전체 | 현재 보드의 고유 샷 수 |
| 완료 | 저장되었거나 막 반영된 완료 이미지가 있는 샷 |
| 생성 중 | 서버 진행 작업의 샷 목록 또는 이 화면에서 접수 중인 샷 |
| 대기 | 위 상태에 속하지 않으며 이미지 완료를 기다리는 샷. 이야기 입력이 필요한 빈 샷도 포함 |
| 실패 | 현재 작업 또는 저장된 러프 이미지가 실패한 샷. 재시도 작업이 있으면 생성 중으로 셈 |
| 최근 묶음 크기 | 별도 큐 알림의 시간 창 집계. 보드 전체와 같은 숫자로 취급하지 않음 |

약속과 이유:

- 러프 생성의 전체 대상, 완료, 생성 중, 대기, 실패를 구분해 알려준다.
  - 왜: 전체 샷 수와 현재 생성 중 샷 수를 혼동하지 않게 한다.
- 여러 샷을 만드는 두 작업의 진행 수가 8에서 5와 4로 줄어도 보드 전체는 47샷이다.
  - 왜: 한 요청이 여러 샷을 만들고 완료 순서가 달라져도 전체 규모를 유지한다.
- 실패한 샷을 다시 생성하면 실패에서 생성 중으로 옮기고 전체 수를 늘리지 않는다.
  - 왜: 반복 접수 기록으로 같은 샷이 두 번 세어지면 안 된다.
- 최근 완료 14샷과 현재 생성 중 4샷을 전체 47샷과 각각 구분한다.
  - 왜: 최근 완료량이 전체 요청량이나 현재 동시 생성량처럼 표시되면 안 된다. 이 검증용 14는 운영 당시 14의 원인을 입증하지 않는다.

검증: 신규 함수가 없어 실패한 최초 실행(23:37) 뒤 구현 후 4개 통과. B 신규 11개·기존 숫자 동기화 16개와 함께 실행한 합계는 4파일 31개 통과(23:38). 신규 집계와 UI의 ESLint 오류 0; root의 별도 변경 구간 `nowMs` 미사용 경고 1개는 root에게 전달했다. 타입 검사에는 B 변경 오류가 없고 병행 A의 `cancelDeferredProposal` 구현 대기 오류 1개를 전달했다. 최종 전체 검사 결과는 root 보고가 소유한다.

추가 변경 파일: `src/lib/writer/rough-progress.ts`, `src/features/writer/rough-storyboard-view.tsx`, `tests/writer/rough-progress.test.ts`, `src/lib/i18n/messages-ko.ts`(root/A 요청 화면 번역 포함).

최종 제한: 현재 요약은 보드 전체 기준이다. 요청별로 승인한 샷 명단을 새로 영속화한 것은 아니다. 샷 추가·삭제가 있으면 보드 전체 수도 바뀐다. 실제 운영 14의 표시 위치·그때의 작업 로그·스크린샷 원본은 미제공이다.
