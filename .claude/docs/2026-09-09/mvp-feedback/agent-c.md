## 사용자에게 보이는 변화와 약속

- **이야기 문장에 등록된 장소의 내부 식별자가 있으면 그 장소의 표시 이름으로 보여준다.**
  - 왜: 씬의 대표 장소가 옥상이어도 본문에 잠깐 등장한 `vending_machine_corner`는 ‘자판기 앞’으로 읽혀야 합니다.
- **이야기와 대사에 등록된 인물의 내부 식별자가 있으면 그 인물의 이름으로 보여준다.**
  - 왜: Writer·Director·Editor의 같은 인물이 서로 다른 내부 번호로 보이지 않아야 합니다.
- **본문에서 채택한 장소 후보도 등록하고 그 장소의 이름을 보여준다.**
  - 왜: 대표 장소 필드에 없는 후보가 이야기 문장에 등장하면 기존 등록 경로에서 빠졌습니다.
- **별칭과 실제 등록 식별자가 겹치면 실제 등록된 인물 이름을 우선한다.**
  - 왜: `char_2`와 `character_2`가 서로 다른 실제 인물일 때 목록 순서로 이름이 뒤바뀌었습니다.
- **대사에 붙은 말투 설명도 인물 이름으로 정리하고 화자 참조는 보존한다.**
  - 왜: 말투에 남은 `char_2`가 대사 본문을 고친 뒤에도 그대로 노출됐습니다.
- **생성 결과의 형식이 맞아도 등록되지 않은 참조나 문장 속 내부 식별자가 남으면 검증 결과에 드러난다.**
  - 왜: JSON 형식이 맞는다는 사실만으로 사람이 읽는 문장이 정상임을 보장할 수 없습니다.
- **인물과 배경 미리보기의 설명은 선택된 콘텐츠 언어의 표시용 설명을 사용한다.**
  - 왜: 한국어 설명이 이미 저장돼 있어도 preview가 영어 생성 원본만 조회했습니다.
- **잠기지 않은 프로젝트의 설명은 현재 화면 언어를 따른다.**
  - 왜: 기존 2026-09-08 콘텐츠 언어 선택 계약과 같은 규칙을 사용해야 합니다.
- **표시용 번역이 없으면 원래 설명을 남기고 번역이 없는 상태를 구분한다.**
  - 왜: 설명을 감추거나 즉석 번역을 발주하지 않고, 현재 읽는 문장의 출처를 알립니다.

새 과금·자동 복구·모델 선택 정책은 없습니다. 생성용 영어 원본, 인물·장소의 구조 참조값은 변경하지 않았습니다.

## MVP-09: 확인된 기제와 확인하지 못한 사건

확인된 사건 증거는 `specs/mvp-feedback-source.md` 164줄 앞의 DOM입니다. ‘쿄타로가 체육관 옆 vending_machine_corner에서…’라는 표시 결과가 보존돼 있습니다. `char2`는 같은 피드백 문장의 사용자 관찰입니다.

현재 코드에서 재현한 누출 경계는 다음과 같습니다.

1. S3의 입력에는 인물·장소의 내부 ID와 표시 이름이 함께 들어갑니다. ID 자체는 구조 참조를 위한 정상 입력입니다.
2. 모델 응답 자리에 식별자가 섞인 정상 JSON을 고정하면 기존 구조 검사는 이를 통과시켰습니다.
3. 기존 `cleanSceneProse`는 인물만 읽었으므로 등록된 장소 ID도 본문에 남았습니다. 본문에서만 사용한 장소 후보는 `mergeOpenWorld`에서 빠졌습니다.
4. preview는 실행 상태의 이름 목록만 읽고 DB에 저장된 전체 장소를 합치지 않았습니다. 실제 렌더에서도 장소 ID가 그대로 나타날 수 있었습니다.

이 네 단계는 **현재 코드에 대한 결정적 재현**입니다. 원래 사건의 모델이 해당 문자열을 최초 생성했다는 증거는 아닙니다.

- 로컬 `logs/`에 기존 로그가 존재함을 파일 목록으로 확인했습니다.
- `logs/`의 JSON·JSONL에서 `vending_machine_corner` 또는 `쿄타로`를 포함하는 파일은 찾지 못했습니다.
- 운영 DB, 다른 사용자의 프로젝트, 봉인된 `.claude/vault/`는 조회하지 않았습니다.
- 서버리스에서 파일 로그는 비활성화됩니다. `flushRawLlm`은 `llm_calls`로 원문을 최선 노력 방식으로 보관하므로 기록 실패·비활성화·필드 길이 제한의 가능성이 있습니다.

사건의 최초 발생을 확정하려면 동일 실행의 `llm_calls` 원문, 최초 `writer_runs.state`, 당시 preview 응답과 배포 버전을 대조해야 합니다. 후속 조사로 프로젝트·실행 ID·현재 preview 누출은 확인했으나 최초 응답과 저장 이전 경계가 연결되지 않아 사건 해결 완료로 올리지 않습니다.

## 오류 주입 및 테스트 증거

유료 모델을 호출하지 않았습니다. 실제 dispatcher의 로컬 공급자 응답만 고정하고 실제 S3/V2 실행과 검사·완료 산출 저장 경계를 통과시켰습니다. preview는 실제 GET 핸들러를 실행했습니다.

| 주입/사례 | 수정 전 | 수정 후 |
|---|---|---|
| 등록 장소 ID가 씬 본문에만 등장 | 영어 식별자가 남음 | 표시 장소명으로 정리, 구조 ID 유지 |
| 장소 후보가 본문에만 등장 | 등록 목록에서 누락 | 채택 후보를 등록, 정리 후 재병합에도 유지 |
