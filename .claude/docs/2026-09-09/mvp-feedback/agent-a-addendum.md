# MVP-29 추가 보고 — 대사 전체 수정 후 완료에 따른 이어가기

**‘전체 한국어로 맞추고 넘겨줘’를 받으면 실제 대사 저장이 끝난 뒤 남은 씬을 자동으로 이어 처리하고, 모두 저장됐을 때만 요청한 단계로 넘기도록 수정했습니다.** 최초 모델 응답이 1~3씬만 반환하는 사례에서 4씬·5씬을 자동 요청·저장하고, 이미 한국어인 6씬을 유지한 뒤 Director로 이동하는 회귀를 통과했습니다.

새로운 검증은 **12개 통과**했습니다. 47샷 화면 검수에서 발견한 진행 안내 중복까지 수정한 뒤 Writer 완료·채팅 보존 **33개 통과**를 확인했습니다. 앞선 넓은 검사에서는 관련 핵심 **47개**, Writer·Chat·Producer 전체 **848개 통과·7개 기존 제외**였습니다. 타입 검사와 수정 코드 ESLint의 상세 시점은 아래 증거에 남겼습니다. 이번 변경으로 유료 그림·영상 생성이나 운영 배포는 하지 않았습니다.

## 확인한 원인

- Writer의 기존 빠른 이동은 다음 단계인 Artist만 대상으로 삼습니다. Writer 대화의 “Director로 넘겨주세요”는 일반 모델 답변으로 흐를 수 있었습니다.
- 모델이 “1~3씬부터 처리할게요”라고 말해도 그다음 호출을 시작하는 코드가 없었습니다. 응답 본문은 미래의 계획일 뿐 실행 완료 신호가 아니었습니다.
- 일반 대사 수정은 저장을 잠시 뒤로 예약한 시점에 적용 건수를 반환합니다. 기존 `applyChatUpdates`의 반환만으로는 실제 저장 완료와 다음 단계 이동을 연결할 수 없었습니다.

## 바뀐 동작

1. 현재 사용자가 지시한 이동 목적지 또는 앞선 사용자 발화의 명시적 목적지를 보존합니다. 이 특별 경로는 전체 한국어 통일과 이동을 함께 요청한 Writer 대화에 적용합니다.
2. 요청 당시의 전체 샷·대사를 보존하고, 일본어·한자·영문 문자가 남은 대사를 처리 대상으로 잡습니다. 이미 한국어인 대사는 유지합니다.
3. 첫 응답에서 실제 실행할 대사 변경을 적용하고 **저장된 행을 확인한 뒤** 다음 대상으로 진행합니다.
4. 남은 씬은 자동으로 다시 요청합니다. 한 씬이 여러 응답으로 나뉘어도 새로 처리한 대상을 빼고 이어갑니다. 처리 대상이 줄지 않으면 같은 요청을 무한 반복하지 않고 미완료를 알립니다.
5. 언어 수정은 대사 삭제·화자 변경·샷 삭제의 승인이 아닙니다. 대사 수·화자를 검사하고, 감정·말투·길이 정보와 이미 한국어인 문장을 원본에서 보존합니다.
6. 모든 수정이 저장되고 이동 목적지의 기존 준비 조건을 만족할 때 완료를 알리고 이동합니다. 저장 실패·모델 무진전·작업 중단·준비 조건 부족이면 남은 작업이나 차단 이유를 알려주고 넘기지 않습니다.

자동 이어가기의 범위는 원래 요청의 샷 집합입니다. 별도의 “4회·60초” 재시도 한도나 새 SDK를 도입하지 않았습니다.

## 약속 문장과 이유

- “전체 한국어로 맞추고 넘겨 달라고 하면 일부 씬 저장 뒤 남은 씬을 자동 처리하고 모두 저장된 뒤 Director로 넘긴다” — 왜: 1~3씬만 처리하겠다는 말 뒤에 나머지가 끝나지 않던 원문 사례를 재현합니다.
- “대사 저장이 실패하면 남은 대상을 알리고 다음 단계로 넘기지 않는다” — 왜: 화면만 바뀌고 저장이 실패한 것을 완료로 보고하면 안 됩니다.
- “모델이 앞으로 하겠다는 말만 해도 남은 씬을 실제로 다시 요청하고 끝내지 못한 이유를 알린다” — 왜: 예정 발화를 실제 실행으로 오인하지 않아야 합니다.
- “대사 통일 응답에 샷 삭제가 섞여 있어도 요청한 대사 이외의 작업은 실행하지 않는다” — 왜: 언어 통일에 불필요한 작업이 따라오면 안 됩니다.
- “앞선 씬의 저장 응답이 오기 전에는 다음 씬을 요청하거나 넘기지 않는다” — 왜: 사용자가 요청한 완료에 따른 이어가기의 직접 검증입니다.
- “대사 통일 중 중단하면 저장을 마친 부분을 유지하고 나머지는 실행하거나 넘기지 않는다” — 왜: 중단 버튼을 누른 뒤 나머지가 계속 바뀌면 안 됩니다.
- “번역 응답에서 말투 정보가 빠져도 원래 화자와 말투를 보존한다” — 왜: 언어만 바꾸는 요청에서 기존 연기 정보가 사라지면 안 됩니다.
- “언어만 통일하라고 했으면 다음 단계로 넘기지 않는다” — 왜: 이동 지시가 없는 요청에서 목적지를 추측해 이동하면 안 됩니다.
- “남은 한 씬도 여러 번 나뉘어 돌아오면 저장한 샷을 빼고 나머지를 계속 처리한다” — 왜: 최초 묶음만 아니라 후속 응답 자체도 일부만 반환할 수 있습니다.
- “모든 대사를 저장했어도 Director 준비 조건이 부족하면 완료 내역을 남기고 이동을 보류한다” — 왜: 자동 이어가기가 기존 제작 준비 조건을 우회하면 안 됩니다.
- “저장할 샷이 도중에 사라졌으면 응답이 성공이어도 전체 저장 완료로 판단하지 않는다” — 왜: 저장된 행이 없는 응답을 저장 성공으로 간주하면 안 됩니다.

## 증거

- 실제 경로: `sendMessage` → 첫 Writer 응답 → 대사 저장 → 후속 Writer 요청 → 남은 대사 저장 → 준비 조건 확인 → `handoffToStage`.
- 첫 재현: `agent-a-29-red.log`.
- 같은 씬의 일부 응답 재현: `agent-a-29-partial-red.log`.
- 저장할 행이 사라진 경계 재현: `agent-a-29-missing-save-red.log`.
- 초록: `agent-a-29-green.log` — 4파일 47개 통과, 새 사례 11개 포함.
- 관련 전체: `agent-a-29-related.log` — 116파일 중 115통과·1기존제외, 848개 통과·7개 기존 제외.
- 타입 검사: `agent-a-29-typecheck.log` — 오류 없음.
- 수정 코드 ESLint: `agent-a-29-lint.log` — 오류·경고 없음.
- 화면 문구 검사: `agent-a-29-i18n.log` — 제품 코드 증가 없음. 리더가 캡처 중인 임시 `playground/mvp-feedback/page.tsx` fixture만 실패. 임시 경로 정리 후 리더가 최종 검사합니다.
- 변경: `src/lib/writer/dialogue-handoff.ts`, `src/stores/writer-store.ts`, `src/stores/global-chat-store.ts`, `src/lib/i18n/messages-ko.ts`, `tests/writer/dialogue-handoff-completion.test.ts`.
- 기존 소스 문자열 검사 2개의 기대값은 그대로 두었습니다.

## 남은 제한

- 이 변경은 **전체 한국어 대사 통일과 이동을 함께 요청한 경우**의 국소 해결입니다. 임의의 모든 편집 요청을 완결하는 범용 실행 엔진으로 보고하지 않습니다.
- 언어 확인은 일본어·영문·한자 문자가 남았는지를 검사합니다. 번역 의미·자연스러움·연기 품질을 증명하지 않으며, 이름·고유 표기의 언어 처리도 별도 품질 판단 대상입니다.
- 모델이 후속 요청에도 실행 가능한 전체 대사를 주지 않거나 저장이 실패하면 자동으로 미완료와 남은 씬을 알리고 이동하지 않습니다. 무조건 성공한다고 약속하지 않습니다.
- 자동 이어가기는 현재 열린 작업 세션에서 실행합니다. 브라우저 종료·새로고침 후 서버에서 자동 재개하는 내구성 있는 작업 원장까지 구현한 것은 아닙니다. 이미 저장한 부분은 유지되며 다시 같은 요청을 하면 한국어로 저장한 부분을 제외합니다.
- 최초 운영 사건의 모델 응답·저장 기록 원본을 재수집한 것은 아닙니다. 이번 결론은 보존된 사용자 사례와 결정적 실제 소비 경로 테스트에 근거합니다.


## 2026-09-10 화면 검수 후 보완 — 진행 안내 중복 제거

리더의 실제 6씬·47샷 브라우저 검수에서 40개 샷이 저장될 때 진행 안내도 40번 대화에 추가·저장되는 문제가 발견됐습니다. 실행 내용은 맞지만 대화를 읽기 어렵게 하므로 같은 요청의 진행 행 하나를 계속 갱신하도록 수정했습니다.

- 새 약속: “47샷의 대사를 처리해도 같은 요청의 진행 안내는 한 줄만 갱신하고 마지막 기록만 저장한다”.
- 왜: 저장한 샷 수만큼 대화와 저장 요청이 쌓여 완료 안내와 기존 대화를 밀어내면 안 됩니다.
- 재현: 40개 일본어 샷과 7개 한국어 샷. 24번째 저장 응답을 지연시킨 시점의 진행 행 수를 확인하고 마지막 완료 뒤에도 같은 ID 한 개임을 검사했습니다.
- 수정: 같은 명령의 진행 ID 하나를 사용합니다. 진행 중 숫자는 그 행에서 갱신하고, 완료·실패·중단 시 마지막 저장 수만 대화에 한 번 저장합니다. 완료 발화·실패 이유·중단 처리는 기존 경로를 유지합니다.
- 결과: 진행 중 한 행·완료 뒤 한 행·동일 ID·진행 기록 저장 1회·대사 저장 40회·Director 이동 1회. 기존 한국어 7샷은 유지합니다.
