# 운영 사건의 제한된 읽기 전용 확인

**사용자가 제보한 프로젝트를 기존 브라우저에서 식별했고, 같은 5개 샷이 각각 세 번씩 실제 생성 완료된 중복을 확인했습니다. 초안은 약 61초, 전체 Writer 실행은 약 10분 25초였습니다. 미리보기와 화면에는 `vending_machine_corner`가 여전히 노출됩니다. 당시 ‘18분’의 계산 근거, 식별자의 최초 발생 지점, 배지 ‘9’가 남았던 조건은 현재 자료만으로 확정하지 못했습니다.**

이 문서는 먼저 작성한 [C 작업 보고](agent-c.md)의 ‘운영 기록을 확인하지 않았다’는 조사 범위를 보완합니다. 이번 조회는 구현·배포가 아니라 **현재 남아 있는 같은 프로젝트 기록의 확인**입니다. 조사 도중 운영 데이터나 유료 작업을 변경하지 않았습니다.

## 조사 범위와 식별 근거

- 조사 시각: 2026-09-09 23:55~23:59 KST.
- 기존 Writer 탭의 프로젝트: `7112d31e-70ce-4743-9562-057f7beac002`.
- 등장인물 쿄타로·코마츠, 밤 학교 옥상·잠옷 요청, 추가 마쯔리 Scene 6의 14샷, ‘6씬·47샷’, ‘전체 한국어로 맞추고 넘겨줘’와 ‘먼저 Scene 1~3’이라는 대화가 원 제보와 함께 일치했습니다. 따라서 **같은 프로젝트**임을 확인했습니다.
- 상태 조회의 마지막 완료 시각과 이어지는 debug 사건에서 Writer 실행 `7ece6db5-b87d-4f40-be33-5d093d9c9eb6`을 연결했습니다. rough 사건 자체의 `run_id`는 null이므로 모든 후속 수정이 동일 Writer 실행에 속한다고 확대하지 않습니다.
- 현재 Writer 탭은 6씬·61샷입니다. 초기 저장 미리보기는 5씬이고, 기존 47샷 뒤 Scene 6의 `sh_06_01`~`sh_06_14`가 Shot 48~61로 보입니다. 채팅의 ‘6씬·47샷’은 발언 내용이며 현재 샷 목록의 실제 개수와 다릅니다.

조회는 기존 탭의 읽기 전용 snapshot, 같은 출처의 Writer status/preview/debug-events GET, 알려진 6개 작업에 대한 queue 상세 GET으로 한정했습니다. 각 라우트 구현을 먼저 읽었습니다. GET이어도 상태 조정·완료 저장을 수행하는 generation-jobs와 generation/active는 사용하지 않았습니다. 탐색 이동·인증 변경·POST·쿠키나 키 조회·원본 프롬프트 출력·다른 프로젝트 목록 조회·봉인 자료 조회는 하지 않았습니다.

debug는 최신 100건을 본 뒤 초기 러프 구간 확인을 위해 상한 200건으로 한 번 확대했습니다. 200건의 범위는 22:12:17.684~23:03:40.729 KST입니다. 더 오래된 S1/S3 원본 로그는 이 범위에 없습니다. 수집한 원문 대신 허용된 시각·개수·식별자만 보존한 자료: [agent-c-history-data.json](agent-c-history-data.json).

## MVP-09: 표시 경계의 누출은 확인, 최초 발생은 미확정

운영 preview의 Scene 2 비트와 같은 탭의 화면에서 다음 문장을 확인했습니다.

> 쿄타로가 체육관 옆 vending_machine_corner에서 음료수를 뽑고 있다.

이 프로젝트의 현재 전체 등록 장소/미리보기 로스터에는 교실·학교 옥상·귀갓길·각자의 방·사진부 동아리실·동네 공원 연못가가 있지만 `vending_machine_corner`는 없습니다. 따라서 **현재 API가 내보낸 텍스트와 실제 표시에서 누출이 이어지고 있음**은 확인됩니다. 현재 미등록인 이 토큰을 ‘자판기 앞’으로 추정해서 운영 데이터를 수정하지 않았습니다.

그 토큰이 원래 모델 응답에서 처음 생성됐는지, 당시 저장 이전 변환에서 생겼는지는 아직 판단할 수 없습니다. 이 실행의 원본 응답과 최초 S3 저장본, 당시 배포 버전을 연결하지 못했기 때문입니다. 코드 fixture는 등록 장소 치환 누락·본문 후보 등록 누락 경계를 재현했지만 이 사건의 최초 원인을 대신 증명하지는 않습니다. **MVP-09는 조사 대기를 유지합니다.**

**원인 해석의 한계:** 같은 미완료 집합을 읽은 자동 요청이 중첩된 사실은 분류·접수 기록으로 뒷받침됩니다. 다중 탭, 마운트/폴링 재진입, 서버 잠금 부재 중 무엇이 최초 트리거였는지는 당시 클라이언트 이벤트의 호출 식별자가 없어 특정하지 않습니다. 현재 미커밋 복구 구현이 운영에 반영됐다는 뜻도 아닙니다.

후속 Scene 6의 14샷은 22:31~22:33에 4+4+4+2개로 접수된 기록 및 현재 Shot48~61과 일치합니다. 그러나 사용자가 원래 본 ‘14’의 위치·시각은 보존되지 않았으므로 **원 제보의 14가 바로 이 추가14샷이라고 단정하지 않습니다.** 원 제보의8→5→4→14 전체 화면 연쇄는 아직 미확정입니다.

## MVP-20 및 MVP-29

- **MVP-20:** 저장된 debug 사건은 완료와 일부 UI 반영 시점을 알려주지만 당시의 `pathname`·`currentStage`·`lastSeen`·배포 버전을 함께 담지 않습니다. 현재 탭만 보고 과거 활성 Writer에서 ‘9’가 남았던 원인을 확정할 수 없습니다. 조사 대기 상태를 유지합니다.
- **MVP-29:** 같은 프로젝트 대화에서 사용자 전체 한국어 변경·Director 이동 요청과 봇의 ‘먼저 Scene1~3’ 예고가 마지막 답변인 점을 확인했습니다. 실제 전체 대사 저장 결과나 당시 처리 호출 이력은 이번 제한 조회에 포함되지 않았습니다. 같은 사건의 대화 근거는 확인했으며, 구현 수정·저장 후 이동 검증은 A 담당 보고를 따릅니다. 현재6씬61샷과 당시 봇이 말한6씬47샷을 동일한 저장 상태로 취급하지 않습니다.

이번 조사는 기존에 사용자가 보고한 프로젝트의 보존 상태를 읽어 사건 근거를 보강했습니다. 코드 수정의 효과는 별도 로컬 테스트·화면 검증으로 판단하며, 이 운영 조회 결과를 수정 배포 후의 성공 증거로 사용하지 않습니다.
