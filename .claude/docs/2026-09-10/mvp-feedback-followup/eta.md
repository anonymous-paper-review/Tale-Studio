# MVP-05 예상 시간 조치

**근거 없는 예상 시간은 서버 응답에서도 제거했습니다. 화면에서는 예상 시간을 계속 표시하지 않습니다. 이번 조치는 예측 정확도 개선이 아니라 부정확한 숫자의 노출 차단입니다.**

사용자 지시: “시간측정 안뜨게하거나 더 정확한 로직 넣거나 하셈 후자가 너무어렵지않은이상 더 좋아보임”. 현재 저장 기록을 확인한 결과, 단순 계산식 보정만으로는 신뢰할 수 있는 남은 시간을 만들 수 없어 사용자가 허용한 숨김 방식을 적용했습니다.

## 확인한 원인

- 기존 계산은 현재 프로젝트에 한정하지 않은 최근 완료 작업 10건의 시작 시각부터 마지막 저장 시각까지를 사용했습니다. 사용자가 초안을 확인하느라 기다린 시간도 생성 시간에 섞였습니다.
- 과거 작업도 당시 입력이 아니라 현재 프로젝트 설정의 영상 길이로 환산했습니다. 제작 방식과 모델 차이도 구분하지 않았습니다.
- 단계별 측정값으로 바꾸는 것만으로 해결되지 않습니다. 현재 실행기는 여러 번 나눠 처리한 중간 실행 시간과 실패한 시도의 시간을 누적하지 않고, 마지막 성공 실행 조각만 기록할 수 있습니다. 그 값을 더하면 실제보다 짧게 예측할 수 있습니다.
- 검토 대기 상태에도 과거 전체 작업 시간 추정값을 반환하던 경로를 회귀검사로 확인했습니다. 18분짜리 잘못된 값이 응답되는 재현 표본은 만들었으나, 사용자가 당시 보았던 18분의 정확한 표본과 표시 시각을 복원한 것은 아닙니다.

## 변경

- `/api/writer/status/:projectId`는 기존 호환 필드 `eta_total_ms: null`, `eta_based_on_runs: 0`을 반환합니다.
- 사용하지 않는 과거 실행 조회·프로젝트 설정 조회·예측 캐시·계산 함수를 제거했습니다. 현재 작업 상태 조회와 진단용 단계 기록은 유지했습니다.
- 새 API 필드·외부 의존성·DB 변경·복구 정책은 추가하지 않았습니다.
- 화면 모양과 진행 문구는 상위 작업자가 별도로 담당합니다. 이 슬라이스는 UI 파일을 수정하지 않았습니다.

## 약속과 검증

| 약속 문장 | 왜 필요한가 |
|---|---|
| 검토 대기가 섞인 과거 기록으로 남은 시간을 표시하지 않는다 | 초안 확인을 기다린 시간을 실제 생성 시간으로 환산하지 않기 위해서입니다. |
| 다른 제작 방식의 기록으로 남은 시간을 표시하지 않는다 | 다른 제작 방식과 프로젝트의 속도를 현재 작업에 대입하지 않기 위해서입니다. |
| 마지막 실행 조각만 측정된 기록으로 남은 시간을 표시하지 않는다 | 중간 저장·재시도 시간이 빠진 기록으로 전체 시간을 예측하지 않기 위해서입니다. |
| 초안 확인을 기다릴 때 예상 남은 시간을 표시하지 않는다 | 사용자 확인을 기다리는 상태를 자동 작업 중으로 보이지 않게 하기 위해서입니다. |
| 예상 시간을 숨긴 상태에서는 다른 프로젝트의 실행 기록을 읽지 않는다 | 표시하지 않는 추정값을 만들기 위한 불필요한 조회를 없애기 위해서입니다. |

새 테스트 5건을 먼저 작성해 **5건 실패**를 확인했고, 제품 코드 수정 후 관련 4개 파일 **21건이 모두 통과**했습니다. 타입 검사와 변경 파일 린트도 통과했습니다. 기존 실패 테스트의 기대값·문장·제외 설정은 변경하지 않았습니다.

실행 명령:

```text
node node_modules/vitest/vitest.mjs run tests/writer/status-eta.test.ts tests/writer/status-assets.test.ts tests/writer/status-sharing.test.ts tests/writer/progress-scope.test.ts
node node_modules/typescript/bin/tsc --noEmit
node node_modules/eslint/bin/eslint.js src/lib/writer/run-store.ts src/lib/writer/use-writer-status.ts src/app/api/writer/status/[projectId]/route.ts tests/writer/status-eta.test.ts
```

증거: `eta-red.txt`, `eta-green.txt`, `eta-typecheck.txt`, `eta-lint.txt`.

## 향후 정확한 예측에 필요한 기록

실제 처리한 모든 실행 조각·실패 시도의 소요 시간, 검토 대기 시작·종료, 작업 당시 입력 길이·모델·제작 방식, 초안 작성 구간과 샷·대사 저장 구간을 구분해 기록해야 합니다. 같은 조건의 표본이 쌓인 뒤 실제 오차를 확인하고 표시 여부를 정할 수 있습니다. 이번에는 이 수집 체계와 새 예측 모델을 구현하지 않았습니다.

수정 파일: `src/lib/writer/run-store.ts`, `src/app/api/writer/status/[projectId]/route.ts`, `src/lib/writer/use-writer-status.ts`(주석), `tests/writer/status-eta.test.ts`.

실제 유료 모델 실행, 운영 반영은 수행하지 않았습니다.
