# 추가 피드백 처리

사용자 지시: 근거 없는 시간은 숨기거나 정확하게 고친다. 내부 처리 단계는 제품 화면에 노출하지 않는다. 보고서의 불필요한 상단 버튼을 정리한다. 12·13·14번은 승인했다. Director 이동을 반복 예고하고 실행하지 않는 새 사례를 등록한다.

- 화면 정리: 검수용 가짜 버튼 줄을 삭제하고 실제 승인 카드와 보류 목록을 다시 캡처한다.
- 진행 표시 약속: “씬·샷을 준비하는 동안 내부 처리 단계 수 대신 현재 만들고 있는 결과를 알려준다.”
  왜: 처리 단계 개수는 완성된 씬·샷 개수나 남은 시간을 뜻하지 않는다.
- 시간 표시 약속: “남은 시간을 뒷받침할 실행 기록이 없으면 분·초 예상값을 표시하지 않는다.”
  왜: 승인 대기·누락된 실행 시간이 섞인 표본을 단순 보정하면 다시 잘못된 숫자가 된다.
- 알림 약속: “보고 있는 단계에서 완료된 결과는 다른 단계로 떠난 뒤에도 미확인으로 다시 표시하지 않는다.”
- 알림 약속: “프로젝트를 바꾼 뒤 이전 프로젝트의 늦은 응답은 현재 알림에 섞이지 않는다.”
- 검증: 수정 전 실제 표시/모듈 실패 → 최소 수정 → 해당 회귀, 타입, 디자인, lint 및 화면 캡처. 기존 두 실패 테스트의 기대는 변경하지 않는다.
- 다른 세션이 인계받은 채팅 도구 파일은 수정하지 않는다. 과거 일회성 완료 콜백은 재전송하지 않는다.
- 후속 지시 반영: 프로그레스바는 유지한다. 분·초와 내부 단계 숫자만 숨기며 중앙·채팅의 막대가 같은 상태를 읽는다. 브라우저 검사도 이 명시적 변경에 맞춰 막대 2개 유지·저장 전 미완료를 검사한다.
