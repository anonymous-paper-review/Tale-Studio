2

공통 동작과 실제 복구

요청 → 현재 값 조회 → 작은 편집 실행 → 저장·승인·실패 결과 반환 → 필요 시 입력 수정·재조회·재시도 → 저장값 확인

도구는 read_project와 edit_project 두 개다. 지원하는 조회·편집은 정상 처리부터 도구를 쓰고, 같은 실행 함수를 복구에도 쓴다. 생성·삭제·이동 등 기존 기능은 기존 처리 경로를 유지한다.

상황처리·검증 결과
저장 실패인물 이름 변경의 첫 PATCH만 서버 도달 전에 503으로 차단했다. 모델이 실패 결과를 받고 같은 편집을 다시 호출했다. 다음 API 응답 200과 DB 값 일치를 확인했다.
도구 미선택배경 설명을 조회한 모델이 편집 도구 없이 답변을 끝냈다. 앱이 한 번 더 실행을 요구하자 편집 도구를 호출했고 승인 대기로 이어졌다. 추가 사용자 메시지는 없었다.
잘못된 입력·낡은 조회값허용 필드·대상·조회 버전을 검사한다. 문제가 있으면 실행 결과를 돌려 입력 수정·재조회하도록 한다. 이 경계는 고정 응답·DB 모형 테스트로 확인했다.
저장 응답 유실·일부 완료저장 여부를 다시 읽고 확인한다. 후속 답변 실패·중단 때 이미 저장한 결과를 남긴다. 저장 결과가 불확실하면 완료로 표시하지 않는다. 자동 테스트로 확인했다.
승인·반복 실행승인 전 원천 변경을 보류한다. 같은 도구 호출의 중복 실행과 반복 실패를 제한하고, 성공한 대상은 유지한다. 승인 전후 DB 확인은 Producer·배경 표본에서 수행했다.

성공한 요청 4개에서 채팅 API 왕복은 각각 3·3·4·4회였다. 요청 시간 합은 약 13~18초였으며, 승인 대기·별도 저장·브라우저 조작 시간은 제외했다. 성능 보장 수치가 아니다.

발견·수정한 결함

문제확인 근거수정
Writer 화면에서 Artist로 전송실제 Writer 화면의 첫 요청이 Artist API로 나가 씬·샷 편집을 거절했다.현재 화면의 단계를 전송에 명시했다. 같은 요청을 Writer API로 다시 보내 씬·샷·대사를 저장했다.
저장 실패인데 완료처럼 보이는 답변실패 결과와 모델의 성공 문장이 충돌하는 자동 재현.실패·승인 대기 시 실행 결과를 우선 표시하고 중복 JSON 변경을 막았다.
샷 길이만 저장되는 부분 실패샷 저장 후 씬 총길이 갱신 실패·응답 유실을 자동 재현.부분 완료로 반환하고 재시도 시 씬 총길이까지 다시 맞추도록 했다.
이전 예약 저장이 새 대사를 덮음화면 저장 예약/응답 대기 각각에서 완료된 한국어 대사가 옛 대사로 복귀하는 테스트 2개 실패 확인.같은 샷의 저장 순서를 보장하고 예약 실행 시 최신 대사를 읽는다. 대사와 앞선 화면 편집을 함께 보존하는 테스트 통과.
소품 조회의 없는 DB 컬럼DEV DB에서 props.role 조회 오류 확인.실제 컬럼만 조회하고 소품의 역할 변경은 거부한다.

이번 Writer 전송 오류를 과거 “일본어로 확정돼 변경할 수 없다” 응답의 원인으로 단정하지 않는다. 과거 발화의 당시 상태는 재현하지 않았다.

남은 범위와 구현 선택

항목현재 상태·후속 확인
UI 전체와 채팅 대조이번은 조회·편집 공통 기반과 대표 표본이다. 생성·삭제·모습 변형·후보 선택·배경 개명·스타일 등 모든 UI 동작을 새 도구로 연결하지 않았다. 기존 전수조사 목록은 남아 있다.
단계별 도구 노출설정 도구는 Producer, 씬·샷·대사는 Writer, 인물·배경은 Writer·Artist에 노출한다. 어느 단계에서든 모든 도구를 사용할 수 있는 상태는 아니다.
확인된 잔여 · 인물 개명Artist에서 도윤→도윤 검증을 저장한 뒤 Producer 재접속에 두 이름이 모두 표시됐다. 초안과 DB를 이름으로 병합하는 기존 복원 로직 때문이다. DB 인물 행은 1개다. 언어와 함께 초안·확정본 동기화 묶음으로 우선 수정할 항목이다.
확인된 잔여 · 배경 설명Artist DB에는 새 설명이 저장됐지만 Producer 재접속 입력칸에는 옛 설명이 남았다. 이름이 같은 배경은 초안 값을 우선하는 병합 로직을 확인했다.
확인된 잔여 · 단계 간 언어Producer는 초안(producer_draft)을 저장하고 Writer 채팅은 확정본(settings)을 읽는다. 실제 DB는 초안 ko / 확정본 ja다. 확정본 갱신은 기존 Writer 인계에 연결돼 있다. 언어만 즉시 전파할지, 인계 규칙을 조정할지는 별도 수정 범위로 남겼다.
미검증 · Producer러닝타임·장르·포맷·톤 변경의 실제 LLM 표본 및 다양한 말투. 자동 검사만 통과했다.
미검증 · Writer많은 샷 일괄 수정, 다른 탭·사용자와의 동시 편집, 모든 씬·샷 필드의 실제 호출. 두 샷의 결과로 대량 처리까지 보장하지 않는다.
미검증 · Artist역할·설명·기본 외형 변경의 실제 LLM 저장, 외형의 다른 모습·후보 조작. 배경은 기본 설명 1건만 실제로 확인했다.
LLM 해석 품질한국어 대사에 。를 쓴 사례가 남았다. 도구 실행 성공은 사용자 문장의 정확한 해석까지 보장하지 않는다. 다양한 발화·불필요한 거절은 사용 피드백으로 추가한다.
복구 한도현재 내부 기본값: 모델 왕복 6회 / 도구 실행 16회 / 같은 실패 2회. 명시적 편집의 도구 누락은 한 번 재확인한다. 확정 제품 정책이 아니며 코드에서 조정 가능하다. 대규모 편집은 한도에 걸릴 수 있다.
기록·성능채팅의 기존 토큰·적용 수 표시는 도구 전체 왕복을 합산하지 않는다. 전체 실행 이력의 영속화·총비용 표시·진행 중 재접속 복구는 후속 범위다.
충돌 보장 범위Writer는 저장할 DB 값의 변경 여부도 비교한다. Producer·Artist의 읽기→쓰기 전체가 하나의 원자적 트랜잭션인 것은 아니다. 여러 브라우저 동시 수정은 미검증이다.
운영 반영코드는 dev 작업 공간에만 있다. 새 의존성·DB 마이그레이션·커밋·배포를 추가하지 않았다. 이전 MVP 변경과 Director 연계를 보존했다.
6

화면 검증의 한계

실제 화면의 DOM과 채팅 요청·저장 결과는 확인했다. 제품 화면 PNG 수집은 완료하지 못했다. Orca 캡처의 표시/포커스 오류와 별도 브라우저의 로드·선택자 대기 오류를 기록했다. 화면 이미지로 결과를 검수할 수 있는 자료는 아직 없다.

이 보고서 자체는 밝은·어두운 테마와 390px 화면에서 렌더를 확인했다. 제품 화면 캡처와 혼동하지 않는다.

7

사용자가 할 일

다음 수정 우선순위는 초안·확정본 동기화다. 언어·인물 개명·배경 설명을 같은 묶음으로 대조하면 된다. 이번 공통 루프 구현·검증을 마치기 위해 사용자가 직접 할 필수 작업은 없다. 평소 사용 중 이상한 응답이 나오면 단계 / 한 말 / 기대 결과 / 실제 결과만 주면 된다. 그 사례의 실행 기록·저장값·회귀 테스트는 에이전트가 확인한다.

기존 Artist 테스트 2개의 검사 방식 교체 판정은 MVP 보고서의 대기 항목으로 유지한다.
