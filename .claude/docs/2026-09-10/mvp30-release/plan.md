# 30번 수정과 main 배포

사용자 승인: 실패한 기존 두 검사의 개선,30번 수정,검증 뒤 main 즉시 배포. 재승인 요청 없이 진행한다.

확정한 경험:
- Writer에서 Director로 넘겨 달라고 하면 실제 저장 상태와 이동 조건을 확인하고 가능한 경우 Director 화면을 연다.
- 못 넘어가면 빠진 대상·막힌 이유와 어느 화면에서 무엇을 해야 하는지 알려준다.
- 이동 가능한지 묻는 질문에는 조건을 답하고,이후 ‘넘겨줘’는 앞서 사용자가 지정한 Director로 이어진다.
- 이미 이동 가능한데 대사 언어를 임의로 다시 묻거나 변경하지 않는다. 대사 변경은 명시된 수정 요청만 처리한다.
- 실제 화면이 열리기 전에는 이동 성공 표식을 남기지 않는다. 저장·권한·화면 이동 실패를 숨기지 않는다.
- 두 테스트는 인물·배경 새 모습 생성 약속을 유지하며 실제 승인·접수 동작을 검사한다.

원인 확인: 채팅은 adjacent handoff만 인식해 Writer→Director와 대상생략 후속 지시가 일반 모델 대화로 내려간다. readiness는 Artist 화면에서만 계산돼 Writer에서는없거나낡았다. stage-nav는DB수정오류를무시하고,currentStage변경과router호출만으로성공을표시한다.

진행: 신규 실패 회귀→최소 실행 경계 수리→통합·브라우저검증→main기준별도체크아웃에MVP범위선별통합→전체검사·빌드→mainpush·Vercel·필요migration검증→운영smoke·한국어보고갱신.
