채팅 도구와 실험

채팅에 현재 값 조회·편집 도구 2개와 실행 결과를 돌려받는 흐름을 연결했다. 관리자 계정에서 바로 열어볼 실험 프로젝트 3개를 준비했다.

추가 결정 요청은 없다. 아래 P1·W1·A1을 먼저 사용하고, 답변과 실제 저장값이 다른 사례를 알려주면 된다.

1

추가한 도구 2개

Tool call은 모델이 앱의 함수를 호출하도록 요청하는 것이다. 실제 저장은 앱이 수행하고, 모델은 그 결과를 받아 다음 행동을 판단한다.

도구앱이 수행하는 일“첫 샷을 9초로”의 예
read_project현재 프로젝트의 지원 항목을 읽는다.첫 샷의 실제 ID와 현재 길이 8초를 확인한다.
edit_project조회했던 항목의 요청한 값을 변경하고 저장·승인·실패 결과를 반환한다.첫 샷을 9초로 저장하고, 다시 읽은 값이 9초인지 확인한다.
  1. 사용자: “첫 샷을 9초로 바꿔줘.”
  2. 모델 → read_project → 앱: “첫 샷은 현재 8초.”
  3. 모델 → edit_project → 앱: 저장 후 “9초 저장 확인.”
  4. 모델: 실행 결과를 받은 뒤 변경 내용을 답한다.

일시 저장 실패라면 실패 결과도 모델에게 돌아간다. 남은 실행 한도 안에서 재조회·입력 수정·재시도를 이어갈 수 있다.

이전에도 JSON 명령으로 편집은 했다. 이번에는 실제 실행 결과가 모델에게 돌아가 같은 요청의 다음 행동을 판단할 수 있게 연결했다. 두 도구는 정상 조회·편집부터 사용하며, 실패 복구에도 재사용한다.

도구에 넘기는 값도 JSON이다. 새 Agent SDK나 bash 실행 권한을 추가한 작업은 아니다.

단계이번 두 도구가 다루는 범위
Producer러닝타임·장르·세부 장르·포맷·톤·대사 언어. Producer 초안 기준.
Writer씬·샷·대사·인물·배경의 지원 필드 조회·편집.
Artist인물 이름·역할·설명·기본 외형, 배경 설명 조회·편집.
Director이번 신규 연결 범위에서 제외.

먼저 해볼 실험 3개

DEV의 admin@tale.studio로 로그인한다. 아래 링크는 각각 별도 프로젝트를 연다. 다른 브라우저에서는 로그인 후 같은 실험 링크를 다시 열면 된다.

개발 서버: 127.0.0.1:3001. 같은 컴퓨터에서 사용한다. Producer에 스타일 선택 창이 뜨면 닫는다. 채팅 입력은 각 화면 오른쪽이다.

프로젝트는 다시 열어도 초기화되지 않는다. 반복 실험은 같은 항목을 이전 값으로 돌리는 요청을 사용한다. 단계마다 위 전용 링크를 열면 서로의 실험 데이터가 섞이지 않는다.

확인 결과와 남은 한계

구분확인한 것확인하지 않은 것·한계
이번 프로젝트 전달 수정기존 링크의 프로젝트는 테스트 계정 소유였다. 새 3개는 DEV 관리자 소유이며, 로그인된 브라우저에서 요청한 프로젝트 ID와 실제 열린 ID의 일치를 확인했다.새 3개는 사용자가 시작할 초기값을 유지했다. 여기서 변경 실험을 다시 실행한 것은 아니다.
앞선 실제 채팅 검증Producer 설정 6필드, Writer 씬·샷·대사·인물·배경, Artist 인물·기본 외형의 대표 변경을 실제 LLM·DEV 저장·재조회로 확인했다. Artist 배경 편집은 앞선 표본에서 확인했다.전체 UI 기능, 지원 필드의 모든 조합, 다양한 표현의 반복 성공률은 미검증.
실패 복구인물 저장에 일시 오류(503)를 한 번 주입했다. 실제 모델이 재조회·재시도로 저장하는 표본을 확인했다.오류 응답 한 번을 시험용으로 주입했다. 가이드의 일반 채팅으로 같은 장애가 자동 발생하지 않는다. 모든 오류의 자동 해결은 보장하지 않는다.
언어·이미지언어 설정과 외형·배경 설명의 저장을 확인했다.Producer 언어 설정만 바꿔도 기존 대사가 자동 번역되지는 않는다. 설명 변경만으로 그림이 바뀌지는 않는다. 이미지·영상 생성과 품질은 이번 범위 밖.
단계 간 동기화Producer 초안과 Writer·Artist 저장값을 별도로 확인했다.Producer 초안→확정 언어 전파, Artist 개명 뒤 Producer 옛 이름 중복, 배경 초안의 옛 설명이 남는 문제가 있다. 전 단계 동기화 완료로 볼 수 없다.
복구·재접속 경계승인 카드 새로고침 복원과 성공 대상 보존을 확인했다.새 일시 오류 분류는 인물 API에 연결했다. 재조회만 하고 확인용 편집을 생략하면 옛 실패 표시가 남을 수 있다. 다중 탭 동시 수정·브라우저 종료 후 진행 중 작업 자동 재개는 미검증.
자동 검사 · 앞선 실행 기록2,852 통과 · 실패 0 · 기존 22 제외. 타입·디자인 통과. 소스 lint 오류 0·기존 경고 24.자동 테스트 수는 LLM 성공률이 아니다. 이번 전달 수정은 제품 소스를 바꾸지 않아 전체 검사를 다시 실행하지 않았다.

초기 화면과 전달 기록

관리자 실험 프로젝트의 실제 화면 4장

2026-09-10 관리자 브라우저에서 촬영. 준비된 그림은 저장소의 정적 템플릿이다. 새로 생성한 이미지가 아니다.

이번에 정한 준비 방식
선택이유·되돌리기
단계별 관리자 소유 프로젝트 3개기존 계정 권한을 바꾸지 않고 각 실험을 독립적으로 열게 했다. 되돌리기 쉬움: 전용 프로젝트만 정리 가능.
초기값과 정적 이미지 준비생성 대기 없이 조회·편집부터 확인한다. 기존 사용자 프로젝트는 편집하지 않았다.
제품 정책 변경 없음이번 작업은 프로젝트 준비·접근 확인·가이드 수정이다. 일반 실행 허가를 다시 받을 항목은 없다.

근거: 관리자 접근·초기 화면은 .smoke/chat-tools-owner-20260910/. 앞선 실제 LLM·저장·복구·자동 검사는 .smoke/chat-tools-lab-20260910/. 구현 대조는 src/lib/chat-tools/{protocol,loop,executor}.ts와 src/stores/chat-tool-bindings.ts.

기존 가이드의 “직접 사용” 프로젝트를 관리자 계정에서도 바로 열 수 있다는 전제가 잘못됐다. 이번에 관리자 소유의 프로젝트와 링크로 교체했다. 커밋·배포·운영 DB 변경은 없다.
