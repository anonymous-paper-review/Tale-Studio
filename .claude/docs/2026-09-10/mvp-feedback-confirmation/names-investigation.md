# MVP-09: 원래 입력부터 모델 응답과 저장본까지 확인

**`vending_machine_corner`는 사용자 입력이 아니라 모델이 만든 장소 식별자였고, 9월9일22:03:40 씬 모델 응답에서 처음 사람용 문장으로 새어 나왔습니다.** 저장본과 같은 문장이며, 과거 실행 미리보기에서 당시 장소 이름을 누락한 표시 경로도 수정했습니다.

운영 원본 프로젝트 `7112d31e-70ce-4743-9562-057f7beac002`만 읽기 전용으로 조회했습니다. 원문 story_text와 producer_draft에는 해당 토큰이 없었습니다. 앞선 조사는 최근 debug_events에 치우쳐 이미 남아 있던 llm_calls36개를 충분히 조회하지 못했습니다. 오너가 입력을 다시 제공할 필요는 없었습니다.

| 시각(KST) | 확인한 사실 |
|---|---|
| 9월9일22:03:02.447 | dramaturgy 원본 응답에 `id: vending_machine_corner`, `name: 교내 자판기 코너`가 처음 생깁니다. 구조적 식별자 생성 자체는 정상입니다. |
| 22:03:40.053 | scenes 원본 응답의 scene_actions에 ‘쿄타로가 체육관 옆 vending_machine_corner에서 음료수를 뽑고 있다.’가 들어갑니다. |
| 현재 보존된 실행 상태 | 위 문장이 그대로 남아 있습니다. 해당 씬의 대표 장소는 별도의 `location_2`였고, 자판기 코너는 본문에만 등장한 후보여서 최종 장소 목록에서 빠졌습니다. |
| 기존 운영 미리보기 | 최종 등록 이름만 읽어 자판기 코너 후보의 이름을 찾지 못했습니다. |

당시 모델은 gemini-3-flash-preview입니다. 호출 식별자는 각각 `2dc98d0f-fbe5-4fed-9cb1-aa1d99b440b7`, `a3c9931d-944e-40a2-86fd-398333f49f9b`입니다. 이 프로젝트의 실행은1개이고 응답·저장 문장 및 실행 시간대가 일치합니다. archive의 run_id가 비어 있어 명시적 외래키 연결로 확인한 것이라고 표현하지 않습니다. 당시 배포 커밋도 확정하지 않았습니다.

`char_2`의 생성 경로는 별개로 확인했습니다. 이름에서 영문자를 뽑아 식별자를 만드는 기존 코드가 일본어·한국어 이름에서 빈 문자열을 얻으면 `char`를 쓰고, 다음 인물에는 `_2`를 붙입니다. 실제 원본 프로젝트에서 `char`=쿄타로, `char_2`=코마츠이고, 첫 모델 요청에 이미 이 대응이 들어 있습니다. 구조 칸의 ID 자체는 정상입니다. ‘char2가 다른 단계에 노출’됐다는 제보의 최초 화면 시각까지 확인한 것은 아닙니다.

새 실행은 앞선 이름 정규화·본문 검사와 후보 장소 병합 수리를 사용합니다. 이번에는 과거 실행 미리보기에도 보존된 후보 이름을 최후의 대체 이름으로 추가했습니다. 이미 확정된 이름이 우선이며 원본 저장 상태는 바꾸지 않습니다. 이름이 전혀 없는 토큰을 임의로 번역하지 않습니다.

약속과 이유:
- **과거 씬에 남은 장소 식별자는 같은 실행에 보존된 장소 이름으로 보여준다.** 왜: 본문에만 등장해 최종 장소 목록에 빠진 실제 제보 문장이 있습니다.
- **확정한 장소 이름이 있으면 예전 후보 이름으로 덮어쓰지 않는다.** 왜: 이미 이름을 바꾼 장소가 오래된 이름으로 되돌아가면 안 됩니다.
- **이름이 기록되지 않은 장소는 새 이름을 지어내지 않는다.** 왜: 없는 이름을 만들어 입력 내용을 바꾸면 안 됩니다.
