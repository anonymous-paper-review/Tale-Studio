# 프로토 v04 반영 계획 — 그룹 5개, 순서대로

> 근거: `.claude/docs/2026-09-28/proto-v04-diff.html`(기획안 대조 보고서). 기획안 = `~/Downloads/ref/tale-proto-v04.html`.
> 작업 브랜치 `dev`. 그룹 하나가 끝날 때마다 `.claude/docs/<날짜>/proto-v04-g<N>-report.html`로 보고서를 낸다.
> 이 문서는 계획이다. 각 그룹의 동작 목록("~이면 ~한다")은 그 그룹을 시작할 때 이 문서 아래에 적고, 테스트 이름으로 그대로 쓴다.

## 한 문장으로

앞 단계(Producer)는 넘긴 뒤 잠그고, 뒤 단계(Writer·Artist)는 손으로 직접 만지게 풀되, 사람과 에이전트가 같은 것을 동시에 잡는 순간만 잠근다.

## 순서와 이유

```
그룹 1 점유와 잠금 ─→ 그룹 2 편집 팝업 셋 ─┬→ 그룹 3 넘기기 점검
                                          └→ 그룹 4 Artist에 샷 데이터 연결 ─→ 그룹 5 탐색·뷰
```

- 1이 먼저: 2·3의 팝업이 전부 "지금 누가 이걸 잡고 있나(사람 / 에이전트 / 아무도)" 상태 위에 선다.
- 2 다음에 3·4는 병렬 가능. 5는 각각 독립이라 언제 해도 된다.
- 따로 두는 둘: **첫 입력 A/B/C + 로그라인 카드**(대화 전략이라 화면 그룹에 안 걸림, 별도 실험), **Writer 로딩 화면**(기획자가 "검토 필요"로 남김. 결정 뒤에).

## 그룹별 범위

| 그룹 | 항목 | 재사용할 것 | 새로 만들 것 |
|---|---|---|---|
| **1 · 점유와 잠금** | 넘긴 뒤 Producer 잠금 배너 · 산문 변경 검토(적용/되돌리기) · 검토 중 포맷·넘기기 잠금 · Writer 채팅 변경 되돌리기 · Artist 제안 카드 표시와 되돌리기 | 승인 카드 `pendingProposal` · `evaluateProducerSourceImpact`(정의만 있음) | 잠금 상태 판정 · 문단 비교 · 이전 값 보관 |
| **2 · 편집 팝업 셋** | Producer 산문 고치기(직접 팝업 / ✦ 다시 쓰기) + 직접 고치는 동안 채팅 잠금 · Writer 샷 팝업 하나로(편집 = 추가 = 대본 클릭, 텍스트 폼 부활, '추가하고 러프 그리기') · Artist 상세 팝업(모습 목록 · 레퍼런스 추가/삭제 · 정보 부족 표시) | 3프레임 나열 · 화살표 그리기 · 모습 관리줄 · 씬 추가 위치 선택 | 산문 편집기 · 샷 텍스트 폼 · 레퍼런스 업로드 |
| **3 · 넘기기 점검** | Producer→Writer 확정 팝업(이야기·언어·화면 + "확정할게요" 체크) · Writer 헤더 'Director로 · 준비 N/9' + 그 자리에서 채우기 | 게이트 판정 `producer-gate.ts` · `project-handoff.ts` | 채팅 글을 팝업으로 |
| **4 · Artist에 샷 데이터 연결** | '쓰인 샷' 칩 · 삭제 경고 "샷 N개에 나와요" · 샷 단위 Director 점검 · Writer 서랍의 '나오는 샷' | 없음 | `artist-store`가 샷을 읽는 경로 |
| **5 · 탐색·뷰** | 인물·배경 필터 + 씬 칩 + 자동 접기 · 드래그 정렬 · 마스터 시트(A4/PDF) · 로드맵 띠 · 2탭 합치기 · 인물·배경 서랍 | 컨택트 시트 합성 · 샷 `cast` · `sortOrder` | 각 뷰 |

## 시작 전에 오너 답이 필요한 것

대조 보고서 4절 그대로. **그룹 2를 시작하기 전**까지 답이 있어야 한다. 그룹 1은 이 답 없이 진행한다.

1. 프로토가 뒤집는 옛 오너 결정 3건 — ① Artist '+ 인물 추가'(2026-07-15 제거) ② Artist 카드 생성·전체 생성 버튼(2026-08-31 제거) ③ Writer 샷 팝업 텍스트 편집 폼(2026-08-09 제거). 되살림 / 유지 / 되살리되 과금 버튼만 확인 팝업.
2. Producer 산문 편집 진입점 — 전체 덮는 팝업(추천) / 인라인 / 채팅만.
3. Writer 탭 — 2탭(러프 | 대본, 추천) / 3탭 유지.
4. 프로토 안의 "확인 필요" 3건 — 홈 '불러오기' 정체 · 장르를 포맷 항목으로 두나 · Writer 로딩이 길 때.

## 각 그룹 진행 방식

1. 그룹 시작: 이 문서 아래에 **동작 목록**을 적는다 — 같이 정한 것 / 혼자 정한 것(동작 · 왜 · 버린 선택지 · 되돌리기). `비쌈` 이상은 오너 확인 전 구현 금지(`.claude/rules/tdd.md`).
2. 문장을 이름으로 한 테스트를 먼저 쓴다(`tests/<묶음>/`). 화면 생김새는 테스트 대신 dev 스크린샷.
3. 구현 → `pnpm typecheck && pnpm lint:design && pnpm test` → dev 브랜치 커밋.
4. 보고서 발행(artifact 표준): 동작 목록 그대로 + 이전|이후 스크린샷 + 혼자 정한 것 + 결정이 필요한 것.

## 그룹 1 · 점유와 잠금 — 동작 목록 (2026-09-28)

### 설명

Writer로 넘긴 뒤 Producer에 다시 들어오면 산문과 포맷은 보기·복사만 되고 고칠 수 없다. 산문이 확정된 뒤 에이전트가 산문을 고치면 바로 덮어쓰지 않고 바뀐 문단을 보여준 채 적용·되돌리기를 묻는다. Writer에서 에이전트가 샷을 고치면 바뀐 샷이 표시되고 되돌릴 수 있다. Artist에서 에이전트 제안이 대기 중인 카드는 표시가 붙고, 승인한 글 변경은 되돌릴 수 있다.

### 같이 정한 것 (기획안 + 오너 요약)

Producer
- P1. Writer로 넘긴 뒤 Producer에서는 산문·제목·인물·배경·스타일·장르·톤·포맷·대사 언어를 고칠 수 없고 보기·복사만 된다.
- P2. 넘긴 뒤 Producer 상단에 "Writer와 Artist가 이 포맷과 산문을 기준으로 작업하고 있어요" 배너와 '새로 만들려면?' 버튼이 보인다.
- P3. '새로 만들려면?'을 누르면 새 프로젝트를 만들어 산문을 옮기는 방법을 안내한다.
- P4. 산문이 확정된 뒤 채팅이 산문을 바꾸면 바로 덮어쓰지 않고 바뀐 문단을 표시한 채 적용·되돌리기를 묻는다.
- P5. 적용을 누르면 새 산문이 들어가고, 되돌리기를 누르면 원문이 그대로 남는다.
- P6. 산문 변경을 검토하는 동안 포맷 뱃지와 Writer로 넘기기가 잠긴다.

Writer
- W1. 채팅으로 샷이나 씬을 고치면 바뀐 카드가 표시된다.
- W2. 러프 보드 위 띠에 "에이전트가 N개를 고쳤어요"와 적용·되돌리기가 보인다.
- W3. 되돌리기를 누르면 바꾸기 전 내용으로 돌아간다.
- W4. 적용을 누르면 표시가 사라지고 내용은 그대로 남는다.

Artist
- A1. 에이전트 제안이 대기 중이면 그 인물·배경 카드에 "에이전트 제안 확인 중" 표시가 붙고 그 카드의 모습 추가와 팝업 열기가 잠긴다.
- A2. 채팅으로 인물 외형이나 배경 설명을 바꾸는 제안을 승인한 뒤에는 되돌리기로 이전 문장으로 돌아갈 수 있다.

### 혼자 정한 것

| 동작 | 왜 | 버린 선택지 | 되돌리기 |
|---|---|---|---|
| P7. 넘긴 뒤에도 러닝타임과 채팅 언어는 계속 고칠 수 있다 | 프로토 1L-d 제안 그대로. 러닝타임은 목표값이라 Writer에서 샷이 늘면 합계가 느는 게 정상이고, 채팅 언어는 작업물에 영향이 없다 | 전부 잠금 | 쉬움 |
| P8. 산문이 아직 확정되지 않은 동안(살아있는 초안)에는 채팅이 산문을 그대로 갱신한다 | 첫 대화에서 매 턴 초안이 자란다. 매번 적용을 물으면 대화가 멈춘다. 검토는 `storyReady`가 참이 된 뒤부터 | 항상 검토 | 쉬움 |
| P9. 잠긴 항목을 누르면 "넘긴 뒤에는 고칠 수 없어요 · 바꾸려면 새 프로젝트" 안내가 뜬다 | 프로토 1L "고치려고 하면 무엇이 영향을 받는지 먼저 알려준다" | 조용히 무시 | 쉬움 |
| P10. 산문 검토 카드의 버튼은 '적용'과 '되돌리기' 둘이다('나중에' 없음) | 프로토 1-f 그대로. 검토 중엔 포맷이 잠기니 미루면 보드가 멈춘다 | 승인·나중에·요청 취소 3버튼 유지 | 쉬움 |
| P11. 직접 고치는 동안 채팅 잠금은 그룹 2(산문 팝업)에서 팝업과 함께 넣는다 | 지금 보드의 직접 편집은 작은 팝오버라 잠글 순간이 없다. 프로토도 잠금을 팝업에 묶는다 | 팝오버 열림 동안 채팅 잠금 | 쉬움 |
| W5. 되돌리기는 마지막 채팅 한 번의 변경 묶음만 되돌린다 | 이력 스택은 그룹 5(드래그 정렬)와 함께 | 여러 단계 되돌리기 | 쉬움 |
| W6. 새 채팅 변경이 오면 이전 묶음은 적용된 것으로 본다 | 띠가 둘 이상 쌓이면 어느 것을 되돌리는지 헷갈린다 | 여러 띠 | 쉬움 |
| W7. 채팅이 샷·씬을 추가하거나 지운 것은 되돌리기 대상이 아니고 띠에 "추가·삭제는 되돌릴 수 없어요"로 알린다 | 지운 행은 DB에서 사라져 같은 id로 못 돌린다 | 추가·삭제도 되돌리기 | 쉬움 |
| A3. 되돌리기는 마지막 승인 한 건만 | W5와 같음 | 스택 | 쉬움 |
| A4. 모습 삭제·재생성 승인은 되돌리기 대상이 아니다 | 서버에서 지워지거나 과금이 된다. 승인 카드 impact에 이미 "되돌릴 수 없어요"가 있다 | 삭제 되돌리기 | 쉬움 |

`비쌈` 이상 없음 → 오너 확인 없이 구현 시작. 보고서에 그대로 싣는다.

## 그룹 2 · 편집 팝업 셋 — 동작 목록 초안 (2026-09-29, 오너 답 대기 중) → 아래 "확정본"으로 대체됨

> 아래는 **초안**이다. 결정 ①②③(위 "시작 전에 오너 답이 필요한 것" 1번)에 따라 표시된 항목이 빠지거나 바뀐다. 답이 오면 이 절을 확정본으로 고치고 테스트를 쓴다.

### 설명

Producer 산문을 팝업에서 직접 고치거나(그동안 채팅 잠김) ✦ 다시 쓰기로 에이전트에게 맡긴다. Writer 샷은 카드 클릭·샷 추가·대본 줄 클릭이 전부 같은 팝업으로 열리고, 시작(지문·인물·배경·대사·샷 크기·앵글)과 연출(그리기+텍스트)을 두 묶음으로 고친다. Artist 카드 팝업에 모습 목록·레퍼런스 추가/삭제·정보 부족 표시가 들어간다.

### 같이 정한 것 (기획안 + 오너 요약)

Producer — 결정 2(산문 편집 진입점)가 "팝업"이면
- P12. 산문 카드의 '고치기'를 누르면 '직접 고치기'와 '✦ 다시 쓰기' 둘 중 하나를 고른다.
- P13. 직접 고치기를 열면 화면 전체를 덮는 팝업에서 산문을 고치고, 그동안 채팅 입력이 잠긴다.
- P14. 팝업에서 적용하면 산문이 바뀌고 채팅에 "직접 고쳤어요" 한 줄이 남는다. 취소하면 아무것도 안 바뀐다.
- P15. ✦ 다시 쓰기를 누르면 에이전트에게 요청이 가고, 결과는 그룹 1의 산문 검토(적용/되돌리기)로 온다.
- P16. 에이전트가 산문을 고치는 동안 직접 고치기 버튼은 '취소하기'로 바뀌고, 누르면 에이전트 요청을 멈춘다.

Writer — 결정 ③(텍스트 폼 부활)이 "되살림"이면
- W8. 러프 카드 클릭·'+ 샷'·대본(트리트먼트) 샷 줄 클릭이 전부 같은 샷 팝업을 연다.
- W9. 샷 팝업 위에 시작·연출·끝 세 장, 아래에 '시작 고치기'(지문 · 등장인물 · 배경 · 대사 · 샷 크기 · 앵글)와 '연출 고치기'(그리기 + 텍스트) 두 묶음이 있다.
- W10. 시작 고치기를 저장하면 연출·끝 프레임이 다시 그려지고, 연출 고치기만 저장하면 끝 프레임만 다시 그려진다.
- W11. '+ 샷'으로 연 팝업에는 '추가만'과 '추가하고 러프 그리기' 두 버튼이 있고, 닫으면 추가되지 않는다.
- W12. 러프가 없는 샷을 대본에서 열면 '저장하고 러프 그리기'가 보인다.
- (③이 "유지"면 W9의 시작 고치기 묶음이 빠지고 W8·W11·W12만 남는다. 텍스트는 종전대로 채팅.)

Artist — 결정 ①②에 따라
- A5. 카드 팝업에 모습 목록(보기 · 삭제 · + 모습 추가하기)이 있고, 보기를 누르면 왼쪽 이미지가 그 모습으로 바뀐다.
- A6. 카드 팝업에서 레퍼런스 이미지를 올리고 지울 수 있다(모습당 여러 장).
- A7. 외형 문장이 없는 인물 카드에 '정보 부족' 표시와 '채우기 / 건너뛰기'가 붙고, 건너뛴 인물은 Director 점검에서 "건너뜀"으로 보인다.
- A8. (①이 "되살림"일 때만) 도구줄에 '+ 인물 추가'가 있고 Producer 카드와 같은 곳에 저장된다.
- A9. (②가 "되살림"·"확인 팝업"일 때만) 도구줄에 전체 선택 · 선택 생성 · 전체 생성이 있고, 생성 전에 "N장 · 과금" 확인 팝업이 뜬다.

## 그룹 2 · 편집 팝업 셋 — 동작 목록 확정본 (2026-09-29)

### 결정 ①②③을 어떻게 읽었나

오너가 두 번 답하지 않은 채 "순서대로 진행"을 유지했으므로, **오너가 붙여 준 기획 요약 원문**을 기준으로 범위를 정했다.

| 결정 | 오너 요약에 있나 | 이번 처리 |
|---|---|---|
| ③ Writer 샷 팝업 텍스트 폼 | 있다 — "샷 팝업은 '시작 고치기 / 연출 고치기(옵션+텍스트 or 그리기+텍스트)' 두 묶음" | **되살린다**(새로 짠다) |
| ① Artist '+ 인물 추가' | 없다(프로토 화면에만) | **현행 유지**. 결정 목록에 남김 |
| ② Artist 카드·전체 생성 버튼 | 없다(프로토 화면에만) | **현행 유지**. 결정 목록에 남김 |
| 산문 편집 진입점 | 있다 — "직접 고치기 팝업 / ✦ 다시 쓰기" | 팝업 |
| 레퍼런스 여러 장 | 요약엔 "레퍼런스"만 | 지금 구조(모습당 1장) 안에서. 여러 장은 DB 변경이라 결정 목록에 남김 |

다르게 읽으셨으면 알려 주면 된다 — 전부 되돌리기 쉬움.

### 설명

Producer 산문 카드의 '고치기'에서 직접 고치기(화면 전체 팝업, 그동안 채팅 잠김)나 ✦ 다시 쓰기(에이전트에게 맡김, 결과는 그룹 1의 적용·되돌리기)를 고른다. Writer는 러프 카드·'+ 샷'·대본의 샷이 모두 같은 샷 팝업을 열고, 위에 세 장, 아래에 '시작 고치기'와 '연출 고치기' 두 묶음이 있다. Artist 카드 팝업은 넓어지고 모습 목록·레퍼런스·정보 부족 표시가 들어간다.

### 같이 정한 것 (오너 요약 문장)

Producer
- P12. 산문 카드의 '고치기'를 누르면 '직접 고치기'와 '✦ 다시 쓰기'가 나온다.
- P13. 직접 고치기를 열면 화면 전체를 덮는 팝업에서 산문을 고치고, 그동안 채팅 입력이 잠긴다.
- P14. 팝업에서 적용하면 산문이 바뀌고 채팅에 "산문을 직접 고쳤어요" 한 줄이 남는다. 취소하면 아무것도 바뀌지 않는다.
- P15. ✦ 다시 쓰기를 누르면 에이전트에게 요청이 가고, 결과는 바뀐 문단 표시와 적용·되돌리기로 온다.
- P16. 에이전트가 산문을 고치는 동안 직접 고치기 버튼은 '취소하기'로 바뀌고, 누르면 에이전트 요청을 멈춘다.

Writer
- W8. 러프 카드 클릭, '+ 샷', 대본의 샷 열기가 모두 같은 샷 팝업을 연다.
- W9. 샷 팝업 위에 시작·연출·끝 세 장, 아래에 '시작 고치기'(지문·등장인물·대사·샷 크기·앵글·길이)와 '연출 고치기'(화살표 그리기 + 연출 텍스트) 두 묶음이 있다.
- W10. '시작 적용 · 연출·끝도 다시'를 누르면 글을 저장하고 그 샷의 세 장을 다시 그린다. '연출 적용 · 끝 다시'를 누르면 끝 한 장만 다시 그린다.
- W11. '+ 샷'으로 연 팝업에는 '추가만'과 '추가하고 러프 그리기'가 있고, 닫으면 샷이 생기지 않는다.
- W12. 러프가 없는 샷을 열면 세 장 자리가 비어 있고 '저장하고 러프 그리기'가 보인다.

Artist
- A5. 카드 팝업은 왼쪽에 16:9 이미지, 오른쪽에 설명·레퍼런스·모습 목록이 있는 넓은 팝업이다.
- A6. 모습 목록에서 '보기'를 누르면 왼쪽 이미지가 그 모습으로 바뀌고, '삭제'와 '+ 모습 추가하기'도 여기서 한다.
- A7. 레퍼런스 이미지를 팝업에서 보고, 올리고, 지울 수 있다.
- A8. 외형 문장이 없는 인물 카드에 '정보 부족' 표시와 '채우기 / 건너뛰기'가 붙는다.
