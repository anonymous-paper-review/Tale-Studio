# 그룹 G — 생성 품질/프롬프트 로직 (결과물이 이상함)

상태: 대기 · 우선순위: 7

주의: 헌법상 그림·영상의 좋고 나쁨 판정은 오너만 한다. 이 그룹의 완료 조건은 "비교 재료 준비"까지다.

## 이슈

| # | 화면 | 증상 원문 |
|---|---|---|
| G1 | 전체 | End 프레임의 변화폭이 적음 → 슬로우모션 야기. 속도 개념 필요. Shot 시간에 따른 변화폭 반영 |
| G2 | Director | First/End Frame을 의도적으로 더 이전/이후 시간의 장면으로 생성해야 (G1과 한 몸) |
| G3 | Director | 실사랑 일본느낌 차이가 없음 → 스타일 앵커가 처음만 입력되고 추후 입력 안 됨. 앵커 중간 삽입 필요 |
| G4 | Director | 플래시백 장면에서 Artist에서 만든 젊은 옥화·체장수가 아닌 현재의 옥화가 나옴. 체장수 pre-viz 미반영. 전반적으로 플래시백에서 헤멤 |
| G5 | Director | Shot9 Video Start&End 프레임 꼬임 (End 프레임 안 넘어간 듯). 체장수가 나와야 하는데 없고, 젊은 옥화와 현재 옥화가 손잡고 있음 |
| G6 | Artist | 재생성한 체장수를 인지 못함. side/back뷰 이미 했는데 세 번이나 다시 물음 |
| G7 | Editor | 대사를 말하지 않음 → I2V는 대사를 넣어야 함 |

## 관찰 메모

- G1+G2: I2V 입력 프레임 쌍의 시간 간격 설계 문제 — 프롬프트에 "샷 길이 n초, 그 사이 변화량" 개념이 없음.
- G4+G5: 씬 시간대(현재/과거)와 캐릭터 버전(현재 옥화/젊은 옥화) 매핑이 프롬프트 조립에 반영 안 됨 — 캐릭터 레퍼런스 선택 로직.
- G3: 스타일 앵커를 최초 1회만 주입 → 긴 체인에서 희석. 재주입 지점 설계.

## 논의 필요 항목

1. **G1 속도 개념의 형태**: (a) 샷 길이에서 자동 계산, (b) 샷별 속도 필드(느림/보통/빠름) 노출, (c) 둘 다(자동+수동 오버라이드). 오너가 조절하고 싶은지가 관건.
2. **G4 캐릭터 버전 모델**: "젊은 옥화"를 별도 캐릭터로 볼지, 옥화의 "시대 변형(variant)"으로 볼지 — 데이터 구조 결정이라 A/B 이후라도 빨리 정해야 함. variant 모델이면 씬의 시간대 태그로 자동 선택 가능.
3. **G7 대사 파이프라인**: 대사를 어디서 확정하나 — Writer 스크립트의 대사를 I2V 프롬프트+TTS에 흘리는 경로 설계. 음성 생성과의 순서.
4. **품질 검증 방법**: 프롬프트 변경 전후 같은 입력으로 비교 세트를 만들어 오너 판정 받는 절차 (실험 규칙 `.claude/rules/experiments.md` 적용).

## 완료 조건 (초안)

- 각 항목별 전/후 비교 세트(입력 고정) 생성 → 오너 판정 대기 상태로 전달.
