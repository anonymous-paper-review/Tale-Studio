2026-08-27 기준 상태: **D10 닫힘 · 나머지 9건 보류(다른 세션과 파일 충돌)**

## 논의 필요 항목

1. **D1 4단계의 구현 단위**: "수행 중 표시"를 챗 말풍선(진행 카드)으로 넣을지, 별도 진행 위젯으로 넣을지. 말풍선이면 그룹 A에서 만들 잡 추적 인프라를 구독하면 됨 — A 설계에 의존.
2. **수다의 수위**: D3 "최대한 수다스럽게"의 기준 — 완료/실패/단계 전환마다 말 걸기까지는 확정으로 보이는데, 생성 중간 경과(50%…)까지 말 걸면 시끄러울 수 있음. 어디까지?
3. **D9/D10 진행 판정**: "다음 뭐 해라" 가이드의 근거가 되는 프로젝트 진행 상태(무엇이 몇 개 완료됐나)를 누가 계산하나 — 챗 프롬프트에 스냅샷으로 주입하는 구조 필요. 주입 주기와 형태 결정.
4. **D5 문구 톤 규칙**: 챗 문구에 탭 이름·기술 용어 대신 "어디를 눌러서 뭘 하면 되는지"를 쓰는 문구 규칙을 시스템 프롬프트에 명문화. 초안을 만들어 오너 검수 받을지.
5. **D7 스테이지 바 신호**: 호버링 액션의 구체 형태 — 펄스 애니메이션? 뱃지("준비됨")? 챗 알림과 중복이니 역할 분담.

## 진행 상태 (2026-08-27)

### D10 — 닫힘. Editor 이동 제안이 진행률을 본다

오너 원문: "다 안 했는데 Editor로 넘어가라고 함".

조건이 `nodes.some(video && videoUrl)` 이었다 — **영상이 하나만 있어도 참**이라
샷 14개 중 1개를 만든 사람에게도 "영상이 완성됐다"며 Editor 이동을 권했다.
문구까지 사실이 아니었다("You have a finished video").

수리:
- 샷 대비 영상 진행률로 판정 (`EDITOR_NUDGE_MIN_RATIO = 0.8`)
- 같은 샷에 테이크가 여러 개여도 **부모 샷 기준 1개**로 센다
- 100%를 요구하지 않는 이유: 마지막 한두 샷을 남기고 편집을 시작하는 흐름도 정상이다
- 문구가 실제 수치를 말한다 — "샷 14개 중 3개에 영상이 있어요. Editor로 넘어갈까요?"

회귀 잠금: `tests/director-editor-nudge.test.ts`(4).
