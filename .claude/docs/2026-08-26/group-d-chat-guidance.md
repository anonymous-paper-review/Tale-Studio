# 그룹 D — 챗 가이드/수다 부족 (에이전트 행동 설계)

상태: 대기 · 우선순위: 5 (설계 스펙 D1 확정이 선행)

오너가 쓴 4단계가 이 그룹 전체의 설계 원칙이다:
**명령 입력 → 이해한 내용 설명하고 행동 → 수행 중 표시 → 끝나면 다음 연계 작업 가이드** (현재는 2단계까지만 함)

## 이슈

| # | 화면 | 증상 원문 |
|---|---|---|
| D1 | 전체 | 채팅 메커니즘 4단계 (위 원칙) — 현재 "이해 설명+행동"까지만 함 |
| D2 | Writer | 내용 처음에 확정 버튼 누르면 채팅방에 뭔가 변화가 있었으면 |
| D3 | Writer | 아티스트가 먼저 되면 되었다고 말걸어주기 (최대한 수다스럽게) |
| D4 | Writer | 언제 Artist로 넘어가는지 큐사인이 채팅창에 떠야 |
| D5 | Writer | "Renderer탭에서 선택하면 바로 트리거할 수 있어요" 문장이 너무 어려움 → 결국 재생성 못 함 |
| D6 | Artist | Writer에서 캐릭터 추가하면 카드는 생기지만 생성은 직접 해야 함 — 이런 걸 채팅방에서 계속 가이드해야 |
| D7 | Artist | "나중에" 눌러 Director 이동 팝업 사라진 뒤 갈 길 막막 → Director 바에 호버링/활성화로 "준비되면 눌러서 넘어가세요" 신호 |
| D8 | Director | Director로 넘어올수록 채팅창이 불친절하고 조용해짐 |
| D9 | Director | 작업 많이 했는데 여전히 "러프스토리보드를 촬영이미지로 생성해보세요" 옛 문구가 떠있음 |
| D10 | Director | 다 안 했는데 Editor로 넘어가라고 함 (진행 판정 오류) |

## 논의 필요 항목

1. **D1 4단계의 구현 단위**: "수행 중 표시"를 챗 말풍선(진행 카드)으로 넣을지, 별도 진행 위젯으로 넣을지. 말풍선이면 그룹 A에서 만들 잡 추적 인프라를 구독하면 됨 — A 설계에 의존.
2. **수다의 수위**: D3 "최대한 수다스럽게"의 기준 — 완료/실패/단계 전환마다 말 걸기까지는 확정으로 보이는데, 생성 중간 경과(50%…)까지 말 걸면 시끄러울 수 있음. 어디까지?
3. **D9/D10 진행 판정**: "다음 뭐 해라" 가이드의 근거가 되는 프로젝트 진행 상태(무엇이 몇 개 완료됐나)를 누가 계산하나 — 챗 프롬프트에 스냅샷으로 주입하는 구조 필요. 주입 주기와 형태 결정.
4. **D5 문구 톤 규칙**: 챗 문구에 탭 이름·기술 용어 대신 "어디를 눌러서 뭘 하면 되는지"를 쓰는 문구 규칙을 시스템 프롬프트에 명문화. 초안을 만들어 오너 검수 받을지.
5. **D7 스테이지 바 신호**: 호버링 액션의 구체 형태 — 펄스 애니메이션? 뱃지("준비됨")? 챗 알림과 중복이니 역할 분담.

## 완료 조건 (초안)

- 확정/생성/완료/단계전환 이벤트마다 챗이 반응한다.
- 가이드 문구가 실제 진행 상태와 일치한다 (옛 문구 잔존 없음).
