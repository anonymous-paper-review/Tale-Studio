# 그룹 H — 신규 기능

상태: 대기 · 우선순위: 8

> 이미지 노드 연결(H1~H3)의 설계·조사 심화 — Higgsfield 노드 카피 관찰, 프레임 포트,
> Artist i2i 연계: [image-pipeline-improvements.md](image-pipeline-improvements.md)

## 이슈

| # | 화면 | 요청 원문 |
|---|---|---|
| H1 | Director Node | Image: START/DIRECTION/END 프레임을 각각 한 개 object로 분리 or 오른쪽 출구 여러 개에 할당. Video: START/DIRECTION/END/REF 입력구로 |
| H2 | Director | 샷 체이닝 (First-end-First-end-First로 chaining) — Node-Edge에서 직접 하게. Scene3처럼 카메라 연출이 샷마다 분절된 씬에 필요. 실제로 요새 많이 쓰는 기법 |
| H3 | Director | Generate Storyboard(이미지 전체 생성)처럼 비디오 전체 생성 + 진행바 |
| H4 | Editor | 자막/타이틀 + 타이틀씬 (0~1초 검은 화면에 텍스트랑 이미지) |
| H5 | Editor | 화면 전환 → 우선 디졸브만 구현 |
| H6 | Editor | 자체 음원 몇 개 |

## 논의 필요 항목

1. **H1 Node 구조 두 안 중 선택**: (a) 프레임별 노드 분리(노드 수 3배, 그래프 복잡) vs (b) 한 노드에 다중 포트(출구/입구 여러 개 — 그래프 간결, 구현은 포트 시스템 필요). H2 샷 체이닝은 (b)의 포트 연결로 자연스럽게 표현됨 → H1과 H2를 같은 설계로 묶어 결정 권장.
2. **H2 체이닝 의미론**: "샷 N의 End = 샷 N+1의 First"를 엣지로 연결하면 생성 순서가 직렬화됨(앞 샷 완료 후 다음 샷 생성 가능). 전체 생성(H3) 진행바·병렬성에 영향 — 체인 구간만 직렬, 나머지 병렬로 갈지.
3. **H4 타이틀/자막 범위**: 폰트·위치·스타일 커스텀까지 갈지, 1차는 고정 스타일 프리셋 몇 개로 갈지.
4. **H6 음원 조달**: 라이선스 확보 경로 — CC0/구매/생성(음악 생성 API). 몇 곡, 어떤 무드부터.
5. **H5 디졸브**: 렌더 파이프라인에서 클립 간 크로스페이드 구현 위치 (미리보기와 최종 렌더 양쪽).

## 완료 조건 (초안)
