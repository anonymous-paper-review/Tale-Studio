> 그 옥화를 바탕으로 만들어져야 연속성이 보존될거니까. 다만 이게 나중에 결국 artist가

> (Artist 화면) "결국 artist기준으로 '젊은옥화' 카드가 추가되거나 아니면 옥화쪽 카드가
> 그룹화가되거나 그런식이려나?"

## 실측 — 지금 무슨 일이 벌어지는가

### 사례: 옥화 (프로젝트 `4cb8fc9d`)

같은 프로젝트에 **두 캐릭터가 남남으로** 등록돼 있다:

| 이름 | character_id | 외형 | 시트 |
|---|---|---|---|
| 옥화 | `char_3` | Mid-40s female, unbleached cotton skirt and jeogori | 있음 |
| 젊은 옥화 | `char_new_9l6xq` | Early 20s Joseon-era woman, white jeogori and black skirt | 있음 |

`char_new_` 접두사가 나중에 급조된 흔적이다. **둘 사이에 아무 연결이 없다.**

시트 두 장을 나란히 보면(`evidence/g4/okhwa-old.png`, `okhwa-young.png`)
**얼굴 골격·눈매·코가 전부 다르다.** 같은 사람의 다른 시절이 아니라 다른 사람이다.
의상 색도 완전히 다르다(미색 ↔ 흑색).

### 왜 이렇게 되나 — 코드 확인

`src/app/api/artist/generate-sheet/route.ts`:

```
const refMain = character.view_main   // 자기 자신의 정면
...
reference_image_urls: [refMain]       // 방향 뷰는 자기 정면을 참조
```

**시트 생성이 참조할 수 있는 건 "자기 자신의 정면"뿐이다.**
다른 캐릭터를 참조로 넣는 경로가 아예 없다. 그러니 젊은 옥화는 옥화를 본 적이 없다.

### 사물 축 — 이미 씨앗은 있다

`characters.entity_type` 이 `person` / `object` 를 구분한다(실측: person 161, object 6).
사물로 등록된 것: 엿판 5, 옥비녀 1.

그러나 **사물도 캐릭터 테이블에 산다.** 그래서:
- `character_blocking` 에 사물이 섞여 들어가 "얼굴 없는 인물"로 그려진다(#object-not-figure)
- 지금 방어는 그걸 뒤늦게 걸러내는 것 — 방어 한 겹만 빠져도 되돌아간다(2026-08-27 실제 발생)

## 설계

### 데이터 구조

```
캐릭터 (정체성)            소품 (사물)
  옥화                       엿판
   ├ 모습: 현재 (기본)         └ 상태: 새것 / 낡음  ← 나중
   └ 모습: 젊은 시절
        ↑ 옥화의 얼굴을 참조해서 생성 = 연속성
```

**핵심은 "모습"이 캐릭터를 상속한다는 것.** 젊은 옥화를 만들 때 옥화의 정면을 참조로
넣으면 얼굴이 이어진다. 별도 캐릭터면 그 연결이 원천적으로 불가능하다.

### 지금 여는 것 / 나중에 얹는 것

| 지금 | 나중 |
|---|---|
| 모습 층 (필드: 시점 하나) | 의상 세트 |
| | 소품·장비 (인벤토리) |
| | 상태 (다침·젖음) |

**미리 만들지 않는다. 층만 연다.** 필드 하나로 시작해도 구조가 같으므로 확장이 자연스럽다.
오너 걱정("너무 복잡할지")에 대한 답이 이것이다 — 지금 복잡해지는 건 층 하나뿐이다.

### Artist 화면

오너 질문에 대한 답: **카드 추가가 아니라 그룹화**다.

```
[옥화]  ← 카드 1개
  ├ 현재 (기본)      ← 지금 있는 시트
  └ 젊은 시절        ← 탭으로 전환
```

모습이 하나면 지금과 똑같이 보인다. 추가했을 때만 탭이 생긴다.
카드를 늘리지 않는 이유: 카드가 늘면 "이 둘이 같은 사람"이라는 정보가 화면에서 사라진다.

### 씬 시간대와의 연결

씬에 `time_of_day` 가 있으나 이건 **하루 중 시각**(Dawn/Morning/오후)이고 조명용이다.
캐릭터 생애 시점과는 다른 축이므로 **거기 욱여넣으면 조명 정보가 오염된다.**

씬에 별도의 **서사 시점** 태그가 필요하다(현재/과거/회상). 그게 있으면
플래시백 씬에서 자동으로 "젊은 시절" 모습을 고를 수 있다.

## 이미지 칸의 실제 상태 (2026-08-27 조사, 오너 질문)

오너 질문: *"view main 같은 코드가 있는 거야? view 방식은 템플릿 시트 이전의 4방향 생성
이런 거의 잔재 같은데 맞아?"*

**맞다.** 데이터가 증명한다.

| 칸 | 전체 167행 | 8/20 이후 45행 | 판정 |
|---|---|---|---|
| `view_main` | 84% | **87%** | **현역** — 다만 이름과 다른 것을 담음 |
| `portrait` | 84% | 87% | **현역** — `view_main` 파생 |
| `view_side_left` | 1% | **0%** | **잔재** |
| `view_side_right` | 1% | **0%** | **잔재** |
| `view_back` | 1% | **0%** | **잔재** |

167행 중 3방향이 찬 것은 **딱 1행**(옛 데이터). 최근 45행은 전부 0%.

### 무슨 일이 있었나

**옛 방식** (`turnaround.ts` 주석에 그대로 남아 있음):
```
main     = 정면 1장 (T2I)
back     = main 을 참조로 i2i 재생성   ← 개별 호출
sideLeft = main 을 참조로 i2i 재생성   ← 개별 호출
sideRight= main 을 참조로 i2i 재생성   ← 개별 호출
```

**지금 방식** (커밋 `8c0d384` "character turnaround sheet via I2I template"):
```
템플릿(public/character-template.png)을 참조로 I2I 1회
  → 4방향·표정·팔레트가 다 들어간 와이드 시트 1장
  → view_main 한 칸에 통째로 저장
```

그래서 **`view_main` 은 "정면 1장"이 아니라 "시트 전체"** 다. 이름이 실체와 어긋나 있다.

### `portrait` 의 정체

별도 생성물이 아니다. **`view_main` 시트의 좌상단 CONCEPT 박스를 크롭한 얼굴**이다
(`src/lib/artist/portrait.ts`). 카드·칩 표시용.

실측: 140행 전부 `view_main` 과 `portrait` 가 짝이고, 한쪽만 있는 경우가 **0건**.
파일명 해시도 동일 — 같은 원본에서 나왔다.

```
view_main (시트 전체)
   └ portrait (얼굴 크롭)  ← 카드에 보이는 것
```

### 4방향 코드는 왜 안 지워졌나

`generate-sheet` 라우트에 개별 방향 생성 경로가 살아 있다(`buildCharacterViewPrompt`).
다만 **자동 경로(진입 시 생성)는 시트 1장만 만든다**(`draft-trigger.ts:130`).
개별 방향은 버튼을 눌러야 도는데 아무도 안 누른다 — 죽은 게 아니라 **호출자가 없는 상태**.

### G4 에 미치는 영향

1. **참조로 넣을 이미지를 골라야 한다.** 젊은 옥화를 만들 때 현재 옥화의 무엇을 참조로
   넣을 것인가 — 시트 전체(`view_main`)인가, 얼굴만(`portrait`)인가.
   memo.md 의 중국 팀은 **얼굴을 따로 넣고 심지어 의도적으로 훼손**해 그대로 복사되는 것을
   막는다("아이덴티티를 확인할 수 있는 요소들만 남겨두고 얼굴 섹션도 의도적으로 훼손").
   → 후보: `portrait`(얼굴 크롭)를 참조로, 시트 레이아웃은 템플릿이 잡는 방식.

2. **`view_side_*` 3칸은 물려받지 않는다.** 죽은 칸이므로 "모습" 층 설계에서 제외한다.
   기존 1행은 마이그레이션에서 무시하거나 시트로 대체한다.

3. **v2/v3 시트 레이아웃 차이 주의.** `portrait.ts` 경고 — 2026-08-27 이전 생성분(v2)은
   레이아웃이 달라 v3 좌표로 재크롭하면 안 된다. 모습 층 마이그레이션 때 같은 함정이 있다.

### 정리하면 지금 캐릭터의 이미지 자산은

```
characters
  ├ view_main        시트 1장 (현역, 실체는 와이드 모델시트)
  ├ portrait         └ 그 시트의 얼굴 크롭 (현역, 카드 표시용)
  ├ view_side_left   ✗ 잔재 (0%)
  ├ view_side_right  ✗ 잔재 (0%)
  └ view_back        ✗ 잔재 (0%)
```

"모습" 층은 이 중 **시트 + 얼굴 크롭 두 칸만** 물려받으면 된다.
