# Artist 설명 승인과 배경 저장 실패 처리

기존 임시 저장본 `3c449ab6`에서 오너가 배포를 승인한 두 수정만 최신 main `ba02d1dc`에 옮겼다.

## 같이 정한 것

- 오래된 변경 제안을 승인해도 그 뒤에 수정한 내용은 덮어쓰지 않는다.
  - 왜: 제안을 만든 뒤 승인하거나 저장하기까지 다른 편집이 들어올 수 있다.
- 이미지 업로드가 실패하면 승인 결과를 완료로 알리지 않고 기존 배경을 유지한다.
  - 왜: 저장되지 않은 임시 이미지 주소를 완료 결과로 사용하던 문제를 막는다.
- 업로드 응답에 공개 주소가 없으면 승인 결과를 완료로 알리지 않고 기존 배경을 유지한다.
  - 왜: 성공 응답처럼 보여도 실제 저장 주소가 없으면 완료를 확인할 수 없다.
- 업로드 응답의 공개 주소가 비어 있으면 승인 결과를 완료로 알리지 않고 기존 배경을 유지한다.
  - 왜: 빈 주소가 기존 배경 선택값을 대신하지 않도록 한다.

설명 저장의 세부 동작과 되돌릴 수 있는 구현 판단은 `source-behaviors.md`에 기록했다.

## 이전과 달라지는 점

설명 승인은 기존에도 표시된 값을 다시 읽어 비교했다. 이번에는 원문·영문 저장값·수정 시각과 기본 모습 식별 정보까지 함께 기억한다. 승인 때 재확인하고, 실제 저장도 이 값들이 여전히 같을 때만 실행한다. 확인 정보가 없는 옛 승인 카드는 새로 요청하도록 한다. 확인 정보를 전달하지 않는 수동 편집 API 사용 방식은 그대로다.

배경 저장은 기존에 업로드 오류를 내부에서 처리하고 빈 결과를 돌려줬다. 호출부가 이를 임시 이미지 주소로 대신해 완료로 처리했다. 이번에는 업로드 오류와 공개 주소 누락을 실패로 전달하고 저장 주소를 확인한 다음에만 완료로 처리한다. 프로젝트가 있는 동기식 배경 생성 경로에 적용한다.

## 확인 기록

- 배경 저장 실패 테스트: 변경 전 5개 중 3개 실패, 변경 후 5개 모두 통과.
- 원천 보호 최초 재현: 19개 중 15개 실패. 구현 후 관련 6개 파일의 44개 테스트 통과.
- 최신 main의 대본 원문 보존·업로드 이미지 용도 선택: 23개 테스트 통과.
- Artist·채팅 전체 회귀 검사에서 저장 완료 테스트의 대역 하나가 새 원천 정보를 제공하지 않는 누락을 확인했다. 임시 저장본에 있던 해당 대역 변경을 추가했고 테스트 이름과 기대값은 유지했다.
- 타입 검사 통과. 전체 커밋 관문과 운영 배포 결과는 실행 로그 및 GitHub CI·Vercel 상태로 확인한다.

## 범위와 한계

채팅 모델 교체, Writer 저장·번호 처리, 배경 삭제 안내, 과거 보고서 복원은 포함하지 않았다. 최신 main의 대본 보존·이미지 용도 선택·이미지 사용 동의 기능은 유지했다. DB 구조 변경은 없다.

검사는 저장소 코드·대역 테스트 기준이다. 실제 유료 이미지 생성이나 사용자 데이터 변경으로 고장을 주입하지 않았다. 업로드 API는 기존부터 같은 저장 경로에 파일을 덮어쓴 뒤 DB를 갱신한다. 따라서 이 수정의 보장은 실패를 완료로 표시하지 않고 화면의 기존 선택 주소를 유지하는 것이며, 파일 업로드 뒤 DB 저장이 실패했을 때 파일 내용까지 되돌리는 트랜잭션은 포함하지 않는다.
