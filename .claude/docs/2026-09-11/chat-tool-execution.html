채팅 도구 실행

지원하는 조회·편집은 정상 실행부터 도구를 사용하고, 실패하면 같은 도구로 복구를 시도한다.

현재 연결된 도구는 read_project(현재 값 조회)와 edit_project(값 편집)다. 모델이 호출을 요청하고 앱이 실행한 뒤, 성공·승인 대기·오류 결과를 모델에게 돌려준다.

1

채팅의 실행 방식

구분모델과 앱의 동작실측
도구를 사용하는 조회·편집모델의 tool_use 요청 → 앱 실행 → tool_result → 모델 후속 판단. 실패 시 같은 도구로 입력 수정·재조회·재시도한다.Writer “첫번째샷을 9초로 바꿔줘”
도구 2회 · 저장 확인
일반 상담프로젝트 수정 없이 설명을 답한다. 도구가 제공된 채팅에서도 실제 호출은 0회일 수 있다.“WS와 CU의 차이를 설명해줘”
도구 0회 · 답변만
기존 JSON 실행모델이 JSON 필드를 응답하고, 앱이 기존 처리 함수로 반영한다. 이 경로의 JSON 출력만으로 저장 성공이 증명되지는 않는다.Producer 이야기 완성
도구 0회 · storyText 저장
2

연결된 기능과 연결하지 않은 기능

단계두 도구로 조회·편집하는 범위두 도구에 포함하지 않은 범위
Producer설정 6개: 러닝타임·장르·세부 장르·포맷·톤·대사 언어스토리·캐스트 원천 카드·배경 원천 카드·시각 스타일은 기존 JSON 처리. Writer 이동은 기존 코드 게이트.
Writer씬: 장소·시간대·분위기·줄거리·등장인물·예상 길이
샷: 종류·행동·등장인물·길이·대사
인물: 이름·역할·설명·기본 외형
배경: 기본 묘사		씬·샷 생성/삭제·재정렬, 이미지 생성 등은 이 두 도구의 편집 범위 밖. 대사 목록 편집은 가능하며 삭제를 포함하면 기존 승인 경계를 따른다.
Artist인물: 이름·역할·설명·기본 외형
배경: 기본 묘사		새 모습·이미지 생성·후보 선택·시각 스타일 등은 기존 기능 경로. 기본 외형/배경 원천 변경은 승인 대상.
Director이번 두 도구 연결 범위 밖기존 Director 동작은 유지한다. 이번 수정·유료 영상 검증 대상에서 제외했다.

표의 “미연결”은 이번 두 도구에 포함되지 않았다는 뜻이다. 기존 채팅 기능으로 가능한 항목도 있다. Artist 범위는 코드와 앞선 검증 기준이며, 이번 실제 실행 표본은 아래 Producer·Writer다.

샷 편집과 승인 대기의 차이

순서Writer: 첫 샷 9초Producer: 일본어 → 한국어
1. 조회샷 ID sh_01_01, 길이 8초, 버전 r1 반환현재 언어 ja 반환
2. 편집 호출모델이 durationSeconds: 9 요청모델이 dialogueLanguage: ko 요청
3. 앱 결과저장 후 재조회 → status: ok와 9초 반환기존 Writer·Artist 산출물에 영향을 주는 원천 변경 → approval_required 반환. 저장값은 ja 유지.
4. 후속 동작모델이 변경 결과를 답하고 종료승인 카드 표시. 승인 뒤 앱이 저장·재조회한다. 실제 DB와 이후 채팅 조회에서 ko 확인.

승인 대기는 도구 실행 결과의 한 종류이며, 저장 완료를 뜻하지 않는다. 승인 버튼 클릭 자체가 새 LLM tool call은 아니다. Producer 언어 초안 변경으로 기존 일본어 대사가 자동 번역되지는 않는다.

실제 확인 결과와 남은 한계

표본관측된 호출판정
Producer 언어 변경조회 1 + 편집 1승인 전 ja, 승인 후 초안 ko. 무관한 스타일 choices 0.
Producer 언어 재조회조회 1현재 대사 언어 ko 응답. 편집 없음.
Writer 샷 길이 변경조회 1 + 편집 1첫 샷 9초·둘째 10초 저장 확인.
Writer 일반 상담0설명만 답하고 기존 샷·대사 유지.
Producer 이야기 완성0 · 기존 JSON초안 storyText·storyReady 저장. 새 기획의 준비 전환에서 스타일 창 표시.
Producer 수채화 스타일 요청조회 1 + 잘못된 편집 1 → 기존 JSON잔여 문제: 모델이 도구에 지원하지 않는 styleAnchorKey를 넣어 거절당했다. 후속 JSON으로 실제 스타일은 watercolor로 저장됐지만, 화면에는 앞선 도구 오류가 남았다. 저장 결과와 최종 안내의 통합이 추가로 필요하다.

호출 횟수에는 거절된 요청도 포함된다. 저장 성공은 반환 결과와 저장값을 따로 확인했다.

복구는 허용된 앱 기능과 제한된 실행 횟수 안에서 진행한다. 모든 표현·실패가 자동 해결되는 것은 아니다. 특히 위 스타일 사례는 기존 JSON 경로로 넘어간 뒤의 결과 안내가 아직 통합되지 않았음을 보여준다.

이번 실제 표본으로 LLM의 반복 성공률을 평가하지 않았다. 이미지·영상 생성, 모든 UI 기능, 다중 탭 동시 편집, 브라우저 종료 후 자동 재개는 이번 검증 밖이다.
