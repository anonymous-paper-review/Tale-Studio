# /warp — 세션 정산

이 세션에서 코드로 닫히지 않은 관측·미결·판단·실패를 **결과를 만들 수 있는 입력**으로
정리한다. 해당 없는 갈래는 건너뛰고, 남길 것이 없으면 그렇게 보고한다.

## 활성 계약

- 오너가 쓰는 자유 메모의 원문은 `.claude/vault/inbox/<actor>.md`다. `/warp`는 오너의 원문을 대신
  고치거나 승인 문서로 바꾸지 않는다.
- 실행의 해석·분해·실행·결과 기록은 `.claude/vault/backlog/_NIGHT.md` 하나를 따른다.
  현재 실행의 결과 보고는 `runs/<actor>/<run_id>/report.html`, 오너 피드백은
  `feedback/<actor>/<run_id>/`에 남긴다.
- 소비자와 소비 시점이 없는 독립 기록은 만들지 않는다. 티켓·실험·결과 카드가 닫힐 때
  관련 기록도 함께 닫는다.

## 라우팅 원칙

1. **코드로 이미 닫힌 것**은 새 기록으로 복제하지 않는다. diff·커밋·검증 결과를 연결할
   기존 티켓이 있으면 그 티켓에 사실만 덧붙인다.
2. **닫힘 조건을 쓸 수 있는 미결**은 즉시 실행 가능한 티켓으로 만든다. 좌표(픽스처·로그·
   데이터·선례 코드), 관측 방법, 수용 기준을 함께 적고 기존 티켓과 중복되지 않는지 먼저
   확인한다. 안전 경계와 비용은 실행 단위에 명시한다.
3. **닫힘 조건이 아직 없는 미결**은 억지로 `ready`로 만들지 않는다. 원문과 부족한 조건을
   `status: draft`로 기록하고, 실행으로 확인할 수 없는 오너 선택은 `status: needs-owner`
   티켓으로 남긴다. 이것은 아침의 사전 승인 대기나 분해 승인 카드가 아니다.
4. **결정됐지만 조건이 아직 안 찬 일**은 `status: waiting`과 `until:<재개 조건>`으로
   기록한다. 조건이 확인되면 밤이 `ready`로 바꾸어 실행한다.
5. **실측·삽질·실패**는 해당 실행 티켓이나 실험 결과에 붙인다. 관측값과 실패 원인을
   소급해 판정선을 고치지 말고, 새로운 기준이 필요하면 새 버전으로 기록한다.
6. **같은 판단이 반복**되면 각 결과 카드에 판단 키와 근거를 연결한다. 독립 카드가 쌓인
   뒤 오너의 확인을 거쳐 규칙 후보로 증류하며, 한 번의 판단을 규칙으로 일반화하지 않는다.

## 사람의 판단과 결과 자산

- **헌법: 산출물 판정은 오너만 한다.** 모델과 코드는 지각·측정 자료를 만들 수 있지만,
  그림·영상에 대해 밤이 “좋다/나쁘다” 결론을 기록하지 않는다.
- 이미지·영상 결과에는 사람이 비교할 원본, 입력, 시점, 설정, 채점표와 결과 경로를
  남긴다. 이 판단 기록은 다음 실행에서 다시 쓸 수 있는 자산이다.
- 실행 단위가 끝나면 결과 카드에 수용 기준, 실제 관측, `pass`·`fail`·`inconclusive`·
  `blocked`, 명령·비용·산출물 경로·다음 질문을 즉시 적는다.

## 실행 경계

- `/warp`는 티켓을 만들 때 사전 승인을 기다리지 않는다. `ready`는 밤 계약의 안전 경계를
  확인한 뒤 실행되고, `draft`는 닫힘 조건을 보완할 때만 실행 단위가 된다.
- 조사·실험·수리·제품 기능 변경을 모두 실행 대상으로 삼는다. 기능 변경은 격리 작업
  사본과 검증을 거치며, 비가역 행동과 예산 초과만 hard-stop이다.
- 수정된 제품 코드를 이 세션의 체크아웃에 직접 머지·커밋하지 않는다. 격리 작업 사본,
  커밋, 검증 명령을 결과 카드에 연결하고 사람 머지 검토가 필요한 상태를 표시한다.

## 닫힌 기록 정리

- 세션 중 닫힌 티켓은 상태·근거를 갱신해 `.claude/vault/_archive/`로 옮긴다.
- 결과 카드와 판단 기록은 아침 리뷰가 끝날 때까지 보존한다. `merge`·`reject`·`feedback`
  결과와 반복 판단에서 나온 규칙 승격 근거를 보고서에 연결한다.
- 마지막 보고에는 변경 파일, 새 티켓·상태, 연결한 실험·결과, 아카이브 목록을 적고
  자동 커밋은 하지 않는다.
