# artifact — 사람이 읽고 판단하는 발행 문서 표준

정본 예시: 이 디렉토리의 `exemplar.html`
(발행본: https://claude.ai/code/artifact/666284f2-5b67-4788-807b-59a93ac148d1 — "판정기 시험 성적표")

exemplar 를 열어 뼈대·톤·CSS 를 계승하고 내용만 바꾼다. 이미지 자리는 `{{...}}` 로 비워둔
템플릿이니, 발행할 때 실제 이미지를 data URI 로 치환한다(아래 §4).

## 1. 말 규칙 — 이 표준의 제1조

> **설명이 필요한 줄임말은 쓰레기다.** (2026-08-13 오너 지시)
> 읽는 사람이 "그게 뭐였더라" 하고 되짚어야 하는 순간, 그 단어는 정보를 전달한 게 아니라 **숨긴 것**이다.

**판별 질문**: "이 단어를 처음 보는 사람이 앞 문장으로 돌아가지 않고 이해하는가?" — NO 면 고쳐 쓴다.

처음 쓸 때 괄호로 풀어주는 것도 **안 된다**. 그냥 풀어쓴 말만 쓴다. 줄임말을 쓰고 각주를 다는 건
읽는 사람에게 사전을 던져주는 것이지 설명이 아니다.

| 쓰지 않는 말 | 대신 쓰는 말 |
|---|---|
| 오라클 | 판정기 — 잘 됐는지 대신 봐주는 프로그램 |
| 계기 / 계기 결함 | 재는 도구 / 재는 도구가 고장났다 |
| 변별력 | 둘을 구분해내는 힘 |
| 2AFC / 쌍대 비교 | 둘을 나란히 놓고 하나 고르게 하기 |
| 축 분리 | 질문을 두 개로 쪼개서 따로 묻기 |
| 스모크 | 예비 시험 — 본격적으로 하기 전에 두어 개만 |
| 모집단 / 모집단 부재 | 잴 대상 / 잴 대상이 아예 없었다 |
| 기각 조건 | 미리 정해둔 판정선 — "이러면 틀린 걸로 친다" |
| 판독 세트 | 사람이 보고 고를 수 있게 정리해둔 비교표 |
| n | 몇 건인지 실제 숫자 |
| previz | 러프 영상 |
| 티켓 id / 질문 번호 / 등급 / 스테이지명 | 그 티켓이 물으려던 것을 사람 말 질문으로 다시 씀 |

**이 표는 닫힌 목록이 아니다.** 규칙은 "새 줄임말을 만들지 마라"이고, 표는 이미 걸린 사례일 뿐이다.

문서 본문 맨 앞(0절)에 이 표를 **문서 자신의 규칙으로 실어라.** 읽는 사람이 "이 문서는 나를 배려한다"를
첫 화면에서 알게 되고, 쓰는 쪽도 스스로를 검사하게 된다.

경로·코드명·영어 원문은 **버리지 말고** 회색 작은 글씨나 접기 안에 둔다 — 본문에서 빼되 추적은 가능하게.

### 1-1. 말투 규칙 — AI 티 나는 문장을 빼라

줄임말만 문제가 아니다. 본문 산문 자체가 AI가 쓴 티를 내면 읽는 사람이 내용을 안 믿는다.
이 문서의 모든 한국어 산문(제목·본문·칩·안내문 포함)은 **korean-natural-writing 스킬**을 따른다:
`/Users/xcape/.aside/u/0/skills/user/korean-natural-writing/SKILL.md`

그 스킬의 강한 수정 신호 중 이 문서에서 특히 자주 터지는 것:

- **"A가 아니라 B"** 처럼 통찰의 모양만 만드는 대비 문장 → 말하고 싶은 B를 바로 쓴다.
- **"핵심은 이겁니다", "아무도 말해주지 않는"** 같은 가짜 발견 도입 → 그냥 사실을 쓴다.
- **"중요한 전환점", "더 큰 흐름", "지속적인 의미"** 같은 근거 없는 과장 → 실제 수치·시점으로.
- **"전문가들은", "업계에서는"** 출처 없는 권위 빌리기 → 실제 출처를 밝히거나 삭제.
- **마지막에 내용을 반복하며 미래 전망·교훈으로 닫기** → 결론(§7)은 사실 문장으로 끝낸다.
- 긴 대시(U+2014)를 극적 전환에 반복 사용, 모든 문장이 같은 길이·같은 모양으로 늘어섬.

줄임말 금지(위 §1)가 **단어** 층위라면, 이 규칙은 **문장·문단** 층위다. 둘 다 통과해야 발행한다.

## 2. 뼈대 — 증거로 판단을 만드는 순서

읽는 사람의 머릿속 순서를 그대로 따른다. 절 번호를 화면에 표시해 어디쯤인지 알게 한다.

| 절 | 내용 | 빠뜨리면 생기는 일 |
|---|---|---|
| **0. 말 규칙** | 위 §1 표 | 독자가 중간에 막히고, 쓰는 쪽도 자기 검열을 안 하게 됨 |
| **1. 무엇을 알고 싶었나** | 질문 한 줄 + 왜 궁금했나 + 어떻게 확인하기로 했나 | 결과를 봐도 그래서 뭐가 어떻다는 건지 모름 |
| **2. 정답지 — 사람이 먼저 본 것** | 기준이 요구하는 조건을 **하나도 빠짐없이** | **가장 자주 터지는 사고 지점.** §3 참조 |
| **3. 안 됐던 시도와 그 이유** | 무엇을 어떻게 했고 왜 실패했는지 | 고친 방법이 왜 고침인지 이해 불가 |
| **4. 고친 시도와 결과** | 무엇만 바꿨는지 + 정답지와의 대조표 | — |
| **5. 정직 분할** | 2열 — 확실한 것 / 전혀 모르는 것 | 독자가 과신하거나, 반대로 통째로 불신함 |
| **6. 믿으려면 뭐가 더 필요한가** | 다음 단계 + **비용 숫자** | 결론이 행동으로 안 이어짐 |
| **7. 결론** | 번호 매긴 문장들. 각 문장이 독립적으로 인용 가능해야 | — |
| **footer** | 근거로 쓴 것 / **이 문서가 하지 않는 것** | 검증 안 된 것이 검증된 것처럼 읽힘 |

## 3. 정답지를 완전하게 써라 — 실제로 터진 사고

2026-08-13 이 문서의 초판이 이 지점에서 오너에게 반려됐다. 기록해 둔다.

영상 실험에서 목표 그림은 두 가지를 요구했다 — ① 서랍이 열려 있을 것 ② **남자의 머리까지 보이는
중간 거리로 잡을 것.** 초판은 ①만 정답지에 적고 ②를 빠뜨렸다. 그 결과 서랍이 열린 영상에
"사람 눈: 갔다"를 붙였는데, 실제로는 카메라가 손 클로즈업으로 밀고 들어가 **쓸 수 없는 영상**이었다.

오너 반응: *"정답이 저거라면 실제 의도는 사람 머리가 보이면서, 손이 클로즈업되지 않는다는 게
정답임? 그게 담겨있음? 모든 맥락에? 그렇다면 둘 다 실패가 맞는데"*

**교훈 셋:**

1. **정답지에 조건을 하나라도 빠뜨리면 문서 전체가 거짓말이 된다.** 판정을 쓰기 전에
   "이 기준이 요구하는 조건을 전부 적었는가"를 반드시 되물어라.
2. **"둘 다 실패"여도 그게 결론이 아니다.** 실패 이유가 다르면 그 차이가 진짜 발견이다.
   초판은 한쪽을 성공으로 잘못 표시해서 오히려 이 발견을 가렸다.
3. **그림이 있으면 직접 열어봐라.** 파일이 있는데 안 보고 기록만 읽고 쓰면 이 사고가 난다.
   단, 본 것을 **판정으로 승격시키지는 마라** — 사람의 판정을 받아 적는 것이 원칙이다
   (`.claude/rules/experiments.md`).

## 4. 그림 — 설명으로 갈음하지 마라

- **원본을 실어라.** "3D 참조를 함께 줬다" 같은 서술 금지. 무엇을 줬는지 눈으로 봐야 결과가 읽힌다.
- **목표와 결과를 나란히.** 목표 그림은 테두리 색을 달리해 한눈에 구분되게(exemplar 의 `.fr.is-ref`).
- **각 그림 아래에 그 그림에 대한 판정을 칩으로 붙여라.** 표로 따로 빼면 눈이 왕복한다.
- **바깥 주소는 전부 차단된다.** 반드시 data URI 로 심는다:

```sh
sips -s format jpeg -s formatOptions 72 -Z 520 원본.png --out /tmp/a.jpg
# 520px 폭 · 품질 72 → 장당 30~40KB. 페이지 전체 16MB 상한이라 넉넉하다.
```

- **대체 텍스트는 그림이 안 보여도 판정을 따라올 수 있게** 쓴다.
  나쁨: `"마지막 프레임"` / 좋음: `"서랍은 열렸으나 카메라가 확대되어 머리가 잘렸고 팔이 하나 더 보인다"`

## 5. 정직 규칙

- **과장 금지.** 시험 문제가 2개였으면 2개라고 쓴다. "재현했다"로 끝내지 말고 "2개로는 못 믿는다"까지.
- **독자의 반박을 문서가 먼저 말한다.** 읽는 사람이 떠올릴 의심을 절 제목으로 세워라 —
  exemplar 5절 제목이 `"당신 의심이 맞습니다 — 이건 아직 증명이 아닙니다"`.
- **말해주는 것과 말해주지 않는 것을 2열로 갈라 놓는다**(exemplar 의 `.split`). 이게 이 표준의 심장이다.
- **footer 에 "이 문서가 하지 않는 것"을 반드시 쓴다.** 아직 안 돌린 것, 제안일 뿐인 것을 명시.
- **한계를 발견하면 그것도 발견이다.** exemplar 에서 "팔이 두 개인 결함은 아무도 안 물어서
  아무도 못 잡았다"가 그 예 — 방법의 본질적 한계를 드러내는 게 성공 사례보다 값지다.

## 6. 디자인

`exemplar.html` 의 토큰과 CSS 를 그대로 계승한다. 직접 색을 쓰지 말고 토큰만 쓴다.

- 바탕은 차가운 회색(`--bg`), 강조는 짙은 청록(`--accent`). 판정색은 강조색과 별개 —
  통과 `--pass`, 실패 `--fail`, 사람 관문 `--gate`, 주의 `--warn`.
- **테마 3상태 전부 처리** — 맨 `:root`에 밝은 테마 전체, `@media (prefers-color-scheme: dark)`
  안에 `:root:not([data-theme="light"])`, 그리고 `:root[data-theme="dark"]`. 색을 미디어 블록
  안에서만 정의하면 기본 상태에서 글자가 안 보인다.
- 본문 글자 16px / 줄간 1.82 / 한 줄 64자 이내. 이 문서는 오래 읽힌다.
- 표·코드는 각자 가로 스크롤(`overflow-x:auto`). 본문이 옆으로 밀리면 안 된다.

## 7. 발행

```
Artifact(file_path=..., favicon="...", description="한 문장")
```

- **같은 파일 경로로 다시 발행하면 같은 주소가 유지된다.** 문서를 고칠 땐 반드시 같은 경로로.
- 제목(`<title>`)은 **이름**이지 요약이 아니다. 두세 단어. `판정기 시험 성적표` (○) /
  `야간 루프 판정기 검증 결과 보고서` (×)
- 큰 이미지가 붙으면 템플릿(`{{...}}`)과 치환 스크립트를 나눠서 작업한다 — 본문을 고칠 때마다
  수십만 자의 data URI 를 다시 쓰지 않게 된다. exemplar 가 그 템플릿 형태다.

## 발행 전 자기 점검

- [ ] 본문에 줄임말·개발용어가 하나도 없는가 (0절 표로 검사)
- [ ] 산문에 AI 티 나는 문장이 없는가 (§1-1 / korean-natural-writing — "A가 아니라 B", 가짜 발견 도입, 출처 없는 권위, 미래 전망 마무리)
- [ ] 정답지에 **조건이 전부** 적혀 있는가 — 하나라도 빠지면 판정이 거짓이 된다
- [ ] 그림 원본이 실려 있는가, 대체 텍스트가 판정을 담고 있는가
- [ ] "확실한 것 / 모르는 것" 분할이 있는가
- [ ] 표본 크기·비용 같은 숫자를 얼버무리지 않았는가
- [ ] footer 에 "이 문서가 하지 않는 것"이 있는가
- [ ] 밝은 테마와 어두운 테마 양쪽에서 글자가 보이는가
