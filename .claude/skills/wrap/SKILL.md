# /wrap — 세션 증류

이 세션을 되돌아보고 아래 4갈래로 라우팅한다. 해당 없으면 그 갈래는 건너뛴다
(빈 문서·빈 섹션을 만들지 마라). 전부 해당 없으면 "남길 것 없음"이라고 보고하고 끝낸다.

## 판정 원칙 (버리는 쪽이 기본값)

- **코드로 귀결된 것은 남기지 않는다** — diff와 커밋 메시지가 기록이다.
- "다음 세션이 이걸 몰라서 같은 삽질을 반복하는가?" — NO면 버린다.
- 실측 없는 추측은 vault에 넣지 않는다 (원칙: "모든 발견은 실측 검증됨").
- **append 전에 기존 vault와 대조한다**: 같은 주제가 이미 있으면 그 파일을 개정하고,
  모순이면 옛 서술에 "무효 — <새 위치>로 대체" 표시. 중복 신설 금지.

## 라우팅

1. **실측·삽질·안 통한 시도** → `.claude/vault/YYYY-MM-DD-<주제>.md`
   - 포맷은 `.claude/vault/_TEMPLATE.md` 준수 (골격 고정, 해당 없는 섹션은 통째로 생략).
   - 핵심 논의는 실제 입출력 원문을 짧게 인용해도 좋다 (요약이 원문을 대체하지 않게).

2. **코드로 귀결 안 된 결정** → 위 vault 파일 안의 `## 결정` 섹션
   - 항목 포맷 (10줄 이내): 상황 / 결정 / 기각한 대안 / 감수하는 것.
   - 별도 결정 로그 파일을 만들지 마라 (specs/decisions.md 없음 — 의도된 부재).
   - **반복 참조될 결정이면 승격**: 해당 정본(specs/design.md, .claude/rules/)에
     반영한다. vault는 사건 기록, 정본은 현재 믿음.

3. **결론 없이 끝난 논쟁** → 위 vault 파일의 `## 미결` 섹션
   - 질문과 함께 **닫히는 조건**(무엇이 정해지면/실측되면 닫히는가)을 반드시 적는다.
   - 세션 중 닫힌 미결이 있으면 해당 vault 항목에 닫힘 표시를 남긴다.

4. **같은 실수가 2번째 확인됨** → `.claude/rules/` 해당 파일에 규칙 1줄
   - 예방적 규칙 금지 — 이 세션에서 실제 발생했고, 처음이 아닌 실수만.
   - 어느 rules 파일에도 안 맞으면 추가하지 않는다 (새 rules 파일 신설은 사용자와 논의).

## 마무리

- 새 문서가 생겼으면 `CLAUDE.md` 인덱스에 한 줄 추가 — "언제 읽어야 하는지"가
  드러나는 훅 문장으로 (예: "- .claude/vault/2026-08-04-x.md — OO 다시 팔 때 먼저").
- 변경 파일 목록과 각 파일의 요지를 보고하고, **커밋 여부는 사용자에게 확인** (자동 커밋 금지).
