## 1. 실측 발견 — 안 통한 시도 포함

- **AX 리서치(4레인: 커뮤니티 실사용담/파일 포맷/조직 설계론/메모리 스키마)** 수렴 결론:
  ① 상시 로드는 인덱스만, 본문은 조건부(2계층 lazy-load가 업계 표준) ② distractor 문서
  1개만 섞여도 성능 하락(Chroma Context Rot 실측) — 해법은 접근권 축소가 아니라 로드 지연
  ③ 규칙은 "실패에서 역산된 것"만 산다 ④ 공유는 항상 명시적 컨테이너 단위.
  전문: https://claude.ai/code/artifact/a6fffac3-5730-4b77-aff2-74a96d7b95f6
- **재현성 리서치(mock/fake drift)** 수렴 결론: "실행 코드는 카피하지 않는다 — 카피하는 것은
  세계(입력·상태·인프라)다". eval 하네스는 제품 함수를 import하는 thin wrapper가 표준
  (LangSmith target/Braintrust task/OpenAI cookbook 동형). 스테이지 격리는 코드 분기가
  아니라 상류 출력 고정으로. seed 재현성은 같은 모델 버전·인프라 안에서만 유효.
- **에이전트 산출물 신뢰**: METR 실측 — 최신 모델 응답 1~2%가 reward hacking, 테스트 조작으로
  벤치마크 100% 사례. → 에이전트에게 스크립트 작성 자유가 아니라 실코드 하네스 호출 권한만
  주는 것이 신뢰의 구조적 해법 (experiments 룰의 존재 이유).
- **감사 실측(4건 병렬)**: 삭제 전 docs 14·scripts 32·tests 92·DB 2레인 전수 감사 완료.
  docs/·scripts/·memo.md는 애초에 gitignore라 처음부터 이 머신 로컬 전용이었음(동료와 git
  공유된 적 없음). live DB의 schema_migrations에는 repo에 파일이 없는 초기 CLI 마이그레이션
  8개가 존재(스키마 이력의 완전한 재구성은 live DB 쿼리로만 가능).
- **안 통한 시도**: 세션 로그를 "주기 배치"로 증류하는 안 — 캡처 시점엔 맥락이 이미 소실됨.
  성공 사례(Cline "update memory bank", compound engineering)는 전부 세션 종료 시점 수동
  명령이었다. 그래서 /wrap도 수동 리추얼로 확정.

## 2. 결정 — 코드로 귀결 안 된 것만

### D-2026-08-05-a: 진실원 = 코드 + live DB, 유도 가능 문서 전량 삭제
- 상황: docs/specs/research에 코드 서술·stale 참조(감사에서 10~84% stale 실측 사례)·레거시 실험 기록 누적
- 결정: 코드로 유도 가능한 문서는 전부 삭제. 남는 문서는 "코드가 될 수 없는 것"(design.md 판별 규칙, vault 실측 기록)만
- 기각한 대안: 문서 유지 + 주기 감사 — 2인 팀에서 유지비가 효용을 초과, stale 문서는 노이즈가 아니라 적극적 오도
- 감수하는 것: 과거 실측 기록(writer 감사, style-anchor 실험 등) 접근성 상실 — git 히스토리와 ~/tale-studio-backup-2026-08-05.tar.gz로만 복구
- 원문: "결국 코드는 코드가 source of truth니까 코드에 있는 내용을 문서로 남길 필요는 없다" (오너)

### D-2026-08-05-b: migration 파일은 git 동기화하지 않는다
- 상황: databases/(수동 번호)·supabase/(CLI) 2레인 공존 발견, 9개 파일이 이 머신에만 존재
- 결정: schema-as-code 관습 기각. live DB가 스키마의 진실이고 적용 완료된 파일은 찌꺼기 → databases/ 전체 삭제
- 기각한 대안: git add -f로 동기화(Claude의 최초 권고) — 업계 관습을 이 팀의 "DB 단일 진실원 + 대시보드 수동 적용" 컨벤션 위에 얹은 오판정이라 철회
- 감수하는 것: 스키마 변경 이력 추적은 live DB와 git 히스토리로만
- 원문: "migration은 db에 적용되고 나서 남은 파일 아님?" (오너)

### D-2026-08-05-c: tests/는 "중간언어"의 완성형으로 판정, 유지
- 상황: "스크립트도 e2e도 틀렸으니 tests도 버려야 하는 것 아니냐"는 제안
- 결정: 유지. 틀렸다고 판정된 것은 ①로직 복붙 스크립트 ②별도 e2e 하네스이고, tests/는 제품 코드를 직접 import하는 in-process 실행 — 합의된 중간언어 그 자체 (86 passed 실측)
- 기각한 대안: 전량 재작성 — 재작성 결과물이 지금 형태와 동일해짐
- 감수하는 것: 없음

### D-2026-08-05-d: 실험 3규칙 + 가설 5줄 폼 + 자격 심사 도입 → 승격: .claude/rules/experiments.md
- 상황: 실험 스크립트의 백엔드 복붙이 재현성을 붕괴시키는 병목으로 확정(리서치로 업계 검증)
- 결정: 복붙 금지(thin wrapper)·상류 고정·좌표 기록 + 가설은 폼 제출 후 자격 심사(옳음이 아니라 반증가능성·측정가능성·전제 생존만 심사)
- 기각한 대안: 훅 기반 자동 증류·자동 심사 — 세션 경계 불명확, 사후 배치 증류는 품질 저하
