## 0. 한 줄 요약

8/6 writer 사망 사고에서 출발해 완주 안정성(체크포인트·병렬·2레인)과 정합성(대사 조인)을 닫았고, 그 과정에서 "프로덕션이 7/23부터 대사를 ~70% 오배치해왔다"는 상시 진행형 버그를 발견·수리했다. 검수(shotCheck) 최적화 시도 2건은 실측 기각 — 교훈이 코드보다 값지다.

## 1. 실측 발견 — 안 통한 시도 포함

- **대사 오배치 (P0)**: shotCheck 분할 → 전면 위치 리넘버 → 리넘버 후 id로 조인이 원인. 프로덕션 감사(읽기 전용): 대사 트랙 있는 완료 run 22개 중 **18개 오염, 발화 라인 189/268(~70%) 오배치**, Sample1 최악(59/62). shotCheck는 프로덕션에서 죽은 적 없음(분할이 7/21~당일 상시 발생 — "크레딧 소진 기간 안전" 가설 기각). 픽스 후 실런 2회 오배치 0/0 (반사실: 85/37, 51/15). **재persist 복구 가능**(design_ref 보존, LLM 0콜) — 07-31 run 1개만 정밀 복구 불가.
- **shotCheck 씬 fan-out 기각**: 프롬프트 무변경 절단만으로 153.6s→261.3s(+70%), 출력 4.4배, 이슈 3배(연속성 7.5배). **교훈: 규칙의 씬-로컬성 ≠ 모델 판단의 규모 불변성** — 씬 하나만 주면 이슈 예산을 분산할 대상이 없어 상대평가가 절대평가로 변한다. 같은 157샷 매칭 실측: 모놀리식 19건 vs 씬단위 합 130건(6.8배), 진짜 신호 2건은 양쪽 다 잡음. 백미: 모놀리식은 "달이 멀쩡해 보이는 건 정보 비대칭 장치"임을 알아보고 자기 기각 — 컨텍스트가 넓으면 서사가 판단에 들어온다.
- **shotCheck 출력 다이어트 기각**: 벽시계 −2.1%(기준 ≥30%). 전제 2개가 실측으로 깨짐 — 분할안은 출력의 23~24%뿐(76%는 semantic_issues), 베이스라인이 이미 델타 출력. 검수 벽시계는 고분산(같은 fixture 87.6~111.8s) — 재도전 시 팔당 ≥3런 + 타깃은 이슈 볼륨.
- **검수 비용은 상류 누수의 함수**: shot_10 족보 — s3 비트[9]가 한 비트에 2동작 → decoupage 통과(자기 프롬프트에 split 지시 있는데도) → V4 충실 전파(위계상 못 고침) → 검수가 사후 분할. 근본 다이어트는 s3 "한 액션=한 비트" 규율 강화.
- **2레인 공정 A/B**: 같은 코드 순차 대조군 대비 post-decoupage **−206.9s**(구조 지표), A는 상류 핸디캡 안고 총 148.4s 승. 대사 레인(씬 순차 메모리 무손상) 통째 은닉 재확증.
- **프로덕션 갭**: decoupage가 env 미설정으로 **동시성 1(순차 ~262s)로 돌고 있었다** — 내부 기본 4로 봉합. shotDesign 동시성 8 실측 −46%(에러 0, 병렬도 6.83) — 기본 4 유지, env 옵트인.
- **안 통한 것(전제 오류)**: "shotDesign 178.5s 순차" 진단은 오판 — 워커풀은 7/21부터 병렬 4로 돌고 있었음(모델시간 637s/벽 178.5s = 3.57×).

## 2. 결정 — 코드로 귀결 안 된 것

### D-a: 검수는 모놀리식 확정, fan-out 코드는 삭제
- 절단·다이어트 모두 기각 → 다음 다이어트 방향은 "이슈 볼륨"이되, 판단 변경 실험이므로 ±30% 가드+3런 설계로만.
### D-b: 대사 상속은 첫-자식-만
- design_ref 첫-자식-만 이디엄 재사용. 분할 자식 대사의 LLM 보정은 후속 옵션으로 보류.
### D-c: 오염 18 run 재persist는 보류 (오너 인지, 2026-08-10)
- 픽스 배포 후 스크립트 1개로 복구 가능 상태 유지. Sample1 최우선.
