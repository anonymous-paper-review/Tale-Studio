# 티켓 폼 — 밤에 하나씩 집어 실행하는 단위

> **아무것도 모르는 사람이 이 파일만 읽고 실행할 수 있어야 한다.** 밤에는 이 티켓을 아무 맥락 없는
> subagent에게 파일 경로만 던져서 시킨다. 여기 안 적힌 게 필요해지는 순간 그 티켓은 잘못 쓰인 것이고,
> subagent가 그 자리에서 `blocked` 으로 돌려보낸다.
>
> **말 규칙** — 설명이 필요한 줄임말은 쓰레기다. 본문·측정·판정선 어디에도 쓰지 마라.
> 판별 질문: "이 단어를 처음 보는 사람이 앞 문장으로 돌아가지 않고 이해하는가?"
> 금지어 대조표는 `.claude/skills/artifact/SKILL.md`.
>
> 자격 심사 규칙은 `.claude/rules/experiments.md` — **어떤 관측이 나오면 이게 죽는지** 못 쓰겠으면 반려다.

```yaml
id: <파일 이름과 같게>
source: <어디서 나왔는지 — 원문으로 돌아갈 수 있게>
kind: audit | llm-test | generation | fix
# audit      — 이미 있는 것을 읽고 센다. 데이터 조회·코드 추적·기록 확인. 돈 0원, 쓰기 금지.
# llm-test   — 모델을 부른다. 글만 뽑고 그림·영상은 안 만든다. 대략 $2.
# generation — 그림이나 영상을 실제로 만든다. 진짜 결제가 일어난다.
#              오너가 승인한 금액이 안 적혀 있으면 실행하지 않고 blocked 처리.
# fix        — 코드를 고친다. 별도 작업 사본에서 브랜치와 테스트 준비까지만, 머지·커밋 금지.
budget: { usd: 0, runs: 1, wall_min: 30 }   # 벽시계처럼 들쭉날쭉한 값은 runs 3 이상
blockers: []   # owner-decision:<물음> | budget-approval:<금액> | human-labor:<무엇> | depends:<티켓 이름> | until:<조건>
status: ready | waiting | needs-owner | running | done | blocked | superseded | draft
# ready — 오늘 밤 집어서 그대로 실행한다. 발주가 걸려 있으면 돈이 나간다.
# waiting — 지금은 못 하지만 언제 꺼내는지 조건이 적혀 있다. 밤이 매일 확인하고 차면 올린다.
# needs-owner — 오너만 답할 수 있다. 밤은 집지 않는다. 답이 나오면 거기서 새 티켓이 나온다.
# running   — 지금 subagent가 붙어 있다.
# done     — 판정선에 대입해 결론이 남았다. **틀렸다는 결론도 done 이다.**
# blocked  — 실행하려다 이 파일 밖 정보가 필요해져 멈췄다. 막힌 지점을 본문에 추기한다.
# superseded   — 다른 티켓이 이걸 흡수했다. 어느 것인지 적는다.
# draft    — 닫히는 조건을 아직 못 썼다. 원래 만들지 말아야 할 것이라 오래 남으면 지우는 게 맞다.
priority: high | normal
```

## 본문 여섯 줄

- **맥락 (사람 말로)** — 두세 문장. 이 티켓이 왜 존재하는지. 개발 용어·코드 이름 없이.
  아침 리포트가 이 문장을 그대로 인용한다. 비워두면 나중에 누군가 맥락을 다시 짜맞춰야 한다.
- **알고 싶은 것** — 한 문장. 무엇이 참인지 거짓인지 가리려는 것인가.
- **깔고 있는 전제** — 기존 실측과 부딪히는 지점. 이게 틀리면 결과 전체가 무의미해지는 것들.
- **예측** — 참이면 무엇이 보이고, 거짓이면 무엇이 보이는가.
- **어떻게 재나** — 무엇을 세거나 비교하는지 구체적으로.
  - **모델은 지각만, 채점은 코드.** 모델에게 점수를 매기게 하지 마라.
  - **서로 다른 것을 한 점수로 뭉치지 마라.** 뭉치면 답이 나와도 쓸모가 없다
    (실측: "동작이 끝났나"와 "화면이 맞나"를 한 번에 물었더니 두 조건이 서로를 상쇄해 신호가 사라졌다).
  - **둘을 나란히 놓고 고르게 하는 쪽이 절대 점수보다 잘 갈린다.**
  - 연결이 불확실하면 추측하지 말고 **"확인 못 함"**으로 남긴다.
- **판정선 (미리 정해두는 것)** — "이러면 틀린 걸로 친다"를 **밤이 시작되기 전에** 못 박는다.
  결과를 보고 나서 고치지 않는다. 애매한 경우를 어떻게 처리할지도 여기 같이 적으면 밤이 안 멈춘다.
  근거 없이 정한 숫자는 `(제안)` 이라고 표시한다.

## 잴 대상이 진짜 있는지 — 만들기 전에 한 번 찾아본다 (필수)

```
- 찾아본 것: <실제로 돌린 명령이나 조회>
- 나온 개수: <숫자>건   (<확인한 날짜>)
```

**이 칸이 비어 있으면 이건 티켓이 아니다.** 0건이면 만들지 말고 아침에 답할 물음으로 보낸다.

끝난 티켓 36건 중 **7건이 결론 없이 끝났고** 대부분 이 이유였다. 대표 사고 — 티켓에
`left_to_right` 라고 적었는데 실제 데이터에는 `left` 라고만 있었다. 한 건도 안 나왔고, 밤은
맞다도 틀리다도 못 하고 끝났다. **찾아보는 데는 돈이 안 든다.** 명령어 한 줄이면 막혔을 일이다.

## 좌표 — 얼려서 적는다

입력 데이터·기록 경로·참고할 기존 코드. **밤에 입력을 찾아 헤매게 하지 마라.**
낡은 경로를 적어놨다가 밤새 없는 것을 뒤진 사고가 있다(2026-08-10, 이미 지워진 코드를 찾아 헤맴).

아직 못 정한 배선이 있으면 `먼저 확정할 것: <절차>` 로 명시한다. 단 **어떻게 재는지와 판정선은
그래도 불변**이다 — 좌표를 찾는 것과 기준을 바꾸는 것은 다르다.

## 무엇을 남기면 끝난 건가

- `research/experiments/<이름>/` 에 결과 문서와 원자료.
  결과 문서는 **사람 말로 쓰고 실제 입력과 출력을 원문 그대로 인용**한다.
- 이 파일의 `status:` 갱신.
- 그날 기계 리포트(`.claude/vault/backlog/reports/<날짜>.md`)에 한 줄 — 판정과 발동한 판정선.
- 아침 리포트(`<날짜>.html`)에 결과 카드 한 장 — **티켓이 끝나는 즉시** 덧붙인다.

**틀렸다는 결론도 산출이다.** "틀렸음"이 남으면 그 티켓은 `done` 다.
