우리 서비스에서 비싼 건 쌓아두는 게 아니라 내보내는 겁니다

세 회사 요금표를 실제 값으로 놓고, 우리 실측 숫자를 대입해 봤습니다. 그리고 "그림 한 장이 태어나서 소비되기까지 어디서 요금이 붙는지"를 다시 셌습니다.

먼저 계산 하나를 고칩니다 — 결과물을 우리 보관함에 저장할 때는 요금이 안 붙습니다. 들어오는 데이터는 과금 대상이 아닙니다. 요금이 붙는 두 지점은 따로 있고, 그중 하나는 사람이 화면을 안 봐도 계속 돌아갑니다.

1

먼저 계산을 고칩니다

"외부 서버가 만든 걸 받아서 저장할 때 한 번, 사람이 볼 때 한 번, 두 번 나간다"는 모델은 절반이 틀렸습니다.

저장할 때는 안 나갑니다. 외부 서버에서 결과물을 받아 우리 보관함에 올리는 건 들어오는 방향입니다. Supabase는 들어오는 데이터와 업로드에 요금을 매기지 않습니다. 나가는 것만 셉니다.

실제로 요금이 붙는 지점은 다른 둘입니다. 그리고 이 둘의 성격이 서로 완전히 다릅니다.

요금이 붙는 지점언제몇 번8월 실측
② 외부 서버가 재료를 받아감생성 요청할 때생성 건수만큼861회 · 1,297 MB
③ 사람이 화면에서 봄화면을 열 때본 횟수만큼 무한 반복기록 없음
① 결과물을 받아 저장생성이 끝났을 때1회요금 없음

③번에 "무한 반복"이라고 쓴 게 핵심입니다. 저장 용량은 파일을 한 번 만들면 그걸로 끝인 일회성 비용인데, 나가는 양은 볼 때마다 다시 붙는 반복 비용입니다.

사용자가 늘면 이 차이가 폭발합니다. 사용자 10명이 각자 자기 프로젝트만 봐도 저장은 10배지만, 한 프로젝트를 10명이 같이 보면 저장은 그대로인데 나가는 양만 10배가 됩니다. 협업 도구일수록 이쪽이 먼저 터집니다.

세는 방식이 회사마다 다릅니다

"파일만 옮기면 나가는 양 문제가 사라지나"에 답하려면 먼저 무엇을 나간 것으로 세는지를 알아야 합니다.

Supabase — 이미지만 세는 게 아닙니다

Supabase 문서는 나간 데이터량에 데이터 조회 응답, 파일 보관함, 실시간 알림, 로그인 처리, 가장자리 함수, 데이터베이스, 연결 관리자가 전부 포함된다고 명시합니다. 즉 화면이 프로젝트 목록을 불러오는 것도 나간 양으로 셉니다.

그리고 중요한 구분이 하나 있습니다 — 중계망을 거쳐 나간 양은 파일 보관함에만 적용됩니다. 데이터 조회나 로그인은 중계망을 안 타므로 전부 직접 나간 양으로 잡힙니다.

이 사실이 우리 숫자를 갈라줍니다.

  • 중계망을 거쳐 나간 8.89기가는 100% 파일입니다. 다른 게 섞일 수가 없습니다
  • 직접 나간 7.54기가는 파일 + 데이터 조회 + 로그인이 섞여 있습니다. 그중 1.30기가는 외부 생성 서버가 받아간 것으로 확정했습니다

Cloudflare R2 — 나가는 양에 요금을 안 매깁니다

대신 요청 횟수로 셉니다. 파일을 읽는 요청과 쓰는 요청을 따로 세고, 저장 용량은 용량대로 셉니다. 파일이 몇 기가 나가든 그건 0원입니다.

세는 축이 다르다는 게 핵심입니다. 우리처럼 큰 파일을 적은 횟수로 주고받는 서비스에는 이 방식이 압도적으로 유리합니다. 반대로 아주 작은 파일을 초당 수만 번 읽는 서비스라면 요청 횟수 요금이 아플 수 있습니다.

②번 화살표를 물리적으로 막을 수 있나

외부 생성 서버가 재료를 받아가는 것 — 없앨 수는 없고, 옮기거나 줄일 수는 있습니다.

아예 없앨 수 있나?

없습니다. 외부 서버가 그림을 만들려면 참조 재료를 어떻게든 받아야 합니다. 재료가 우리 쪽에 있는 한 어디선가는 나갑니다. 이건 요금 정책 문제가 아니라 일이 돌아가는 방식입니다.

방법효과남는 문제
파일을 R2 에 둔다실제로 0원이 됩니다. 외부 서버가 몇 번을 받아가든 요금이 없습니다없음 — 이게 가장 직접적인 답입니다
재료를 작게 만든다배치 참조 시트가 평균 2.17 MB PNG같은 화질에서 JPEG·WebP 로 바꾸면 크게 줄어듭니다. 어디에 두든 효과가 있습니다화질 손실을 눈으로 확인해야 합니다
재료를 덜 만든다같은 시트를 덮어쓰기·재사용보관 용량과 나가는 양이 같이 줍니다없음 — 어차피 고쳐야 할 결함입니다
주소 대신 파일을 직접 올린다외부 생성 서버에 업로드 기능이 있습니다Supabase 에서는 안 나갑니다비용이 사라지는 게 아니라 Vercel 로 옮겨갑니다. Vercel 이 이걸 어떻게 세는지 확인 안 했습니다

정리하면 ②번은 R2로 옮기는 순간 논점이 사라집니다. 나가는 양에 요금이 없으니 몇 번을 받아가든 상관이 없어집니다. 재료를 작게·덜 만드는 건 그것과 별개로 해야 할 일입니다 — 보관 용량도 같이 줄기 때문입니다.

Vercel 무료 등급은 아직 괜찮나

기술 한도로는 문제가 없습니다. 다만 약관 조항 하나가 걸립니다.

나가는 양 — 여유가 많습니다

확인해 보니 next/image를 한 군데도 안 씁니다. 이미지 컴포넌트가 <img>로 Supabase 주소를 직접 물고 있어서, 그림이 Vercel을 안 거치고 브라우저가 Supabase에서 바로 받아갑니다.

src/components/thumb-image.tsx — eslint 규칙까지 꺼가며 의도적으로 <img> 사용

덕분에 이번에 터진 16.43기가가 Vercel 대역폭에는 한 바이트도 안 잡혔습니다. Vercel이 내보내는 건 화면 코드와 데이터 응답뿐이라 100기가 한도에 여유가 큽니다.

단, 이건 파일을 R2로 옮길 때 다시 확인해야 합니다. 만약 옮기면서 이미지를 우리 서버를 거쳐 내보내는 구조로 바꾸면, 지금 Supabase가 내던 16기가가 고스란히 Vercel 대역폭으로 옮겨옵니다. 100기가 한도를 금방 넘깁니다. 브라우저가 R2에서 직접 받아가는 구조를 유지해야 합니다.

함수 호출 — 여유가 있습니다

8월 생성 요청이 716건이었습니다. 화면 조회에 딸린 호출을 넉넉히 잡아도 월 10만 건 한도와는 거리가 있습니다. 다만 정확한 호출 수는 Vercel 사용량 화면에서 봐야 합니다 — 코드로는 알 수 없습니다.

진짜 걸리는 것 — 상업적 이용 금지

한도 그래프에 안 나타남

Vercel 무료 등급은 개인의 비상업적 프로젝트 전용입니다. 수익을 내는 서비스, 유료 상품, 사업자 명의 제품은 유료 등급으로 올려야 합니다.

이건 사용량이 아니라 계약 조건이라 사용량 화면을 아무리 봐도 안 보입니다. talestudio.art 가 지금 또는 가까운 미래에 수익을 낼 계획이라면, 사용량과 무관하게 유료 등급이 필요합니다. 가입자가 이미 114명이라는 점도 같이 봐야 합니다.

확실한 것과 모르는 것

확인한 것

  • 들어오는 데이터와 업로드는 요금 대상이 아니다
  • Supabase 는 데이터 조회·로그인 응답까지 나간 양으로 센다
  • 중계망 몫은 파일 보관함에만 적용된다 → 우리 8.89기가는 100% 파일
  • R2 는 나가는 양에 요금이 없고 요청 횟수로 센다
  • 우리 파일 3.61기가는 R2 무료 10기가 안에 들어간다
  • next/image 를 안 써서 이미지가 Vercel 을 안 거친다
  • Vercel 무료 등급은 상업적 이용이 금지돼 있다
  • 외부 생성 서버에 파일을 직접 올리는 기능이 있다

모르는 것

  • 파일 몫을 걷어낸 뒤 데이터·로그인만의 나간 양 — 지금은 섞여 있어 가를 수 없습니다. 이게 무료 5기가 안에 들어오는지가 "Supabase 를 무료로 유지할 수 있나"의 답입니다
  • Vercel 함수 호출 실제 건수 — 사용량 화면을 봐야 합니다
  • talestudio.art 가 상업적 이용에 해당하는지 — 사업 계획을 아는 사람이 판단할 문제입니다
  • Vercel 이 외부 서버로 나가는 데이터를 어떻게 세는지
  • 파일 9,871개를 옮기는 데 걸리는 시간과 방법
  • 요금표 숫자는 검색으로 얻은 값이라 실제 계약과 다를 수 있습니다

결론

  1. 저장할 때는 요금이 안 붙습니다. 두 번 나간다는 계산에서 한 번은 빼야 합니다. 실제 지점은 외부 서버가 재료를 받아갈 때와 사람이 볼 때입니다.
  2. 내보내는 양에 민감해야 한다는 판단이 맞습니다. 저장은 만든 만큼 한 번 늘지만, 내보내는 양은 만든 것 × 본 횟수로 늘어납니다. 이미 4.5배 차이입니다.
  3. 우리 구조는 순환입니다. 오늘 만든 그림이 내일 생성의 재료로 다시 나갑니다. 사람이 화면을 안 열어도 내보내는 양이 늘어납니다.
  4. 확정된 파일 몫만 10.19기가입니다. 파일을 옮기면 이만큼은 확실히 사라집니다.
  5. R2 는 나가는 양에 요금이 없어서 우리 규모에서는 사실상 공짜입니다. 유료 구간에 가도 월 $0.05 수준입니다.
  6. ②번 화살표는 없앨 수 없지만 R2 로 옮기면 논점이 사라집니다. 재료를 작게·덜 만드는 건 그것과 별개로 해야 합니다.
  7. Vercel 무료 등급은 사용량으로는 여유가 있습니다. 이미지가 Vercel 을 안 거치기 때문입니다. 걸리는 건 상업적 이용 금지 조항 하나뿐이고, 이건 사용량 화면에 안 나타납니다.

이 문서의 근거

  • tale-studio 파일 보관함 전수 집계와 생성 요청 기록 (2026-08-19)
  • 코드 확인 — next/image 미사용, thumb-image.tsx, 외부 생성 서버 업로드 기능 존재
  • Supabase·Cloudflare·Vercel 요금 및 나간 데이터량 정의는 2026년 8월 공개 자료 검색
  • 두 회사 조합 시 주의점은 공개 논의와 문서에서 반복 등장하는 사례
  • 앞선 두 문서 — 저장소 한도 초과 해부, 우리 제품의 배선도

이 문서가 하지 않는 것

  • 아무것도 옮기지 않았고 코드도 고치지 않았습니다. 전부 계산과 비교입니다
  • 파일 몫을 걷어낸 뒤의 나간 양을 재지 않았습니다. 이게 "Supabase 무료 유지 가능?"의 답인데 지금은 측정 수단이 없습니다
  • R2 를 실제로 붙여 보지 않았습니다. 속도·안정성·실제 청구서는 써 봐야 압니다
  • 이전 작업량을 산정하지 않았습니다
  • 요금표는 검색 결과이지 계약서가 아닙니다. 결정 전에 각 회사 요금 페이지에서 다시 확인해야 합니다
