"provider"라는 이름은 코드에 있지만 전부 출력 쪽이다

이름위치하는 일
LlmProvidersrc/lib/writer/llm/raw_collector.ts:4어떤 언어 모델로 글을 쓸까

입력 쪽에는 "어떤 종류의 파일을 어떻게 해석할까"를 묶는 추상화가 없음. 메모에서 말한 "입력 provider"는 이름만 같은 새 축임.

이미지 순서는 보존되지만 "페이지 번호"는 아니다

한 장 안의 세로 컷은 위→아래 순번으로, 여러 장은 고르거나 놓은 순서대로 배열에 들어감.

다만 이건 배열 인덱스이지 메타데이터가 아님. 순서를 검증하거나 다시 배열하는 화면은 없음. 웹툰처럼 순서가 곧 이야기인 입력에서는 이 차이가 중요할 수 있음.

DB 자체에 형식 제약(CHECK 제약·트리거)이 걸려 있는지는 코드만으로 확인 불가. Supabase Pro 전환 뒤 확인 가능.
