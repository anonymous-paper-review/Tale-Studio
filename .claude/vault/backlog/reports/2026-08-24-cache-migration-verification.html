화면 세 곳의 기억 장치를 바꿨습니다 — 진짜 브라우저로 확인했고, 전부 통과했습니다

화면이 서버에서 받아온 데이터를 어디에 어떻게 기억해 둘 것인가를 바꾸는 작업이었습니다. 코드 시험 20건이 먼저 통과했지만, 그건 부품 검사일 뿐입니다. 이 문서는 실제 브라우저를 자동 조작해서 완성차가 굴러가는지를 확인한 기록입니다.

결론 먼저 — 확인 항목 6개 전부 통과. 다만 도구가 두 번 잘못 쟀고(본문 3절), 남의 버그 하나를 주웠습니다(원래 있던 것임을 증명함).

무엇을 알고 싶었나

이번에 화면 세 곳의 기억 장치를 사물함 방식으로 바꿨습니다 — 감독 화면의 카메라 프리셋, 아티스트 화면의 샷 보드, 그리고 인벤토리(이건 조사 중에 죽은 기능으로 판명되어 통째로 제거). 코드 단위 시험 20건은 통과했지만, 세 가지는 실제 브라우저에서만 확인할 수 있습니다:

  • 질문 ① 안 깨지나 — 로그인부터 다섯 화면 전부, 새 기억 장치 위에서 무사히 뜨는가
  • 질문 ② 정말 아끼나 — 화면을 나갔다 돌아올 때, 예전처럼 서버에 다시 묻지 않고 사물함에서 꺼내는가
  • 질문 ③ 되돌리기가 진짜인가 — 샷의 인물 참조를 지우고 실행취소하면, 화면만이 아니라 데이터베이스까지 원래대로 돌아오는가

확인 방법: 시험 계정으로 실제 서비스 빌드에 로그인해서, 브라우저 자동 조작 도구로 사람이 할 일(클릭·이동·단축키)을 그대로 시켰습니다. 데이터가 있는 화면이 필요해서 기존 시험 프로젝트(28샷, 러프 스토리보드 완성) 하나를 시험 계정에 잠시 빌려주고, 끝나고 원위치했습니다.

측정 실수 ① — 새로고침으로 들어가 놓고 "왜 또 묻지?" 했다

도구 잘못

첫 측정에서 화면을 옮길 때마다 주소를 새로 열었습니다(새로고침 진입). 사물함은 브라우저 메모리에 있으므로 새로고침마다 통째로 비워집니다 — 그러니 돌아올 때마다 서버에 다시 묻는 게 정상 동작인데, 그걸 "사물함이 안 듣는다"로 읽을 뻔했습니다. 실제 사용자는 사이드바로 이동하므로, 측정도 앱 안 이동(단축키)으로 바꿔 다시 쟀습니다. 그 결과가 4절의 "추가 질문 0건"입니다.

측정 실수 ② — 엉뚱한 버튼을 눌러 공유 링크를 하나 만들었다

도구 잘못

"둥근 버튼"이라는 넓은 조건으로 인물 칩을 찾다가, 같은 모양인 공유 링크 만들기 버튼을 눌렀습니다. 그 클릭으로 시험 프로젝트에 읽기 전용 공유 링크가 하나 생겼고, 발견 즉시 지웠습니다(데이터베이스에서 생성 기록 확인 후 삭제). 선택자를 "클릭하면 해제"라는 설명문이 달린 버튼으로 좁혀 다시 쟀습니다.

주운 버그 — 편집자 화면의 무한 되그리기 4건 (이번 작업과 무관함을 증명)

원래 있던 버그

순회 중 편집자 화면에서 무한 되그리기 오류가 4건 잡혔습니다. 이번 전환이 만든 사고인지 가리기 위해 전환 이전 시점의 코드를 따로 빌드해서 같은 경로로 돌렸더니, 똑같은 화면에서 똑같이 4건이 나왔습니다. 원래 있던 버그입니다. 고치지 않고 기록만 남깁니다 — 편집자 화면은 이번 작업 범위 밖입니다.

확실한 것과 모르는 것

이 검증이 말해주는 것

  • 새 기억 장치 위에서 로그인·다섯 화면이 깨지지 않는다
  • 앱 안 이동 재방문은 서버에 다시 묻지 않는다 (0건 실측)
  • 칩 해제 → 실행취소가 화면·서버 모두 왕복한다
  • 28샷 데이터가 검증 전후 완전히 같다
  • 편집자 화면 무한 되그리기는 전환 이전부터 있던 버그다 (이전 코드로 재현)

말해주지 않는 것

  • 프리셋 칩을 노드에 드래그해서 적용하는 동작 — 안 눌러봤다
  • 편집자 화면에 영상 클립이 있는 상태 — 시험 프로젝트에 클립이 없었다
  • 인물 칩을 보드에 드래그로 붙이는 동작 — 해제·복원만 시험했다
  • 신선 기간 5분이 체감상 적절한지 — 써 봐야 안다
  • 두 기기에서 동시에 쓸 때의 동작

결론

여섯 항목 전부 통과. 전환은 실기기에서 동작한다.

1. 화면 세 곳의 기억 장치 전환이 실제 브라우저에서 확인됐다 — 깨짐 0, 재방문 시 서버 질문 0, 실행취소 왕복 성공.

2. 인벤토리는 죽은 기능으로 판정되어 제거됐다 — 데이터베이스에 테이블 자체가 없었고, 화면 입구는 7월 15일부터 잠겨 있었다.

3. 측정 도구가 두 번 틀렸고(새로고침 진입, 넓은 선택자) 두 번 다 고쳐서 다시 쟀다. 처음 숫자는 버렸다.

4. 편집자 화면의 무한 되그리기 4건은 전환 이전 코드에서도 똑같이 나온다 — 원래 있던 버그이고, 별도 수리 대상이다.

근거로 쓴 것 — 실제 서비스 빌드(로컬 실행) · 시험 계정 로그인 · 브라우저 자동 조작 6회 순회 · 데이터베이스 직접 조회(전후 스냅샷 대조) · 전환 이전 코드의 별도 빌드(버그 기원 판정). 코드 검증은 별도로 타입 검사 0건 오류, 코드 단위 시험 1,491건 통과, 배포용 빌드 통과. 커밋: 08b76be(프리셋) · eb80089(인벤토리·보드) · 9dd302a(인벤토리 제거)
