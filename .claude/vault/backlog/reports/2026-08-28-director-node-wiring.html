Director 연결선 세 종류와 전체 영상 생성이 코드 시험을 통과했습니다

Shot과 Video를 그림으로 연결하고, 한 장면의 모든 영상을 한 번에 생성하는 작업을 끝냈습니다. 영상에서 영상을 잇는 연결은 공급자에게 영상을 직접 보내지 않고, 이전 영상의 마지막 장면을 그림으로 뽑아 다음 영상의 시작 그림으로 사용합니다.

결론 먼저 — 전체 자동 시험 1,657건 통과 + 실제 화면에서 드래그 연결·마지막 장면 추출까지 확인. 원격 main의 9개 커밋 위로 재배치(rebase)했고 feat/director-node-wiring에 커밋돼 있습니다. 남은 것은 실제 비용을 내는 영상 생성 확인 하나입니다.

1

무엇을 확인하려 했나

Director 캔버스의 입력선이 화면에만 보이는 장식이 아니라, 저장되고 생성 요청까지 이어지는지 확인했습니다.

확인 대상

세 가지 연결
  • 그림→그림: 한 Shot의 결과 그림이나 에셋을 다른 Shot의 이미지 입력으로 연결합니다.
  • 그림→영상: 그림 출처를 Video의 시작·끝·참조 입력으로 연결합니다.
  • 영상→영상: 완료된 Video의 마지막 장면을 공개 그림으로 저장하고, 다음 Video의 시작 그림으로 연결합니다.
  • 전체 영상 생성: 완료 영상이 없고 현재 생성 중이지 않은 Shot만 확인 후 한 번에 실행합니다.

연결에는 노드 번호를 저장하고, 실제 그림 주소는 생성 요청을 보낼 때만 찾도록 했습니다. 생성하지 않은 상태에서 공급자 호출이나 비용이 발생하지 않게 했습니다.

2

정답지 — 모두 참이어야 하는 조건

조건판정확인한 내용
Shot 이미지 입력은 여러 출처를 저장하고 다시 그릴 수 있다통과중복 방지, 삭제, 다시 그리기, 그림 생성 요청까지 확인
Video 시작·끝 입력은 하나씩, 참조 입력은 여러 개다통과교체·중복 방지·삭제·복원 확인
완료 Video의 마지막 장면이 다음 Video 시작 그림이 된다통과화면 캡처, 공개 저장, 생성 요청 역할 확인
연결된 그림 주소에 노드 번호나 영상 주소가 섞이지 않는다통과그림 주소만 공급자 요청에 포함
영상 전체 생성은 명시적 확인 뒤에만 시작된다통과대상 선별, 동시 3개 제한, 진행률·실패 집계 확인
잘못된 연결·순환·불완전한 원본은 거부된다통과자기 연결, 순환 연결, 완료되지 않은 원본을 차단

검사 기준은 연결 상태, 생성 요청 몸체, 저장 업로드 경계, 채팅 명령 검증까지 포함했습니다.

3

도중에 막혔던 것과 고친 방법

공급자는 영상을 입력으로 받지 않았다

직접 영상 연결 불가

현재 영상 생성 통로는 문장만으로 만들거나 그림을 시작점으로 만드는 두 종류입니다. 영상 주소를 넣으면 영상→영상이 되는 계약이 없고, 모르는 입력을 넣었을 때 문장만으로 만드는 방식으로 조용히 바뀔 위험도 있었습니다.

그래서 연결선은 따로 두되, 브라우저에서 이전 영상의 마지막 장면을 캡처해 공개 그림으로 저장합니다. 다음 생성에는 그 그림만 시작 입력으로 보냅니다. 실패하면 연결을 되돌리고 문장만으로 만드는 방식으로 몰래 바꾸지 않습니다.

브라우저 확인은 Orca 내장 브라우저로 다시 돌아 통과했다

해소

처음에는 예비 시험 도구의 화면 저장 명령이 오류를 냈지만, Orca 내장 브라우저에서 개발 서버(localhost:3000)에 시험 계정으로 로그인해 Director 화면을 직접 열었습니다. Shot 1의 오른쪽 손잡이를 Shot 2의 이미지 입력까지 끌어 연결하는 동작이 실제로 작동했고, 두 번 반복해도 같은 결과였습니다.

실제 저장소 영상에서 마지막 장면 추출이 된다

실측

실제 완성 영상(5.16초, 1280×720)을 브라우저에서 교차 출처 허용 모드로 불러와 끝에서 0.15초 앞 지점으로 이동한 뒤 캔버스에 그려 JPEG(101KB)로 뽑는 것까지 성공했습니다. 저장소 응답에 access-control-allow-origin: *가 있어 캔버스가 오염되지 않습니다. 영상→영상 연결이 쓰는 캡처 경로 그대로입니다.

덤 — 연결선 종류 등록 누락을 찾아서 고쳤다

현장 발견

실제 화면을 열자 파생 체인 연결선 종류(chain, prompt)가 화면 등록 목록에 빠져 있어 React Flow가 경고를 렌더마다 쏟아내고 있었습니다. 이번 변경 전부터 있던 누락입니다. 등록을 추가해 경고 0으로 만들었습니다.

전체 린트에는 기존 오류가 하나 남아 있다

이번 변경과 무관

변경 파일만 따로 검사했을 때 오류는 없었습니다. 저장소 전체 린트는 기존 src/features/writer/writer-generation-view.tsx:54의 효과 안 상태 변경 오류 때문에 실패했습니다. Director 변경에서 새로 생긴 오류는 아니며, 변경 파일에서는 기존 경고 세 개만 보였습니다.

  • 비용을 내는 실제 영상 생성에서 마지막 장면이 원하는 시작 구도로 이어지는지 — 생성 버튼은 과금이라 오너 판단 뒤에만 누릅니다

판단하려면 무엇이 더 필요한가

남은 확인 — 딱 하나, 비용이 드는 것

  • 완료 영상을 다음 영상 입력에 연결한 뒤 실제로 생성 버튼을 눌러, 만들어진 영상이 이전 영상의 마지막 장면에서 이어지는 구도로 나오는지. 영상 1편 생성 비용(약 $1)이 들며, 시험 계정에는 완료 영상이 없어 실제 프로젝트에서 눌러야 합니다.

이 확인은 과금 동작이라 자동으로 돌리지 않았습니다. 진행 여부는 오너 판단입니다.

내구성에 관한 선 — 실측으로 확정

연결 번호와 마지막 장면 주소는 Director 캔버스의 브라우저 저장에만 남습니다. 브라우저 저장을 지우고 새로고침하는 새 기기 시뮬레이션에서 Shot 카드 2장은 서버에서 복원됐지만 연결 입력은 빈 값이었습니다. 다른 기기·다른 브라우저까지 보장하려면 서버 데이터베이스에 관계 행을 기록하는 별도 작업이 필요합니다.

7

결론

연결 구조와 생성 경계는 닫혔고, 브라우저 증거만 남았습니다

1. 그림→그림과 그림→영상 연결은 입력 번호를 저장하고 생성 시 공개 그림 주소로 해석합니다.

2. 영상→영상 연결은 현재 공급자 계약에 맞춰 이전 영상 마지막 장면을 다음 영상의 시작 그림으로 변환합니다. 영상 주소를 직접 보내지 않습니다.

3. 연결 실패·원본 변경·순환·삭제는 오래된 결과를 그대로 쓰지 않도록 막습니다.

4. 전체 영상 생성은 확인창과 동시 실행 제한을 거치며, 이미 끝난 영상이나 진행 중인 영상은 건너뜁니다.

5. 실제 화면에서 드래그 연결·새로고침 복원·마지막 장면 추출까지 확인했습니다. 남은 것은 비용을 내는 실제 영상 생성 1건과, 연결 관계의 서버 기록(별도 작업)입니다.

근거로 쓴 것 — 원격 main 재배치 후 feat/director-node-wiring 커밋, pnpm typecheck, pnpm test:all(192개 시험 파일 통과·2개 건너뜀, 1,657건 통과·26건 건너뜀), Orca 내장 브라우저에서 개발 서버 로그인 후 실측: 드래그 연결 2회 재현·새로고침 복원·브라우저 저장 삭제 후 연결 소실·실제 저장소 영상(5.16초)의 마지막 장면 JPEG 추출·저장소 응답의 교차 출처 허용 헤더.

이 문서가 하지 않는 것 — 비용을 내는 실제 영상 생성의 결과 판정(오너 승인 뒤에만), 서버 데이터베이스의 영상 간 관계 저장(별도 작업으로 남김). 공개 링크 발행은 Orca 설정에서 꺼져 있어 로컬 파일로 열었습니다.
