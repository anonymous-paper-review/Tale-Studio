보관함이 왜 찼나 — 3.6기가를 파일 단위로 뜯어봤습니다

Supabase가 요금 한도 초과로 서비스를 끊었습니다. 로그인·데이터·이미지가 전부 막혀 있습니다. 무엇이 얼마나 쌓였는지, 작업 한 건이 용량을 얼마나 먹는지, 어디서 새고 있는지를 실제 파일 목록에서 재봤습니다.

결론 먼저 — 실사용자가 몰려서 터진 게 아닙니다. 테스트·샘플 프로젝트 37개가 전체의 86.6%를 먹었습니다. 이것만 지우면 무료 한도 안으로 돌아옵니다. 다만 지금은 지울 수 없습니다. 파일 삭제 요청도 같이 막혀 있어서, 요금 문제를 먼저 풀어야 청소를 시작할 수 있습니다.

1

무엇을 알고 싶었나

서비스가 멈췄고 세 가지가 동시에 한도를 넘었다는 통보를 받았습니다. 알고 싶었던 건 세 가지입니다.

  1. 실사용자 때문인가, 우리 때문인가. 가입자가 늘어서 터진 거라면 요금제를 올리는 게 답이고, 개발하다 쌓인 거라면 청소가 답입니다. 대처가 정반대로 갈립니다.
  2. 작업 한 건이 용량을 얼마나 먹나. 이걸 모르면 요금제를 올려도 언제 또 터질지 예측이 안 됩니다.
  3. 새는 곳이 있나. 정상적으로 쌓인 것과 안 지워져서 남은 것을 갈라내야 합니다.

확인 방법. 서비스는 막혀 있지만, 데이터베이스에 직접 접속하는 통로는 살아 있었습니다. 요금 차단은 바깥쪽 관문에만 걸려 있고 데이터베이스 자체는 그대로 돌아가고 있습니다. 그래서 파일 목록 표를 직접 읽어 파일 하나하나의 크기·만든 시각·경로를 전부 집계했습니다. 아래 저장 용량 숫자는 추정이 아니라 실측입니다.

반대로 나간 데이터량은 실측이 불가능했습니다. 누가 언제 어떤 파일을 받아 갔는지는 데이터베이스에 안 남습니다. 요청 기록은 관리 화면의 별도 보관소에만 있고 무료 요금제는 보관 기간이 짧습니다. 그래서 이 문서는 저장 용량은 실측, 나간 데이터량은 부분 실측 + 나머지는 미상으로 갈라서 씁니다.

추정의 근거는 있습니다. 가장 큰 프로젝트를 줄인 그림 없이 한 번 열면 301메가가 나가므로, 그런 조회가 50번만 있어도 15기가입니다. 개발하면서 화면을 새로고침한 횟수를 생각하면 충분히 가능한 양입니다. 다만 이건 계산이 맞아떨어진다는 것이지 증명은 아닙니다.

같은 이유로 관리 화면의 1.79기가와 실측 3.61기가가 왜 두 배 차이 나는지도 모릅니다. 집계 시점 차이인지, 세는 방식이 다른지 확인할 방법이 없습니다. 확실한 건 실제 파일은 3.61기가만큼 존재한다는 것뿐입니다.

대처

먼저: 지금 하면 안 되는 것

파일 삭제 요청이 막혀 있다고 해서, 살아 있는 데이터베이스 통로로 파일 목록 표의 줄을 직접 지우면 안 됩니다. 목록에서만 사라지고 실제 파일은 그대로 남습니다. 용량은 하나도 안 줄고 추적조차 안 되는 주인 없는 파일만 늘어납니다. 삭제는 반드시 차단이 풀린 뒤 정상 경로로 해야 합니다.

1단계 — 지금 (차단 중에도 됨)

  1. 요금제 상태를 확인합니다. 관리 화면에서 무료인지, 유료인데 지출 상한에 걸린 건지 봅니다. 후자면 상한 해제만으로 즉시 복구됩니다.
  2. 결제 주기 시작일을 확인합니다. 기다리는 쪽을 택할 경우의 복구 시점입니다.
  3. 관리 화면 파일 탐색기에서 삭제가 되는지 눌러 봅니다. 되면 아래 2단계 첫 항목을 지금 바로 할 수 있습니다.

  3. 줄인 그림 생성을 업로드 시점에 강제합니다. 지금은 만들다 만 상태가 21%나 됩니다.
  4. 보관 기간 규칙을 넣습니다. 임시 파일은 하루, 시험 프로젝트는 한 달 같은 식으로.

4단계 — 구조 (검토 사항)

지금 속도로는 유료 요금제로 올려도 시간을 버는 것뿐입니다. 영상·이미지를 이 보관함에 계속 둘지가 진짜 질문입니다. 선택지는 셋입니다.

  • 외부 생성 서버가 이미 갖고 있는 결과물 주소를 그대로 씁니다. 지금은 받아서 다시 올리고 있습니다. 그 주소가 언제까지 유효한지만 확인하면 저장 자체를 줄일 수 있습니다.
  • 나간 데이터량에 요금을 안 매기는 저장소로 옮깁니다. 영상을 다루는 서비스에서는 이게 일반적인 선택입니다. 데이터베이스와 로그인만 지금 자리에 남깁니다.
  • 지금 자리를 유지하고 보관 기간 규칙으로 버팁니다. 가장 싸게 시작하지만 사용자가 늘면 다시 같은 문제가 옵니다.

결론

  1. 실사용자 때문이 아닙니다. 가입자 114명 중 110명은 파일을 하나도 안 만들었습니다. 관리자 계정의 시험용 프로젝트 37개가 전체의 86.6%입니다.
  2. 샷 한 건이 3.41메가입니다. 무료 한도 1기가는 샷 300건, 프로젝트 6~10개 분량입니다.
  3. 배치 참조 시트가 단일 최대 낭비입니다. 295장 625메가가 저장 용량을 먹고, 외부 서버가 받아 가면서 나간 데이터량을 또 먹습니다. 파일 이름에 만든 시각이 들어가 덮어쓰기가 원천적으로 불가능한 구조입니다.
  4. 줄인 그림 스위치는 문제가 아니었습니다. 운영 서버에서 7일 전부터 켜져 있었습니다. 문제는 줄인 그림이 21% 빠져 있다는 것입니다.
  5. 나간 데이터량 16.4기가 중 1.3기가만 출처를 확정했습니다. 나머지는 기록이 없어 추정만 가능합니다.
  6. 시험 프로젝트 정리만으로 무료 한도 복귀가 가능합니다. 3,124메가를 회수하면 482메가가 남습니다.
  7. 다만 지금은 아무것도 지울 수 없습니다. 요금 문제를 먼저 풀어야 청소가 시작됩니다.
