## interpretation

오너는 입력 단계가 형식을 미리 정해두고 분기하는 방식(딱딱함)이라고 보고 있고, 무엇이
들어오든 해석해서 정보화하는 방식을 원한다. **바꿀지 말지는 오너의 설계 선택**이므로 밤은
결정하지 않는다. 다만 "지금 실제로 무엇이 강제되고 있는가"는 코드 안에 있으므로 사실 지도를
깔아둔다. 이 지도가 있어야 오너가 말랑함의 크기를 잴 수 있다.

## observation — 이 조사가 답해야 할 질문

producer 단계가 사용자 입력을 받아 DB 로 넘기기까지, 형식을 강제하는 자리가 어디에 몇 개나
있는가.

## 선기입 수용 기준

1. producer 단계의 사용자 입력 수용 지점을 전부 나열한다 (채팅, 파일 업로드, 폼 필드 등).
   각각 `파일:줄`.
2. 각 지점에서 **거부·분기의 근거가 되는 조건**을 나열한다 — 확장자 허용목록, MIME 검사,
   스키마 검증, 필수 항목, 길이 제한, 종류별 분기문. 각각 `파일:줄` 과 실제 허용값.
3. 자유 텍스트가 구조화된 DB 값으로 바뀌는 자리를 특정한다. 그 변환이 규칙 기반인지 모델
   호출인지 구분해 쓴다.
4. "무엇이 들어오든 모델이 해석해 정보화하는 경로가 이미 존재한다"를 **참/거짓/부분** 으로
   판정하고 근거를 붙인다. 부분이면 어디까지 되고 어디서 막히는지 쓴다.
5. 스토리·연출·비주얼 세 축으로 입력을 분해하는 자리가 이미 있는지 참/거짓으로 답한다.
   있으면 그 축의 실제 이름과 자리를 쓴다.
6. 설계 제안·개선안은 쓰지 않는다. 현재 사실만 쓴다.

### 확인한 것 — 딱딱한 곳은 "파일 관문" 하나다

오너 물음: "무엇이 들어오든 모델이 해석해 정보화하는 경로가 이미 있나?" → **부분.**

- **있다**: 채팅 자유 텍스트와 첨부 이미지는 실제로 모델이 해석해 설정·인물·배경·줄거리로
  정보화한다(`src/app/api/produce/chat/system-prompt.ts`,
  `src/lib/parse-extracted-settings.ts:24-62`, `src/lib/claude.ts:40-125`).
- **막힌다**: 그 앞에 **확장자 화이트리스트 6종**이 있다 — txt·md·markdown·docx·jpg/png/webp
  만 통과(`src/lib/upload/limits.ts:59-68`). PDF·HWP·DOC·SVG·GIF 는 거부 문구까지 하드코딩돼
  모델이 보기도 전에 반송된다(`limits.ts:75-82`). 오너가 지목한 "무조건 이런 입력이면 이렇게
  처리해야 해"가 바로 이 자리다.
- **반대 방향의 무름**: txt·md·docx 는 오히려 **모델을 안 거치고** 원문 그대로 저장된다.
  이건 실수가 아니라 의도다 — `global-chat.tsx:592` 주석: "모델을 태우면 시스템 프롬프트상
  짧은 문단으로 압축돼 업로드 원고가 사라진다". 즉 "클로드가 다 해석하게 하자"를 그대로
  적용하면 **이미 한 번 밟은 지뢰를 다시 밟는다.**

**드래그 앤 드롭은 아예 없다** — `onDrop`/`onPaste` 핸들러 0건. 업로드는 클릭 버튼 하나뿐
(`global-chat.tsx:1488`). 형석 메모의 "드래그 앤 드롭 활성화"와 같은 자리다.

**검증이 필드마다 들쭉날쭉하다**(사실): 모델이 뱉은 `format`·`dialogueLanguage` 는 검증 없이
그대로 꽂히고(`src/stores/producer-store.ts:387-394`), `entityType`·`role` 은 반대로 이진
화이트리스트로 뭉갠다(`producer-store.ts:93,102`, `src/app/api/writer/start/route.ts:39-41`).
런타임 화이트리스트 `parseProjectFormat`(`src/types/project.ts:40-44`)은 존재하지만 producer
저장 경로에는 안 걸려 있고 director/writer 쪽에서만 쓰인다.

### 확인한 것 — 세 축 해석기는 없다

오너의 "스토리·연출·비주얼 축을 각각 뽑는 해석기" → **없다.**
producer 프롬프트가 이름 붙여 뽑는 것은 사실상 **스토리 축 하나**다. 비주얼은 이미지가
첨부됐을 때만 발동하는 부가 항목으로 부분 존재하고(`system-prompt.ts:126-144`),
**연출 축은 producer 단계에 이름조차 없다**(프롬프트 내 "연출"·directing·cinematography 검출
0건). director 스테이지는 있지만 그건 입력 해석기가 아니라 writer 산출물 위에서 도는 하류
저작 단계다.

### 확인 못 한 것
