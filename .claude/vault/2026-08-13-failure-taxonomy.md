  "실패 지점만 재생성"의 다음 투자처는 스테이지 체크포인트(P3)보다 잡 축 클래스별 재제출일 수 있다.
- **백필 분포** (2026-08-13, status='failed' 48건): `bad_request` 14 · `infra` 13(8/5 쿼터 사고
  수동 정리) · `moderation_soft` 9(빈/검은 산출) · `data_ref` 5(참조 URL 접근 불가) · `billing` 4
  · `provider` 2 · `moderation` 1(명시 content_policy_violation) · unknown 0.
- **Bad Request 14건 조사 — 가설 2개 기각**:
  - 전부 fal `gpt-image-2/edit`, 제출 성공 후 웹훅 `payload_error='Bad Request'`(본문 소실),
    7/24~8/11 분산 = 단일 장애 아님, 발생률 ~3%.
  - **안 통한 것**: 프롬프트 길이 가설 — 실패 최장 12,793자 < 성공 최장 12,961자(성공 중앙값

  - **안 통한 것**: 동일-target 재시도 성공 여부로 재시도성 판정 — 동일 target 후속 잡이 1/14뿐.
    그리드 계열은 실패 후 시트 재편성으로 target 이 바뀌어 **이력으로는 구조적으로 판정 불가**.
  - 결론: 원인 확정 불가(fal 이 400 본문을 버림) → 처방을 "조사"에서 "태깅 후 자동 재시도가
    스스로 재시도성을 답하게"로 전환. bad_request 를 독립 클래스로 두고 재시도 성공률을 축적한다.
- **분류 규칙 정본은 코드**: `classifyJobError`(generation-jobs.ts) — 규칙 순서가 우선순위다

  함, 429 문구에 "quota" 가 끼는 프로바이더 때문에 quota 단어는 billing 판정에 안 씀).
  테스트 픽스처는 전부 실측 메시지(tests/job-error-class.test.ts).
- **writer 축 실패 사망 원인은 예외가 아니라 시간 예산 소진**(3건 중 2건) — #stage-retry P1 의

## 2. 결정 — 코드로 귀결 안 된 것만

### D-2026-08-13-a: 클래스별 처방 방향 (정책 확정은 아직 — §3)
- 상황: 오너가 "오류를 분류해서 정하자"고 방향 제시. 분류는 완료, 정책은 미확정.
- 방향 합의(실측 근거): `provider`·`moderation_soft` = 자동 재시도 가치 있음 /
  `moderation`·`data_ref`·`billing` = 재시도 무의미(각각 프롬프트 수정·데이터 수리·오너 알림이
  맞는 처방 — **billing 은 사용자에게 재시도 버튼을 보여주면 안 되는 클래스**) /
  `bad_request` = 미확정(태깅 데이터가 답할 것).
- 기각한 대안: 전 클래스 일괄 자동 재시도 — 이유: billing/data_ref 는 확정 낭비, moderation 은
  같은 거부 반복.

### D-2026-08-13-b: 오너 확정 — 이해된 클래스 선배선, 나머지는 데이터 대기
- 상황: 오너가 "집계된 오류들 미리 배선" 지시 — provider/우리서버=무차감 백그라운드 재시도,
  저작권/NSFW=유저에게 물음, 나머지=실사용 집계 후.
- 결정(코드로 귀결 — 커밋이 진실, 여기는 판단만):
  - writer 축: `network` 클래스 신설, **예산 무차감** 재시도(진입 attempt 원복 + `_netRetry`
    안전핀 캡 8 + 지수 백오프 ≤15s). 캡은 정책이 아니라 무한 루프 안전핀 — 소진 시 resume 버튼.
  - 잡 축: give-up 게이트가 `provider`/`infra` 를 **세지 않음** — 빈칸 자율 채움이 백그라운드
    재시도를 담당(새 재시도 기계를 만들지 않고 기존 자율 채움+게이트 면제로 구현한 것이 핵심 선택).
  - moderation(NSFW·저작권 뭉침): 면제 안 함 — 게이트가 곧 멈추고 실패가 유저에게 보이며,
    회복은 사람의 명시 재생성(기존 계약 그대로가 "유저에게 묻기"의 구현).
  - `bad_request`·`moderation_soft`·`data_ref`·`billing`·`unknown`: 정책 미확정 유지 — 집계 대기.
- 감수하는 것: 미태깅(null) 실패는 보수적으로 게이트에 센다. network 장기 장애 시 최대
  캡×백오프만큼 조용한 지연이 생긴다(관측은 `_repairs` 의 `[network n/8]` 태그로 가능).
