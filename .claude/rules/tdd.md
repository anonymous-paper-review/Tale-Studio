# 약속 선행 (TDD) — 모든 슬라이스 공통

> 근거: 2026-09-04 오너 결정. 2026-09-02 실측 — 빌링 정책 12문장 삼진 결과 "내가 정함 0 · 인지 4 ·
> 처음 봄 8". 정책이 구현 뒤에 태어나 오너 머리를 거치지 않았고, 오너는 그 슬라이스의 테스트를
> "뭘 하는 건지 몰라서" 쓸 수 없었다. 순서를 뒤집는다: **약속이 먼저, 구현이 나중.**
> 오너의 TDD는 코드가 아니라 **한국어 약속 문장을 먼저 정하는 것**이다. 코드화는 에이전트 몫.

## 순서 — 기능·수정·버그 어느 것이든

1. **설명** — 에이전트가 이 슬라이스가 바꾸는 **사용자 경험**을 한국어 5줄 이내로 쓴다.
   구현 용어(RPC·402·mock·낙관 갱신 등) 금지. 오너가 "뭘 하는 건지 모르겠다"면 여기서 멈춘다 —
   설명이 안 되는 슬라이스는 만들지 않는다.
2. **약속** — 약속 문장을 정한다. 오너가 직접 쓰거나, 에이전트가 후보를 내고 오너가 고르거나
   고친다. 문장 하나 = 테스트 케이스 하나. 꼴은 "~이면 ~한다" 수준의 한국어.
   오너 삼진: ① 내가 정함 / ② 인지 / ③ 처음 봄. **③이 남아 있으면 구현을 시작하지 않는다.**
3. **빨강** — 에이전트가 그 문장을 **그대로 케이스 이름**으로 테스트를 먼저 쓰고 빨간 것을 확인한다.
   파일 머리말(첫 줄 주석)은 "이 파일이 지키는 약속" 한국어 한 줄.
4. **초록** — 구현한다. 커밋 전 훅(`.githooks/pre-commit`)이 통과해야 한다.
5. **보고** — 완료 보고에 약속 문장 목록을 그대로 싣는다(`owner-gates.md` 정책 문장 diff와 같은 표면).
   원장(`pnpm test:ledger`)에 오너가 정한 문장이 그대로 남는다.
   문장마다 **"왜: 어떤 상황에서 필요한가"** 한 줄을 붙인다(2026-09-07 오너 지시). 정상 경로 테스트는 "정상 경로 고정"이라 적고,
   고장 테스트는 그 고장이 언제 일어나는지(누가·어느 경로에서) 적는다. 오너는 ts 를 읽지 않으므로 이 두 줄이 테스트의 전부다.

## 빨간불 판정 — 에이전트는 테스트를 고치거나 지우지 않는다

`pnpm test`가 실패하면 판정 카드(파일 머리말 · 약속 문장 · 실제 결과)가 자동으로 찍힌다.
판정은 셋 중 하나이고 **②③은 오너 몫이다.**

- ① 코드가 틀렸다 → 약속 유지, 코드를 고친다. 기본값 — 에이전트가 바로 고치고 보고에 남긴다.
- ② 약속이 바뀌었다 → 문장을 고친다. 오너가 새 문장을 정한 뒤에만.
- ③ 약속이 없어졌다 → 지운다. 오너 판정 뒤에만.

빨간 테스트를 통과시키려고 문장·기대값·`skip`을 손대는 것은 ②③을 에이전트가 대신 판정한 것이다. 금지.

## 적용 경계 — 약속으로 쓸 수 있는 것과 없는 것

- **약속으로 쓴다(선행 필수)**: 로직 · 정책(빌링·쿼터·플랜·게이트) · 권한 · 상태 전이 · API 응답 ·
  저장 형식 · 핸드오프 · 텍스트 처리. 지금 스위트의 거의 전부가 여기다.
- **약속으로 못 쓴다**: 그림·영상·프롬프트 산출의 **품질**(오너만 판정 — `experiments.md`),
  화면의 **생김새**(스크린샷 보드 — `owner-gates.md`). 이 경우 1단계에서 "테스트 대신 무엇을
  검수 표면으로 쓰나"를 명시한다. 품질을 흉내 낸 가짜 테스트(항상 통과·경고만 찍는 것) 금지.

## 부채 — 이 규칙 이전에 태어난 테스트

2026-09-04 기준 머리말 없는 파일 183 · 영어 케이스 이름 700여 · 구현 용어로 적힌 약속 다수
(예: `shadow 는 enforce=false 로 RPC 를 호출한다`). 청산은 별도 작업(머리말 → 묶음 정리 →
한국어 약속 문장화)으로 하고, **새로 태어나는 테스트는 이 규칙대로만** 쓴다.
