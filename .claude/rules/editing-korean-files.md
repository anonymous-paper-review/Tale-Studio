# 한국어가 많은 파일 편집 — 도구 선택 규칙

2026-08-26 세션에서 편집 도구 호출이 반복적으로 거부·중단됐다. 원인은 코드가 아니라 **도구 호출 방식**이었다.
같은 손해를 반복하지 않기 위한 규칙.

## 관측된 실패 두 가지

1. **한글이 유니코드 이스케이프로 직렬화됨** — 편집 도구에 한국어를 보낼 때 실제 글자 대신 `\uXXXX`
   코드로 나가면 안전장치가 실행을 거부한다. 한 글자만 틀려도 조용히 다른 글자가 되므로 막는 게 옳다.
2. **긴 편집 내용이 중간에 잘림** — 한 번에 보내는 텍스트가 길면 출력 한도에 걸려 인자 전송이 끊긴다.
   한국어 주석·문서처럼 문자당 비용이 큰 내용에서 특히 잘 난다.

둘 다 재시도하면 통과하지만, 세션 시간을 크게 갉아먹는다.

## 규칙

- **작은 수정(한두 군데)**: 편집 도구를 쓰되 한 번에 한 덩어리만. 한국어 블록은 짧게 쪼갠다.
- **문서 전면 개정**: 편집(부분 치환)이 아니라 파일 쓰기로 통째로 새로 쓴다.
- **여러 곳 기계적 제거·치환**: `python3 - <<'PY'` 힙독 스크립트로 처리한다. 이스케이프 문제도,
  길이 한도도 우회된다.
- **스크립트로 편집한 직후에는 반드시 `pnpm typecheck`.** 실측(2026-08-26): 정규식이 JSX 안
  템플릿 리터럴의 중괄호에서 잘못 끊겨 파일을 깨뜨렸고, 타입체크가 즉시 잡아냈다.
  정규식 치환은 중괄호·백틱이 섞인 JSX 에서 특히 위험하다 — 가능하면 문자열 완전일치로 바꾼다.
- **새 코드 주석은 영어로 써도 된다.** 기존 한국어 주석 스타일과 섞이지만, 편집 실패를 반복하는 것보다 낫다.
  단 사용자에게 보이는 문구(UI 텍스트·문서)는 한국어 원칙을 유지한다.
