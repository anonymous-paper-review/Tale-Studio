# Experiments — 재현성 3규칙 + 가설 자격 심사

> 형태 원칙: architecture.md와 동일 — 판별 질문 위주, 파일 나열 금지.

## 재현성 3규칙

1. **복붙 금지** — 실험 코드는 제품 함수를 import해 호출만 하는 얇은 껍데기다.
   백엔드 로직이 한 줄이라도 복사돼 있으면 잘못된 것.
   판별 질문: "제품 코드가 바뀌면 이 실험 코드도 따라 고쳐야 하는가?" — YES면 복붙이 있다.
2. **스테이지 격리는 입력 고정으로** — 특정 스테이지 실험 = 상류 출력을 fixture로
   고정하고 실제 스테이지 코드를 실행. 실험용 파이프라인 별도 구현 금지.
   판별 질문: "이 실험이 통과하는 코드가 유저 요청이 통과하는 코드와 같은가?"
3. **좌표 기록** — 모델 버전·seed·파라미터·입력을 실험 기록에 항상 남긴다.
   출력 재현은 모델 버전 경계를 넘으면 불가능하다는 전제.
   재현의 단위는 "같은 출력"이 아니라 **"같은 입력 + 같은 채점 기준"**이다.

## 3D·Blender 작업은 서브에이전트 전용 (2026-08-11 오너 지시)

메인 세션(Fable)은 Blender를 직접 실행하지 않는다 — 설치·bpy 스크립트·렌더는 **서브에이전트에 위임**한다.
사유: 3D 반복은 시행착오가 길고 출력이 장황해 메인 대화의 맥락을 잠식한다(맥락은 판단에 쓴다).
메인이 하는 일은 지시·판독·보고뿐. 이미 만든 블록아웃은 **재사용**하고 재제작을 시키지 않는다
(fal storage URL은 실험 폴더 manifest.json에 보존).

판별 질문: "이 작업이 Blender를 켜거나 bpy를 실행하는가?" — YES면 위임.

## 가설 자격 심사 (실험 시작 전)

새 실험의 가설은 `research/experiments/_HYPOTHESIS.md` 폼으로 작성한다.
에이전트는 가설이 **옳은지**가 아니라 **자격**만 심사한다:

- 반증 조건이 없으면 반려 — 어떤 관측이 나오면 죽는 가설인가?
- 측정이 가설의 개념을 담지 못하면 반려 (개념→측정 비약)
- 전제가 기록된 실측(vault·live DB)과 모순되면 반려
- 실험보다 싸게 죽일 방법(DB 감사 등)이 있으면 실험 전에 그걸 먼저 제안

기각 조건은 실험 **전에** 확정하고, 결과를 본 뒤 가설을 소급 수정하지 않는다(사전 등록).
