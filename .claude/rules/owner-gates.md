# 오너 관문 — 검수 표면 규칙

> 근거: 2026-09-02 레버리지 설계 토론. 오너의 검수 표면은 **한국어 문장과 화면 이미지** 둘뿐이다
> (오너는 TS 코드를 읽지 않는다). 오너 승인이 필요한 산출물이 이 두 매체 밖에 있으면
> 검수를 통과한 것이 아니다. 실측 배경: 빌링 정책 12건을 오너에게 보였더니 오너가 직접 정한 것 0건 —
> 정책이 유도로 태어나 오너 머리를 거치지 않았다.
>
> 용어는 세션 보고서 표준(`~/.claude/skills/artifact/SKILL.md`)을 따른다: 같이 정한 것 / 혼자 정한 것 /
> 결정이 필요한 것. 새 조어를 만들지 않는다(2026-09-11 오너 지시 — "약속 문장"·"삼진" 폐기).

## 정책 문장 diff (정책성 작업)

- 대상: 빌링·쿼터·게이트·플랜 등 "고객에게 한 약속"이 코드로 들어가는 작업.
- 작업 완료 보고에 **이번에 태어나거나 바됌 정책 문장**을 한국어로 나열한다. 구현 용어 금지 —
  테스트 이름 수준의 "~이면 ~한다" 문장으로. 두 묶음으로 나눈다:
  - **같이 정한 것** — 대화에서 오너가 정했거나 이미 알고 있는 것. 훑어보기만.
  - **혼자 정한 것** — 에이전트가 유도한 것. 표: 동작 / 왜 / 버린 선택지 / 되돌리기(`쉬움` `비쌄` `못 돌림`).
    `비쌄` 이상은 오너 확인 칸을 비워 두고 **결정이 필요한 것**으로 올린다.
- 정책이 걸린 테스트 이름은 한국어 정책 문장으로 쓴다 (기존 관례를 의무로 승격).
- 2026-09-04부터 이 구분은 구현 **앞**에 한다 — `tdd.md`. 완료 보고의 문장 목록은 앞에서 정한
  문장이 그대로 실렸는지 확인하는 자리다.

## 스크린샷 보드 (UI 작업)

- UI 작업 완료 시 핵심 화면 스크린샷을 세션 보고에 첨부한다.
  수집기는 smoke(`pnpm smoke`, Orca 브라우저). 보드 자동화(티켓 `smoke-screenshot-board`)
  전까지는 현행 smoke 스크린샷 첨부가 최소 이행이다.
- 에이전트 역할은 수집과 기계적 실패 검출(콘솔 에러·HTTP 실패·미렌더)까지.
  품질 판정 승격 금지 — `.claude/rules/experiments.md` 대전제와 동일.

## 색상 게이트 (기계 강제)

- `pnpm lint:design`(CI 포함)이 `src/components`·`src/app`의 raw 색(hex·rgb/hsl/oklch)을 막는다.
  의도적 예외는 `eslint-disable-next-line no-restricted-syntax` + 사유 한 줄.
  규칙 본문: `eslint.design.config.mjs`. 전체 `pnpm lint`는 기존 부채 청산 후 CI 편입.
