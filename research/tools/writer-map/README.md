# writer 배선도

비주얼 축(v0~v5)과 샷 층(데쿠파주 · 샷 설계 · 샷 검수)을 노드 그래프로 펼친 지도.

```bash
pnpm map:dev                  # http://localhost:4321 — 코드가 바뀌면 자동 갱신
pnpm map:build [출력.html]     # 아티팩트로 올릴 정적 스냅샷 (기본: writer-visual-shot-map.html)
```

## 왜 이렇게 만들었나

지도는 손으로 쓰면 반드시 낡는다. 그래서 **코드가 진실인 부분은 하나도 복사해 두지 않는다**:

| 무엇 | 어디서 오나 |
|---|---|
| 지시문 원문 | 요청 시점에 소스에서 잘라 온다 (`extract.mjs`) |
| 상수 (샷 초 대역, 동시성, 샷 상한 등) | 정규식으로 소스에서 읽는다 |
| 실제 산출 예시 | `logs/` 의 가장 완결된 런에서 읽는다 |
| 소비처 유무 ("사장 필드") | 매 요청마다 다시 센다 |
| **해석** (왜 이 모양이 됐나) | 여기만 손으로 쓴다 — `data.mjs` / `findings.mjs` |

앵커는 줄 번호가 아니라 **문자열 경계**다. 줄이 밀려도 살아남고, 그 문자열 자체가 사라지면
페이지 상단에 "문서와 코드가 어긋난 자리"로 뜬다 — 조용히 낡지 않는다.

## 파일

- `extract.mjs` — 소스 색인, 문자열 경계 슬라이스, 상수 프로브, 소비처 카운트, 런 로그 읽기
- `data.mjs` — 노드·밴드·체인 정의 + 앵커 + 검증 항목. 손으로 쓰는 곳
- `findings.mjs` — 끊긴 곳·새는 곳. 손으로 쓰는 곳
- `render.mjs` — 모델 조립 + HTML 생성 (서버판·스냅샷판 공용)
- `serve.mjs` — 로컬 서버 + 파일 감시 + SSE 새로고침
- `build.mjs` — 정적 스냅샷

## 고칠 때

- **코드를 바꿨는데 앵커가 깨졌다** → 페이지 상단 경고에 어느 앵커인지 뜬다. `data.mjs` 의 `from`/`to` 를 고친다.
- **사장 필드였는데 배선이 생겼다** → `probes` 가 알아서 잡아 "배선됨" 배지를 띄운다. 노드 설명을 갱신한다.
- **노드를 추가한다** → `data.mjs` 의 `NODES` 에 넣고 `band`/`row`/`col` 로 자리를 정한다. 엣지는 `inputs[].from` 에서 자동으로 그려진다.

환경변수: `WRITER_MAP_PORT`(기본 4321), `WRITER_MAP_RUN`(예시로 쓸 런 디렉토리 고정).
