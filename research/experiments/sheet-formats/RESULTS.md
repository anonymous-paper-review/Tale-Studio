# 포맷별 러프 시트 템플릿 — 제작·배선·라이브 실측 (#sheet-formats)

- 날짜: 2026-08-17 / 오너 지시: "Vertical, Cinematic, Square 템플릿과 strip 템플릿을 추가 제작"
- 선행: `#fal-canvas`(같은 날) — 캔버스는 포맷을 따르게 됐지만 러프 템플릿·셀 좌표는 가로
  고정이라, 포맷의 진짜 뿌리(시트 셀이 포맷 종횡비를 갖는 것)가 미해결이었다.

## 설계 결정 3건

1. **템플릿은 스펙에서 그린다** — 레거시 템플릿의 "교체 시 재실측 ⚠️" 함정(격자선 dark-ratio
   프로파일로 수동 검출)을 제거. `SHEET_SPECS`(rough-storyboard-grid.ts)가 캔버스·셀 px 박스·
   프레임 축의 단일 진실이고, `tests/rough-template-assets.test.ts` 의 게이트 생성기가 같은
   스펙에서 PNG 6장을 그리며, 같은 파일의 상시 테스트가 커밋된 PNG 치수를 스펙과 대조한다
   (드리프트 = CI 실패). 색은 레거시 실측(#FAF8F2 종이 / #5B5A59 격자선)을 승계.
2. **세로 스트립은 가로 3열** — 3단 적층으로 9:16 셀을 만들면 1024×1536 캔버스에서 좌우 여백이
   각 379px(셀 266px 폭)로 극단. 가로 3열(1536×1024)이면 셀 474×842 — 좌→우 = START/DIRECTION/
   END. 프레임 축 개념(frameAxis 'rows'|'cols')을 크롭·합성·프롬프트에 도입해 축만 다르고
   구조는 동일하게 처리.
3. **리페인트 레퍼런스는 프레임 AR 매칭** — 기존(가로) 러프 프레임을 세로 셀에 fill 하면 왜곡.
   합성은 프레임 실측 AR 에 가까운 시트(레거시 vs 포맷)를 골라 붙이고, 고른 지오메트리가
   캔버스·프롬프트 축·finalize 크롭의 공통 계약이 된다(스냅샷 `sheet_format`). 레거시 프레임 +
   세로 캔버스 조합은 #fal-canvas T2 실측이 검증한 경로 — 러프를 포맷 템플릿으로 재생성하면
   프레임 AR 이 바뀌어 자연히 포맷 시트로 넘어온다(자가 치유, 마이그레이션 불요).

## 전환기 검증 (오프라인, 무료)

- 어제 T2 실측물(레거시 가로 레퍼런스 → 1024×1536 실사 시트, 3샷)을 포맷 좌표 크롭으로 파스:
  **3샷 전부 세로 프레임(AR<0.9) 추출 성공**. 좌측 보더 실 몇 px 포함은 코스메틱 — 모델이
  자체 배치한 시트라 v5 전역 거터 검출이 잡되 경계가 수 px 흔들린다. 러프가 포맷 템플릿으로
  재생성되면 시트가 템플릿 비례를 따라가 사라지는 전환기 한정 현상.
- 러프 뷰 UI: 실제 프레임은 `sizeToImage`(그림 비율 추종)라 세로 프레임 표시 안전.
  `aspect-video` 는 빈칸/로딩 플레이스홀더에만 남는다.

## 2차 개정 (같은 날, 오너 육안 피드백 "vertical 이 너무 길쭉하다")

**판정**: 이상한 건 레거시 쪽 — 레거시 16:9 셀은 실측 372×241 = **1.544 (-13.2%)** 로 처음부터
16:9 가 아니었다(4×3 셀을 시트 AR 에 욱여넣은 기하적 필연). 1차 vertical 셀은 정확 9:16(+0.1%).
"길쭉해 보인" 원인의 나머지 절반은 1차 캔버스 선택 실수 — 4×3 그리드에 9:16 셀을 담는 콘텐츠는
3:4 인데 2:3(1024×1536) 캔버스를 써서 상하 154px 데드밴드가 생긴 것. 90도 회전안은 셀 0.648
(+15.2%) — 레거시의 오차를 방향만 바꿔 물려받는 것이라 기각(오너에게 목업 제시 후 수제안 채택).

**공식 스키마 확보**(fal 문서): 16배수 / 최대 변 3840 / AR ≤3:1 / 총 0.66~8.29MP —
1차의 "64배수 스냅" 추정 정정(T4 의 643→640 은 16배수 스냅이었다).

**수치 원리**: 데드밴드 없는 캔버스 AR ≈ (열수/행수)×셀AR. 셀 면적은 레거시(89.7k px²) 이상 보존.

**최종 8종** (셀 AR 전부 포맷 정확값 ±1%, 오너 "수동 제작" 지시로 레거시 종이 질감 추출·승계):

| 포맷 | grid4 | 셀 | strip1 | 셀 |
|---|---|---|---|---|
| horizontal_16:9 | 1728×768 | 400×225 | 1024×1712 | 952×536 |
| vertical_9:16 | 1152×1536 | 255×453 | 1536×896 (가로 3열) | 474×842 |
| square_1:1 | 1344×1024 | 303×303 | 640×1792 | 568×568 |
| cinema_2.39:1 | 1920×704 | 447×187 | 1024×1296 | 952×398 |

레거시 좌표·템플릿은 포맷 미상(null) 구 프로젝트 + 구 잡 크롭 호환 전용으로 강등(파일 유지).
**horizontal 도 스펙 시트로 이동** — 프로덕션 37개 16:9 프로젝트의 러프·리페인트가 새 시트를
쓴다(기존 프레임·보드는 불변, 새 생성부터). 질감 생성은 게이트 생성기에 내장(레거시 PNG 에서
패치 추출 → 미러 2×2 타일 → 스펙 보더 오버레이) — 재현 가능·결정적.

**2차 라이브 실측** (286s, 6콜 — 동일 게이트 테스트, 치수 어서션은 스펙 동적 대조로 전환):
R0 horizontal 1728×768 · R1 vertical 1152×1536 · R2 v-strip 1536×896(가로 3열) ·
R3 square 1344×1024 · R4 cinema 1920×704 러프 전부 요청 치수 정확 반환 + 시트 계약 유지 +
실크롭 파스(R0 프레임 AR>1.6 — 레거시 1.54 대비 진짜 16:9 확인). R5 리페인트 체인(재합성
transposed 자동 선택 → 1536×896 리페인트 → 세로 프레임 크롭)도 신규 캔버스에서 재통과.
비네이티브 신규 치수 6종(1728·1712·1344·1792·1920·1296·896)이 전부 스키마 문서대로 동작.

## 파싱 최종 설계 — 하이브리드 (#fixed-crop, 오너 방향 수렴)

경위: 프레임 크기가 샷·프레임마다 달라(451/469/447) UI 순환 상자(첫 프레임 비율+cover)가
direction 하단을 표시에서 잘랐다. "고정 좌표로 재설계" 시도 → 오너 반론("생성기가 템플릿을
정확히 못 지키니 고정은 불가능") → 실측이 오너를 입증: 모델이 DIRECTION 캡션을 여러 칸
괘선 표로 부풀리며(최대 ~110px) 3행을 아래로 민다. 캡션 스트립 템플릿(셀의 20%)을 내장해도
모델은 괘선을 제 위치에 다시 그린다 — 픽셀 고정 기대는 성립하지 않는다.

확정 설계(실측 시트 6장 검증):
- **열 = 스펙 고정** (가로 드리프트 실측 수 px)
- **행 위치 = 순차 체인 적응**: 행1=스펙 → 행N+1=행N 끝(+DIRECTION 뒤는 전 열 최대 오버플로
  통과) 이후 첫 어두운 전환. 고정 창 스캔(±46px)은 표가 크면 반드시 놓친다 — 체인은 밀림
  크기와 무관.
- **프레임 크기 = 스펙 표준으로 상시 균일** (249×447 등 — UI 순환·영상 레퍼런스 전제)
- **DIRECTION 만 하단 오버플로(캡션 표, ≤128px·표 괘선 틈 내성 blank 12행) 포함 후 비율 유지
  축소+종이색 패딩 정규화** — 라벨 무손실 + 균일성 유지.
- 레거시(null 포맷) 시트는 종전 적응형(v4/v5) 그대로.

FAL 해상도 답: 출력 치수는 요청 그대로 픽셀 정확(누적 15+콜 전부 일치) — 해상도 불일치
문제는 없고, 문제는 캔버스 안 그리기 드리프트였다(위 하이브리드가 흡수). 화질 상향 여지:
스키마(≤3840·8.3MP) 안에서 캔버스 2배(세로 그리드 2304×3072 → 셀 510×906) 가능 — 비용
실측 후 옵션.

부속: 캡션 스트립 템플릿 8장 재생성(셀 20%, 40~96px), 라벨 다이어트(FOCUS 24자·각도어
' angle' 제거), 문안 "스트립 안에만·글씨 줄여서". a219b9f3 3시트는 재과금 없이 재크롭 반영.

### 행 래치 신호의 최종 형태 — 잉크 밀도 (같은 날 3차)

두께 기준(≥15px 연속 어두움)도 실패: 붙은 캡션 2줄(17px 연속)이 그림으로 오인돼 end 상단에
WARM 침입(오너 실측 — 재생성으로 시트가 바뀌어 로컬 검증 시트와 해시 불일치였던 것도 이때
발견, 재파싱은 "샷별 최신 잡, 오름차순" 규약으로 고정). 실측 프로파일은 이중 모드다:
캡션 텍스트 줄 0.08~0.20 / 행 그림 0.67~0.90(중간 공백), 굵은 표 괘선은 진하지만 1~3행.
행 래치 = **진한 행(≥0.35) 연속 ≥6행**, 래치 후 블록 진짜 시작(>0.08 연속 상단)까지 소급.
DIRECTION 오버플로 상한 = 다음 행 시작 - 2 (행 스캔과 한 진실 — 별도 종료 조건 폐기).
현행 시트 3장 × 9프레임 전수 검증 통과.

### 최종형: 패널 실측 박스 + 정규화 (#detect-normalize — "빈공간" 종결)

오너 질문("왜 16:9 는 잘 됐는데 갑자기 안 되나")의 답: 레거시가 잘 된 게 아니라 한 달의
v1→v5 수렴을 쓰고 있었고, 신규 4지오메트리는 그 수렴을 하루에 재주행 중이었다. 구조적
신규 변수는 캡션(넓은 셀에선 1~2줄, 좁은 셀에선 4~5줄 표) 하나다.

빈 밴드의 근원 = 고정 크기 크롭 ≠ 모델이 실제 그린 패널 크기. 최종 분업 —
**정합은 검출**(행 상·하단 전부 실측: 상단 잉크 래치, 하단 밝은 런) / **균일은 정규화**
(실측 박스 → 표준 크기 스케일: 차이 ≤8% fill, 초과 contain+종이 패딩).
행 프로파일은 **채워진 열 범위만**으로 계산(1샷 시트는 전폭 기준 잉크가 ~0.19 로 눌려
래치 불가였다 — 배터리 실측).

**회귀 배터리 신설**(tests/rough-crop-battery.manual.test.ts, BATTERY=1): 실측 시트 코퍼스
(corpus/, gitignored 로컬)에 지표 3종 — 크기 균일 / start·end 상·하단 white-band 금지 /
direction 라벨 잉크 존재. 첫 실행에서 1샷 시트 상단 밴드 26행을 즉시 검출해 값을 증명.
코퍼스 8장(세로 5 + square 3) 전 통과, 두 프로젝트 재파싱 반영.

### 코너 등록 마커 복원 (#corner-marks — 오너 제안, 초판 템플릿 요소의 귀환)

생성기 안정화를 위해 각 셀 내부 4꼭지점에 ㄱ/ㄴ 브래킷(10px 팔, 보더 4px 안쪽)을 복원 —
초판 템플릿에 있다가 7/22 "단순판"에서 제거됐던 요소다. 프롬프트에 "브래킷을 제자리에
재현하고 모든 그림을 그 안에" 계약 추가. 트레이드(오너 인지): 마커가 크롭 프레임·리페인트에
전파된다 — 실측 결과 프레임 꼭지점의 작은 브래킷은 촬영 프레임 룩으로 무해 판정.
실측 1시트: 마커 재현 ✓ 크롭 클린 ✓ 배터리(코퍼스 9장) 통과. 효과의 정량 판정(드리프트
분산 감소)은 시트가 쌓이면 배터리로 추적.
