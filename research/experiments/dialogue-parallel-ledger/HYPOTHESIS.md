# 가설 — dialogue 씬 병렬 + 사전유도 원장 (2026-08-11)

- **가설**: dialogue 씬 순차 실행의 진짜 의존은 `notable_lines`(기출 대사 반복 금지) **하나뿐**이고, 나머지 세 메모리 필드(`established_facts`·`relationship_state`·`tone_notes`)는 dialogue 시작 전 이미 확정된 s3 `scenes[]`에서 **결정론적으로 유도**된다. 따라서 유도 원장을 주입하면 씬을 병렬 실행해도 대사 품질이 유지되고, 임계경로 dialogue 409초가 씬 1~3개분으로 붕괴한다.
- **전제**:
  1. dialogue 벽시계 409s = 보이스 프로필 1콜 + 씬 콜 순차 (436초 런 실측; 한 씬은 재시도 포함 213.5s).
  2. 메모리가 씬→씬으로 넘기는 것은 4필드뿐이고 둘은 `slice(-12)`/`slice(-10)`로 유계 — `dialogue.ts` `applyMemoryUpdate` 코드 확인.
  3. `scenes[].dialogue_summary`(대사로 오간 것 한 줄)·`scene_actions`(화면에 보이는 것)·`emotion_beat`·`info_asymmetry`가 dialogue 시작 전 전부 확정 — fixture 확인. 규율 B("인물은 이 씬 시점까지 *화면에 공개된 것*만 안다")의 원천은 대사가 아니라 씬 구조다.
  4. **반증 대조**: shotCheck fan-out 회차에서 "프롬프트가 같아도 컨텍스트를 자르면 모델 판정 분포가 바뀐다"가 실측됐다(이슈 19→130). 대사 생성도 같은 위험을 갖는다고 가정하고 품질 가드를 사전 등록한다.
  5. **왜 여기인가**: 임계경로는 `max(Visual 435, Dialogue 409)`. Visual만 최적화하면 천장이 −6%다. dialogue를 안 건드리면 다른 어떤 처방도 409초 아래로 못 간다.
- **예측**: 참이면 — ① 벽시계 **≥50% 단축** ② B의 씬 간 중복 대사가 A의 **3배 이내** ③ 총 라인 수가 A 대비 **±40% 이내** ④ 씬 실패(빈 대사 흡수) **0** ⑤ B가 C(빈 메모리)보다 품질 지표에서 우월 — 원장이 실제로 기여함.
- **측정**: fixture 고정 = `logs/e4da245a-8d89-44e5-8fde-131d016ef2e3` (15씬 / 기존 순차 출력 88라인). 제품 `runDialogue` 직접 호출(복붙 없음), **`mode`/`ledger` 옵션만 갈린다**. 3팔 × 2런:
  - **A** 순차 + 메모리 체인 (현행 · 대조군)
  - **B** 병렬 + 유도 원장
  - **C** 병렬 + 빈 메모리 (바닥 대조 — 원장의 기여를 분리)

  수확: 벽시계 · 콜별 duration · 총/씬별 라인 수 · **씬 간 중복 대사**(정규화 후 정확일치 + 문자 3-gram Jaccard ≥0.6) · 침묵 예산 준수(씬 라인 수 ≤ `ceil(estimated_seconds/10)`) · 흡수 씬 수 · 화자 유효성(`characters_in_scene` 밖 화자).
- **기각 조건** (사전 등록 — 결과 본 뒤 수정 금지):
  - 벽시계 단축 **< 50%** → 병렬 이득 없음, 폐기.
  - B의 씬 간 중복 대사가 A의 **3배 초과** → 반복 금지 가드 상실이 실재, 폐기.
  - B의 총 라인 수가 A 대비 **±40% 밖** → 침묵 예산 붕괴, 폐기.
  - B가 C와 **모든** 품질 지표에서 구분 안 됨 → 원장이 무의미. (이 경우 "순차 자체가 무의미"라는 별개 결론이 열리지만, 원장 설계는 폐기.)

## 이 실험이 답하지 않는 것

정보 누설(규율 B 위반)·톤 표류·명대사 인플레는 **결정론으로 못 잰다** — 블라인드 심판이 필요하다. 이번 라운드는 결정론 지표로 **싸게 죽일 수 있는지**를 먼저 본다(실험 규칙: "실험보다 싸게 죽일 방법이 있으면 먼저"). 결정론 지표를 통과하면 그때 심판 라운드를 연다.

좌표: 모델 축 = S축 기본값(`gemini-3.6-flash`) · temperature 0.7(제품값) · 병렬 동시성 5 · 출력 `results-{a-seq,b-ledger,c-blind}.json`

## 사전 등록 조건 대조

- ① 벽시계 ≥50% 단축 → **69.2%. 통과.**
- ② B 씬간 중복이 A의 3배 이내 → **1.0배(1.0 vs 1.0). 통과.** 예상과 반대로 *늘지 않았다*.
- ③ 총 라인 수 A 대비 ±40% 이내 → **−8.5%. 통과.**
- ④ 씬 실패(흡수) 0 → **0. 통과.**
- ⑤ B가 C보다 품질 지표에서 우월 → **판정 불능.** 중복 평균만 B 1.0 < C 2.0인데 N=2에 C가 {1,3}로 분산이 커 신호로 볼 수 없다. 라인 수는 오히려 C가 A에 더 가깝다. 나머지 지표는 전부 동일.

## 판정

**병렬 가설은 확증. 원장의 기여는 미판정.**

핵심 반증: 병렬화의 대가로 지목했던 **"기출 대사 반복 금지 가드(`notable_lines`) 상실"이 결정론 지표에서 나타나지 않았다.** 가드를 통째로 뺀 C조차 씬간 중복이 평균 2.0건이다. 15씬 88~157샷 규모에서 씬을 넘는 대사 반복은 애초에 드문 사건이고, 그것을 막으려고 전 씬을 직렬화하고 있었다.

## 이 실험이 저지른 설계 오류 (기록)

기각 조건 ⑤는 **잘못 설계됐다.** 원장이 방어하는 축은 규율 B(정보 누설)인데 결정론 패널은 그걸 아예 못 잰다 — 같은 문서의 "이 실험이 답하지 않는 것" 절에 그 한계를 적어놓고도 기각 조건에는 결정론 패널로 원장을 판정하겠다고 썼다. 두 문장이 모순이다. 사후 수정 금지 원칙에 따라 조건을 고치지 않고 **판정 불능으로 남긴다.** B vs C는 블라인드 심판 라운드의 과제다.

## 부산물 — repairJson 절단이 3.6-flash에서 발화했다

b-ledger r1의 씬 콜 하나에서 `[repairJson] 손실 복구 절단(전략3) — 원문 2332자, 복구된 최상위 아이템 6개`. `2026-08-10-flash-ab-fanout-review.md` 미결("repairJson 손실 가드를 둘 것인가")의 보류 근거는 *"현행 3.6-flash는 strict 3/3이라 repair 미발동"* 이었는데, **그 전제가 깨졌다.**

손상 여부: 씬별 라인 분포·무음샷 비율(58~65%)·샷 계약(157) 모두 다른 런의 밴드 안이라 **구분 가능한 손상은 안 보인다.** 다만 `normalizeSceneDialogue`가 누락 샷을 침묵으로 채우므로 손실은 "몇 줄이 조용히 침묵이 되는" 형태로만 나타나고, 침묵은 정상 출력과 구분되지 않는다 — 이게 vault가 지적한 무신호 손실의 성질 그대로다. 96개 씬 콜 중 1회.

- **감수하는 것**: 그 축에서 퇴화가 있다면 심판 라운드까지 프로덕션에 실린다. 킬스위치가 있으므로 회수는 env 한 줄.
