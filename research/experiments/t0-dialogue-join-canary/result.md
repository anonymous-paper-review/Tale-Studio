# 대사 오배치, 고친 뒤 정말 멈췄나 — 실사용 기록으로 확인

**판정: 가설 유지(지혈 확인).** 픽스 이후 저장소에 남은 작업물 3건 중 분할이 실제로 일어난 2건에서
대사가 엉뚱한 샷에 붙은 라인은 **0건**이다. 저장된 결과물(53개 샷의 대사)도 올바른 대사와 100% 일치했다.

- 날짜: 2026-08-12 (밤 러너)
- 지출: $0 (읽기 전용 — 새 호출 없음)
- 기각 조건 발동: **없음** (사전 등록: "불일치 라인 1건이라도 나오면 기각")

## 무엇을 확인했나

고침(8월 10일 저녁 6시 29분) **이후에 만들어진 작업물만** 골라, 장면이 쪼개진 자리마다
"이 샷이 원래 누구였는지"와 "지금 붙어 있는 대사가 누구 것인지"를 글자 단위로 대조했다.
사람 판단이나 모델 판단은 한 번도 쓰지 않았다 — 전부 문자열 비교다.

두 가지를 각각 셌다.

1. **조인 자체가 맞는가** — 작업 기록 안의 샷 목록과 대사 목록을, 제품이 실제로 쓰는 조인 함수를
   그대로 불러 맞춰본다.
2. **저장된 결과물도 맞는가** — 데이터베이스에 실제로 저장된 대사 줄이 위 결과와 같은가.
   (저장할 때 샷 이름이 `shot_12` → `sh_04_12` 형태로 바뀌므로, 제품의 이름 변환기를 같이 불러 대조했다.)

## 결과

| 항목 | 값 |
|---|---|
| 고침 이후 작업물 | 3건 |
| 그중 장면 분할이 실제로 일어난 것 | 2건 (밀린 샷 16개 / 11개) |
| 대사가 붙은 샷 | 86개 (44줄 + 11줄) |
| **엉뚱한 샷에 붙은 라인** | **0건** |
| 저장된 결과물 불일치 | **0건** (대사 있는 53개 샷 전수) |
| 기준선 (고치기 전) | 다시 살펴본 22개 중 18개 오염 |

실제로 밀린 자리의 표본 (원문 앞부분만 인용):

- 최종 55번 샷 ← 원래 54번. 붙은 대사도 54번 것: "쯧쯧... 미련한 녀석, 고생 많았다.…" (char_2)
- 최종 56번 샷 ← 원래 55번. 붙은 대사도 55번 것: "윤 역관의 누명은 풀렸소. 그대는 명문가의 …" (royal_inspector)
- 최종 58번 샷 ← 원래 57번. 붙은 대사도 57번 것: "저를 키워주신 아버지는 여기 계십니다. 저는…" (char)

쪼개진 형제 샷도 규칙대로였다 — 부모의 대사는 **첫 자식만** 물려받고 동생은 빈 채로 간다
(53번이 쪼개져 53·54가 되면 대사는 53번만, 10번이 쪼개져 10·11이 되면 10번만). 같은 말을 두 번 하지 않는다.

### 계기 결함과 교정 (기록)

첫 실행에서 저장 결과 불일치가 95건으로 나왔다. 두 가지 계기 결함이었고 둘 다 교정했다.

1. 같은 프로젝트의 **이전 런**과 저장 행을 대조 — 저장 행은 프로젝트 단위로 지우고 다시 넣으므로
   이전 런과는 필연적으로 전건 불일치가 된다. → 프로젝트의 마지막 런만 대조.
2. 저장 시 샷 이름이 `shot_N` → `sh_XX_NN`으로 정규화되는데 그대로 대조 → 전건 불일치.
   → 제품 변환기(`writerShotIdToMain`)를 같이 불러 이름 공간을 맞춤.

교정 후 두 계기(조인 검증 / 저장 대조)가 **독립적으로 0건**에 도달했다. 기각 조건은 교정 전후 모두
같은 문장을 썼다(사전 등록 원문 불변).
