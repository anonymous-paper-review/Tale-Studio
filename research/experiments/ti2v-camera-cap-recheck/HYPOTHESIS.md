# 가설 — TI2V 카메라 무빙 캡("둥둥") 재검증

> 사전 등록 2026-08-10. 배경: 카메라 무빙 억압 감사(G3)에서 decoupage.ts:52-53의 캡("이유 없는
> 카메라 무빙은 금지 — 생성 영상이 '둥둥 떠다니며 집중 안 되는' 가장 큰 원인")이 2026-06-04 작성,
> 근거 문서 소실(8/5 대청소), motion-contract(8/7)로 무빙 의도가 모델에 전달되기 **이전** 시절의
> 관측임이 확인됨. 현 기본 모델 + 현 계약문 경로에서 재검증한다.

- **가설**: 현 기본 영상 모델(happy-horse reference-to-video) + motion-contract 경로에서 카메라
  무빙을 moderate급으로 명령해도 "둥둥"(무동기 부유·표류·워블)은 재현되지 않는다 — 캡의 원사유는
  현 스택에서 무효.
- **전제**: ① 캡의 유일 근거는 프롬프트 주석(랩 문서 소실) ② motion-contract는 결정론 컴파일러라
  같은 spec→같은 계약문 ③ START 단일 ref 사용(END 핀은 정지-설계 스트립과 무빙 명령이 충돌하는
  confound라 제거) ④ 프레임·씬 프롬프트·인물 모션은 티어 간 동결, 카메라 절만 변형.
- **예측**: 참이면 — T1(moderate) 클립에서 명령된 무빙(tracking/dolly_in/pan)이 이행되고, 블라인드
  판독의 둥둥 플래그가 T0(LOCKED static 계약) 대비 증가하지 않는다. 거짓이면 — T1에서 무동기
  부유·워블이 다수 관측된다. (T0 자체가 부유하면: 둥둥은 무빙 명령이 아니라 모델 고유 결함 —
  캡의 인과 자체가 성립 안 함, 별도 결론.)
- **측정**: Sample2(6d66cacd) 실사 스트립 3샷 — sh_04_16(질주→tracking), sh_01_02(발견
  인서트→dolly_in, 암시적 수요 전멸 클래스), sh_02_05(설정 와이드→pan, 프롬프트 미명명 타입) ×
  3티어(T0 static / T1 moderate / T2 large) = 9클립, happy-horse 720p, 샷 원 duration(7/5/5s).
  프롬프트는 제품 buildVideoPrompt(계약문 선두)로 생성. 판정: 1fps 프레임열 **블라인드 판독**
  (티어·계약문 은닉 — 카메라 행동 서술 + "무동기 부유/워블로 집중이 흩어지는가" binary) → 코드
  대조로 이행률·둥둥률 산출. 좌표: 요청 payload 전문을 provenance.json에 기록.
- **기각 조건**: T1 3클립 중 2개 이상에서 둥둥 플래그 → 가설 기각 — 캡 유지 + G3(3D 모션 논거)
  영구 종결. T2(large)는 정보용 — large 개방은 별도 결정이며 이 실험의 기각 조건에 불포함.
