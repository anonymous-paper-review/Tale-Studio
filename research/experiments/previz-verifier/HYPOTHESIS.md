# 가설 — previz 검증기 v0 파일럿

> 폼: `research/experiments/_HYPOTHESIS.md` / 심사 규칙: `.claude/rules/experiments.md`

- **가설**: previz 품질을 "설계 질(A) / 설계→그림 전달률(B) / 그림 구도(C)" 축으로 분리해 축별 격리 판정(코드 통계 + 블라인드 LLM 판독)하면, 사람이 previz를 보고 내리는 진단(어느 스테이지가 문제인지)과 일치하는 리포트가 나온다.
- **전제**: 설계 JSON은 `writer_runs.state->shotDesign`에, 3프레임은 `shots.rough_storyboard.frames`에 보존됨(2026-08-05 코드 실측). 스케치의 색·얼굴 소거는 사양이므로 결함으로 채점하지 않는다.
- **예측**: 참이면 축별 점수가 갈리고(전 축 동점이 아님) 지목된 결함 샷을 사람이 봐도 수긍한다. 거짓이면 B축 판독이 사람 판독과 어긋나거나(스케치 판독 불가) 축 점수가 무차별해진다.
- **측정**: 프로젝트 1개 전 샷. B축 = 블라인드 VLM 판독 vs 설계 JSON 코드 대조 정합률. A축 = 규칙 체크리스트 충족률(코드 트리거 + LLM 의미 판정). C축 = 구도 체크. 종단 = 리드백 beat 커버리지.
- **기각 조건**: B축 판독에서 샷 사이즈·인물 수·모션 방향의 명백한 오판(사람 확인 기준)이 30%를 넘으면 "프론티어 VLM 스케치 판독" 접근을 기각하고 전용 모델(ShotVL 계열) 검토로 전환.
