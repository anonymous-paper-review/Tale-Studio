# 방문자 계측이 로그인 문턱에 튕기고 있지 않은가

**판정: 사전 등록 규칙대로 "판정 불가(NA)".** 수집 경로에 요청을 보내니 **404**가 왔다.
티켓이 미리 정해둔 대로 404는 기각으로 세지 않는다.

**다만 걱정의 핵심은 풀렸다.** 같은 구역의 계측 스크립트 파일이 **로그인 문턱을 안 거치고 정상(200)으로
내려온다.** 즉 **"계측 경로가 로그인 페이지로 튕긴다"는 상황은 아니다.**

- 날짜: 2026-08-12 (밤 러너)
- 지출: $0 (쿠키 없는 GET 4회 — 상태 코드·헤더만 기록, 쓰기·POST 없음)
- 기각 조건 발동: **없음** (404 → NA로 분류, 사전 등록 조항)

## 실제 응답

| 무엇 | 응답 | 읽는 법 |
|---|---|---|
| 통계 수집 경로 | **404** | 로그인으로 튕기지 **않았다**. 다만 왜 404인지는 이 방법으로 못 가린다 |
| 계측 스크립트 파일 | **200 ✅** | 같은 구역이 문턱을 안 거친다는 직접 증거 |
| 보호된 페이지(대조) | **307 → 로그인** | 문턱 자체는 정상 작동 중 |
| 공개 랜딩(대조) | **200** | 정상 |

## 무엇이 확인됐고 무엇이 안 됐나

**확인된 것 — 문턱은 이 구역을 안 막는다.**
계측 스크립트가 로그인 없이 200으로 내려오고, 바로 옆의 보호 페이지는 정확히 로그인으로 튕긴다.
두 결과가 나란히 나온 것이 중요하다 — 문턱이 꺼진 게 아니라 **이 구역만 예외 처리가 먹고 있다는 뜻**이다.
어제 넣은 예외 처리는 살아 있다.

**확인 안 된 것 — 실제로 기록이 쌓이는가.**
수집 경로의 404는 두 가지로 읽힐 수 있고, 이 티켓이 허용한 방법(읽기 전용 GET)으로는 못 가린다.

1. 그 경로는 원래 **기록을 보낼 때(POST)만 응답**하고, 그냥 열어보면(GET) 404를 주는 종류일 수 있다.
2. 아직 배포가 안 됐거나 경로가 다를 수 있다.

티켓이 POST를 금지하므로(실데이터 오염 방지) 여기서 멈추는 게 맞다.

**추가 관측 하나** — 랜딩 페이지의 최초 HTML에는 계측 스크립트 참조가 **보이지 않았다.**
이것도 두 가지로 읽힌다(브라우저가 나중에 붙이는 방식일 수 있음 / 계측이 실제로 안 붙었을 수 있음).
읽기 전용으로는 못 가린다 — **NA**.

## 다음에 필요한 것 (실행 안 함)

"기록이 쌓이는가"를 닫으려면 **대시보드에서 오늘 방문 수가 0이 아닌지 한 번 보는 것**이 가장 싸다.
그건 오너 계정 영역이라 러너가 손대지 않는다(티켓 금지 조항). 대시보드가 0이면 그때 이 티켓의
남은 절반(POST 경로 확인)을 다시 열면 된다.
