# 가설 — 참조 이미지가 러프 그림에서 "같은 방"을 붙잡는가 (배경 뷰 자산화의 전제 검사)

> 사전 등록 2026-08-11. 오너 동의(기각선 2/3) 후 등록.
> 위치: 3D 블록아웃 트랙과 **경쟁이 아니라 전제 검사** — 뷰 시트(I2I)든 3D 스냅샷이든 전달 채널은
> 동일하게 "참조 이미지"다. 이 채널이 러프 양식에서 작동하지 않으면 3D 스냅샷도 같은 이유로 실패한다.
> 출처: [[2026-08-10-background-view-3d]] §3 미결 "뷰 시트 실험" · 밤 러너 `t0-v6-background-ref-trace`(최종 생성도 무방어 확정)

- **가설**: 러프 스토리보드 생성에 **로케이션 사진을 참조로 추가하면**, 서로 다른 씬에서 독립 생성된
  같은 장소의 샷들이 **같은 물리적 공간으로 유지된다**. (현재는 배경이 텍스트 한 줄뿐 — 참조 0장)
- **전제**: ① 현행 러프 경로는 이미 `reference_image_urls`를 쓴다(그리드 템플릿 1장) → 사진 1장 추가는
  구조 변경 없이 배열 원소 추가(실측: `src/app/api/writer/rough-storyboard/route.ts:422-430`).
  ② 문제는 재현돼 있다 — 같은 법정(Sample1 `location`)이 씬 6·7·9에서 목조 법정/시민회관풍/기둥 고전
  법정으로 각각 다르게 그려진 것이 시각 확인됨. ③ 로케이션 사진은 존재한다(`locations.wide_shot` 1장,
  `establishing_shot`은 전부 null). ④ 스타일 오염(실사 사진 → 흑백 러프 이탈)이 실제 위험이며 이 실험의
  감시 항목이다.
- **예측**: 참이면 — 처치군 3장이 서로 같은 방으로 판별되고(페어 3쌍 중 2쌍 이상), 흑백 러프 마네킹
  양식이 유지된다. 거짓이면 — 참조를 줘도 방이 계속 갈리거나(채널 무효), 방은 잡히되 양식이 오염된다
  (대가가 큼).
- **측정**: 픽스처 = Sample1(`9d6efa6d-3216-40b0-8a2c-184ab56f02ec`) 법정 판사석 정면 계열 3샷
  `sh_06_39` · `sh_07_49` · `sh_09_67` (전부 WS/eye_level, 씬만 다름 — 씬 간 드리프트 조건 그대로).
  양 팔 모두 제품 `buildRoughGridCell` + `buildRoughGridPrompt(strip1)` 사용(복붙 금지), **샷당 1회
  독립 생성**(그리드 상호 참조 배제 — 드리프트가 발생하는 실제 조건). 팔 차이는 참조 배열 단 하나:
  · 대조군 A = `[스트립 템플릿]` (현행 프로덕션 그대로)
  · 처치군 B = `[스트립 템플릿, 법정 wide_shot]`
  3샷 × 2팔 = 6장. 판정 = 각 팔의 start 프레임 3장으로 페어 3쌍(6-7, 6-9, 7-9)을 만들어 **눈가림 판독**
  (팔 정보·원본 사진 미제공): "같은 물리적 공간인가" + 일치/충돌하는 건축 요소를 근거로 명시. 판독 3인
  다수결. 부작용 감시(같은 판독에서): 흑백 러프 연필 스케치 양식 유지 여부, 마네킹 인물 규칙 유지 여부.
- **기각 조건 (사전 등록 — 결과 본 뒤 수정 금지)**:
  ① 처치군 같은-방 ≤ 1/3 쌍 → **참조 채널이 러프 양식에서 작동 안 함.** 뷰 자산화의 전달 방식을 재설계해야
     하며, 3D 스냅샷도 같은 채널이라 **3D 승격 근거가 아니라 채널 자체 재검토** 신호.
  ② 처치군 스타일 오염 ≥ 2/3 장(흑백 러프 이탈) → 방은 잡아도 대가가 큼. 참조 형식 변경(실사 대신
     러프화된 뷰)이 선결 과제.
  ③ 대조군이 이미 ≥ 2/3 쌍 같은 방 → 픽스처가 문제를 재현 못 함 = **실험 무효**, 다른 샷 조합으로 재설계
     (기존 시각 증거는 구버전 생성물이므로 현재 코드에서 재현되는지가 이 팔의 역할).
  ④ ①②③ 모두 비발동 + 처치군 ≥ 2/3 쌍 → **"참조가 방을 붙잡는다" 확정.** 뷰 자산화 설계의 전제 성립,
     3D 스냅샷 경로도 같은 전제 위에서 유효 — 다음 질문은 "뷰를 무엇으로 만드나"(I2I vs 3D)로 넘어간다.

**이 실험이 답하지 않는 것 (선긋기)**: 장소당 필요한 뷰 개수(5~8 규격), 시킨 각도가 나오는지(각도 이행),
최종 생성 경로에서의 동작. 전부 별건이며 뷰 자산화가 채택된 뒤의 후속 질문이다.
