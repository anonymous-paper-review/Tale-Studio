# 규칙이 글로만 있고 코드로는 안 지켜지는가

**판정: 가설 유지.** 영상 물리 규칙 8개 중 코드가 실제로 지키게 만드는 것은 **단 1개(12.5%)**다.
나머지 7개는 AI에게 문장으로 부탁만 하고, 어겨도 아무 일도 일어나지 않는다.
사전 등록한 기각선(50% 이상 강제면 기각)에 한참 못 미친다.

- 날짜: 2026-08-12 (밤 러너)
- 지출: $0 (코드 추적만)
- 기각 조건 발동: **없음** (실측 12.5% < 50%)

## 규칙 8개의 실제 상태

| 규칙 | 값 | 문장으로 부탁하는 자리 | 코드가 지키게 하는 자리 |
|---|---|---|---|
| 샷 최소 길이 | 2초 | 6곳 | **없음** |
| 샷 최대 길이 | 8초 | 6곳 | **없음** |
| 샷 절대 상한 | 10초 | 5곳 | **2곳 ✅** |
| 샷당 동사 수 | 2개 | 4곳(문장 직접) | **없음** |
| 움직임 설명 최소 글자 | 50자 | 7곳 | **없음** |
| 움직임 설명 최대 글자 | 80자 | 7곳 | **없음** |
| 첫 장면 설명 최소 글자 | 200자 | 7곳 | **없음** |
| 첫 장면 설명 최대 글자 | 400자 | 7곳 | **없음** |

즉 **"2~8초로 만들어라"는 마흔 번 넘게 부탁하지만, 실제로 잘리는 건 10초를 넘겼을 때뿐**이다.
7초든 12초든 상관없이, 12초짜리가 오면 10초로 깎일 뿐 8초 규칙은 아무도 확인하지 않는다.

## 하나뿐인 강제 장치에도 문제가 있다

10초 상한을 지키는 두 자리는 **규칙 원본을 읽지 않는다.** 각자 자기 파일 안에 숫자 10을 따로 적어놨다.

- 저장 직전 샷 길이를 자르는 자리 — 자기 파일에 `10`을 따로 선언
- 길이를 다시 나눠주는 자리 — 또 자기 파일에 `10`을 따로 선언(주석에 "위와 같은 값 유지"라고 적혀 있다)

규칙 원본 파일은 첫 줄에 "같은 법칙이 스테이지마다 다른 숫자로 표류하던 것을 여기로 모은다"고
적혀 있는데, **정작 강제하는 두 자리가 그 원본을 안 읽고 숫자를 베껴 쓰고 있다.**
원본에서 10을 9로 바꿔도 두 자리는 그대로 10으로 자른다.

## 이게 어제 진단과 맞는가

맞다. 어제의 진단은 **"같은 규칙이 여러 군데에 글로 선언되는데 코드 강제는 맨 끝 꼬리에서 조금"**이었다.
숫자로 옮기면 이렇다 — 부탁하는 자리 **45곳**, 지키게 하는 자리 **2곳**, 그 2곳은 전부 파이프라인의
맨 끝(저장 직전)에 있다. **꼬리에서 조금**이라는 표현이 그대로 맞다.

다만 이 결과가 "3단 구조가 틀렸다"는 결론까지 주지는 않는다. 이 티켓이 채운 건 그 논의의 발밑 사실
하나뿐이다 — **규칙을 강제할 자리가 실제로 비어 있다**는 것. 무엇을 어디서 강제할지는 사람이 정할 몫이다.

## 이 숫자를 어떻게 얻었나 (정직 보고)

자동 탐지만으로는 못 얻었다. 두 번의 자동 통과가 모두 틀렸고, 마지막에 사람 대조로 고쳤다.

1. **1차(상수 이름 추적)**: 강제 0곳. → 그런데 이건 "원본 상수를 읽는 자리"만 본 것이라, 숫자를
   베껴 쓴 강제를 놓쳤다.
2. **2차(숫자 추적)**: 강제 5개(62.5%)로 나와 판정이 **뒤집혔다**. 확인해보니 **전건 오탐**이었다 —
   값 2·8·50이 전혀 무관한 줄(잘라내기 횟수, 렌즈 초점거리 목록 등)에 우연히 등장한 것.
3. **3차(사람 대조)**: 후보 18건을 전부 눈으로 확인해 오탐을 걷어내고, 두 자동 통과가 **놓친**
   진짜 강제 2곳(숫자를 베껴 쓴 클램프)을 찾아 목록에 고정했다.

교훈은 오늘 밤 다른 조사에서도 두 번 나온 것과 같다 — **판정 도구를 먼저 검증하지 않으면
판정이 뒤집힌다.** 이번엔 2차 결과를 그대로 믿었으면 "가설 기각"이라고 잘못 보고할 뻔했다.
