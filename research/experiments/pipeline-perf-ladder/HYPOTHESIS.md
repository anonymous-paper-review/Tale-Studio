# 가설 — decoupage 씬 체크포인트(P0: A+C)의 효과 (버전 사다리 1차)

- **가설**: 씬 커서 체크포인트 + 예산 양보(#scene-checkpoint)를 넣은 v1은, 240s 인보케이션 예산 하에서 17씬 프로젝트를 **완주**시킨다 (v0는 구조적으로 사망). 작은 프로젝트(4씬)에는 회귀(속도 저하·산출 변화)가 없다.
- **전제**: 실패 run(17씬, `3ed26543`)의 씬당 실측 평균 15.4s (2026-08-06 프로브, 429 없음) → 17씬 순차 ≈ 262s > 240s 예산. 완료작 4씬(`6d66cacd`)은 ≈ 62s < 예산. 프로덕션 step 예산은 240s(soft)/300s(hard, steps.ts·step route).
- **예측**: 참이면 — v0(17씬)의 단일 호출 wall이 240s를 넘고(프로덕션이면 사망), v1(17씬)은 모든 인보케이션 wall ≤ 300s로 2개 안팎의 인보케이션에 나뉘어 완주. 4씬은 v0·v1 총 시간 차이 ±20% 이내, 샷 수 동급. 거짓이면 — v1의 어떤 인보케이션이 300s를 넘거나(예산 양보 실패), 4씬에서 유의미한 속도 저하/샷 수 변화가 난다.
- **측정**: 두 프로젝트의 run state를 입력 fixture로 고정하고 제품 `runDecoupage`를 (v0) 예산 미지정 1회 / (v1) `softDeadlineMs = now+240s` 릴레이 시뮬레이션으로 실행. 인보케이션별 wall·처리 씬 수·총 wall·총 샷 수·transient(429 등) 경고 수를 기록. 17씬 각 모드 2회 반복, 4씬 각 1회.
- **기각 조건**: v1(17씬)에서 인보케이션 wall > 300s가 1건이라도 나오면 "예산 양보가 강제 종료를 막는다" 기각. 4씬에서 v1 총 시간이 v0 대비 +20% 초과 또는 샷 수가 씬당 ±2 이상 달라지면 "회귀 없음" 기각. (사전 등록 — 결과 후 수정 금지)

좌표: 모델 축 V = `resolveModels(state.input)` (실행 로그에 기록) · 예산 240_000ms · 대상 run은 각 프로젝트의 최신 run 중 pre-decoupage 산출물(genre·characters·scenes·worldVisual·sceneCinematography) 보유 행.
