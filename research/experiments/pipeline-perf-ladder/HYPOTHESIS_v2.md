# 가설 — 씬 병렬 v2 (동시 4) 의 효과 (버전 사다리 2차)

- **가설**: 동시 4 병렬(v2)은 17씬 decoupage 총 시간을 v1 대비 크게 단축(≈4배)하면서, 안전 속성(모든 인보케이션 ≤ 240s+1씬)·산출 동등성·429 무발생을 유지한다.
- **전제**: 씬들은 상호 독립(decoupageForScene 입력이 씬 단위, 교차 참조 없음)이고 전역 shot_id 재인덱싱은 조립 단계에서 일어난다(1차 실측으로 확인). 씬당 지연 실측 15~16s. 현 Gemini 키의 실측 한도는 미확인(preview 모델 — AI Studio 페이지 확인 전) — 이 실험이 곧 그 탐침이다.
- **예측**: 참이면 — v2(17씬)가 단일 인보케이션 ~65–90s 로 완주, transient(429) 경고 0, 샷 수 동급. 거짓이면 — 429 경고 등장(전역 방어 E 없이는 병렬 불가 판정) 또는 총 시간 단축이 미미.
- **측정**: 1차와 동일 fixture·동일 하네스. mode v2 = concurrency 4 — 17씬 ×2회, 4씬 ×1회. **탐색 런**(사전 등록 판정 밖): 17씬 concurrency 8 ×1회 — 429 임계 탐지용.
- **기각 조건**: ① v2 정규 런에서 429 경고 ≥ 1 → "방어 없는 동시 4는 안전" 기각(E 선행 필요로 판정 전환). ② v2 총 시간이 v1 대비 절반 미달(−50% 미만 단축) → 병렬 실익 기각. ③ 샷 수 씬당 ±2 이상 또는 인보케이션 wall > 300s → 동등성/안전 기각. (사전 등록 — 결과 후 수정 금지)

좌표: 모델 축 V = 1차와 동일(gemini-3-flash-preview) · 예산 240,000ms · fixture: 1차와 동일 run (17씬 `5c5d0c96` · 4씬 `5e6577a1`).

## 재실험 등록 (2026-08-09, #fetch-pool 교란 제거)

2차 v2/v2x8 측정은 **교란 변수로 오염**됐다: 계층 분리 프로브(`research/experiments/gemini-concurrency-probe/`) 실측 결과, Node 기본 fetch 디스패처가 origin당 요청을 사실상 직렬화하고 있었다(동시 4콜 = 8.1→16.7→25.6→34.4s 계단; `undici Agent({connections:64})` 교체 시 8.0~9.5s 완전 병렬). 즉 2차의 "병렬 실익 기각"은 병렬이 실행되지 않은 상태의 측정이었다.

재실험(v2-fixed·v2x8-fixed)은 **가설·예측·기각 조건을 위 사전 등록 그대로 유지**하고, 교란만 제거(디스패처 튠 — 프로덕션 instrumentation.ts 와 동일)한 상태에서 같은 측정을 반복한다. 결과 후 가설 수정 없음.
