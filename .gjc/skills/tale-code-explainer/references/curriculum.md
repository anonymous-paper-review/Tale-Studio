# 학습 경로와 결과물 구성

독자는 프로그래밍 경험은 있지만 TypeScript와 Next.js는 처음이다. 비개발자용으로 단순화하지 않되, 저장소에서 처음 만나는 용어와 책임은 실제 코드와 연결한다. 문법, 아키텍처, 비즈니스 의미를 일반론의 별도 장으로 분리하지 않는다.

완료 후 독자는 코드의 실행 위치, 사용자 행동의 파일·함수 흐름, TypeScript가 막는 잘못된 상태, 현재 책임 분리의 효과와 비용을 자기 말로 설명할 수 있어야 한다.

## onboarding 기본 경로

현재 코드로 다시 근거를 확인한 뒤 아래 순서를 사용한다. 조사하지 않은 단원은 확인된 사실처럼 쓰지 말고 제목·목표·실제 기능 후보·선행 단원만 제시한다. onboarding에는 전체 과정 지도와 첫 단원의 상세 설명을 넣으며, 전체 저장소를 파일별로 설명하지 않는다.

| 단원 | 목표 | 기본 후보와 주의 |
|---:|---|---|
| 0 | 실행 위치와 디렉터리 | 브라우저/서버, `page.tsx`, `route.ts`, 실제 `components`, `lib`, `stores`, `types`, `@/` alias, Server/Client Component를 현재 구조로 확인한다. |
| 1 | 동기 요청 하나 | 결제창 열기가 우선 후보다. 부적합하면 더 작은 실제 요청으로 바꾸고 이유를 쓴다. 입력, route 인증·검사, 판단, 외부 API, 응답, union/narrowing/`async`·`await`를 잇는다. |
| 2 | 클라이언트 상태와 서버 진실 | 실제 store와 대응 서버·DB 경로로 화면 상태, 재접속 상태, 서버에 남아야 할 비밀·규칙, Zustand와 React Query의 실제 역할을 비교한다. |
| 3 | 비동기 생성 작업 | Director 영상 생성이 우선 후보다. 요청, 선행조건, 제출, provider request ID, webhook 또는 polling, DB 상태 전이, 재시도·애매한 실패를 분리한다. |
| 4 | AI 제안과 제품 검증 | Writer 또는 Artist의 실제 경로에서 입력 조립, 모델 호출, 파싱, 허용 목록 검증, 상태 적용, 원천과 파생 결과를 다룬다. |
| 5 | 테스트와 변경 영향 | 앞 단원의 실제 테스트로 제품 약속, 단위 테스트 범위, 브라우저 검증이 필요한 범위, 테스트가 확인하지 못하는 것을 설명한다. |

## lesson

`lesson <번호 또는 제목>`은 onboarding 단원 하나를 자세히 다룬다. 숫자는 위 번호이며 제목은 단원 의미로 해석한다. 각 lesson은 실제 사용자 행동 또는 실제 심볼 하나를 중심으로 하며 일반 TypeScript 예제를 새로 만들지 않는다. 현재 코드 때문에 기본 후보를 바꾸면 그 근거와 이유를 쓴다.

## 디렉터리 설명

다음은 조사 전 가설이다. 현재 디렉터리와 프로젝트 규칙을 확인해 포함하거나 수정하며, 그대로 사실처럼 복사하지 않는다.

| 경로 패턴 | 보통의 분류 | 설명 초점 |
|---|---|---|
| `src/app/**/page.tsx` | Next.js 규칙 | URL 화면과 서버·클라이언트 실행 여부 |
| `src/app/**/layout.tsx` | Next.js 규칙 | 하위 화면의 공유 틀 |
| `src/app/api/**/route.ts` | Next.js 규칙 | HTTP 서버 진입점 |
| `src/components` | 프로젝트 관례 | 재사용 UI·표시 책임 |
| `src/lib` | 프로젝트 관례 | 비즈니스 규칙·외부 연동 |
| `src/stores` | 프로젝트 관례 | 화면 수명보다 긴 클라이언트 상태 |
| `src/types` | 프로젝트 관례 | 공유 데이터 모양 |
| `supabase/migrations` | 프로젝트·Supabase | DB 구조 변경 이력 |
| `tests` | 프로젝트 계약 | 실행 가능한 비즈니스 약속 |

`Next.js가 특별하게 해석하는 이름`과 `프로젝트가 책임 분리를 위해 선택한 이름`은 표·배지·SVG에서 시각적으로 구분한다.

## HTML 절별 계약

| id | 반드시 담을 내용 |
|---|---|
| `overview` | 제목, 모드·대상, 기준 커밋, 생성 시각, 읽은 핵심 파일 수, 근거 상태 범례, 학습 목표, 선행 지식 최대 3개 |
| `architecture` | 실행 위치 SVG, 대상의 전체 위치, 관련 디렉터리·책임, Next.js 규칙·프로젝트 관례, 브라우저·서버 경계 |
| `flow` | 방향 SVG, 단계별 입력·출력·상태 소유자, 동기·비동기·DB 읽기·쓰기 구분 |
| `code-journey` | 흐름 순서의 코드 카드와 카드 간 출력 → 다음 입력 연결 |
| `tradeoffs` | 선택/코드 근거/얻는 것/비용/비교할 대안/변경 영향 표 |
| `check` | 실행 위치·비즈니스 조건·변경 영향을 묻는 정확히 3개 질문과 `<details>` 정답·코드 근거 |
| `evidence` | 읽은 파일·테스트·규칙·런타임, 미확인 사항, 추론만 남은 사항, 한계 |

`확인하지 않은 것`은 비어 있지 않아야 한다. 비어 있다면 조사 범위와 표현이 과장되었는지 다시 점검한다.
