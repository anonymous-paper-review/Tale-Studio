# 코드 선택과 시각화 밀도

하나의 코드 블록은 **설명할 주장 하나가 성립하는 데 필요한 최소 실제 코드**다. 줄 수·함수·파일을 고정 단위로 삼지 않는다. 먼저 “외부 입력을 왜 다시 검사하는가?”, “어디서 무료 사용자를 거부하는가?”, “완료를 왜 webhook에서 확정하는가?”처럼 블록이 답할 질문 하나를 쓴다. 파일 전체나 TypeScript 전체는 질문이 아니다.

## 질문별 기본 단위

| 질문 | 기본 단위 | 설명 방식 |
|---|---|---|
| 문법·표현식 | 1~5줄 | 필요한 줄만 `line-by-line` |
| 조건·비즈니스 정책 | 3~15줄 | 조건 묶음별 |
| 함수 책임 | 5~25줄 | 입력 → 판단 → 출력 |
| 파일 책임 | 심볼·의존 관계 | 지도 뒤 핵심 블록 |
| 요청·데이터 흐름 | 파일별 3~15줄, 2~6개 | 순서도와 연결 |
| 디렉터리·레이어 | 디렉터리 지도 | 프레임워크·프로젝트 규칙 구분 |

블록만으로 입력, 판단 또는 변환, 결과, 중요한 부작용을 알 수 있어야 한다. 필수 타입은 블록을 키우지 말고 별도 블록으로 먼저 제시한다.

## 선택과 분리

1. 각 줄을 빼도 질문에 같은 답이 가능하면 뺀다.
2. 떨어진 원문 범위는 붙이지 않고 별도 카드와 정확한 경로·줄 범위로 쓴다. 생략 범위는 코드 밖에서 밝힌다.
3. 25줄 초과, 비즈니스 결정 둘 이상, 정상·복구 경로 혼합, 브라우저·서버 혼합, 타입·런타임 설명 충돌 중 하나면 나눈다.
4. 줄별 해설은 8줄 이하이고 모든 줄이 다른 학습 가치가 있으며 순서가 결과에 영향을 주고 묶음 설명보다 더 짧고 분명할 때만 쓴다. 그 외에는 2~6줄 의미 덩어리다.
5. 파일 전문은 사용자가 지정했고 40줄 이하이며 책임이 하나이고 모든 줄이 필요할 때만 쓴다.

import, 반복 객체 필드, 명백한 로그는 질문에 필요하지 않으면 설명하지 않는다. 원문에 교육용 주석을 넣거나 원문을 고치지 않는다. 일반 예제는 기본적으로 만들지 않으며 꼭 필요하면 `저장소 코드 아님`으로 명시한다.

## 코드 카드

각 카드는 다음 순서다: **질문**, **비즈니스 의미**, **현재 위치**(실행 경계·레이어·호출자 → 현재 심볼 → 피호출자), **실제 코드**(원문과 `저장소 상대 경로:시작줄-끝줄`), **코드 해설**(`line-by-line`/`block`/`function`/`flow` 배지와 이유), **TypeScript·Next.js**, **채택 효과와 설계 비용**.

TypeScript·Next.js는 그 코드에 실제 등장한 문법·동작과 막는 잘못된 상태 또는 제공하는 실행 동작만 설명한다. 작성 의도가 직접 확인되지 않으면 `현재 코드가 얻는 효과`와 `작성 당시 의도: 근거 미확인`을 분리한다. 코드·문서에 없는 대안은 하나만 `비교를 위한 대안`으로 표시한다.

## 내부 분류별 범위

- **feature**: UI/외부 요청 → route → 판단 → DB·외부 서비스 → 저장 → 화면 반영 중 실제 단계만 추적한다.
- **concept**: 언어, Next.js, 라이브러리, 프로젝트 관례를 구분하고 실제 사용처를 비교한다.
- **file**: 호출자·피호출자·export·상태 읽기/쓰기·부작용·결정·학습 포인트·비대화 위험을 지도화한다.
- **symbol**: 입력·출력·부작용·호출자·피호출자를 먼저 확인하고 하나의 책임을 설명한다.
- **onboarding**: 디렉터리 지도와 대표 요청 흐름을 먼저 보여 준다.
- **lesson**: 실제 행동 또는 심볼 하나를 중심으로 하며 일반 문법 예제를 만들지 않는다.

## SVG 관계

SVG는 장식이 아니다. 상자마다 실제 파일·심볼 이름을 넣고, 화살표는 실제 호출문·진입점·데이터 이동으로 확인한 관계만 나타낸다. 미구현 의도는 점선과 `의도`, 미확인 관계는 연결선 없이 `근거 미확인` 영역으로 표시한다. 코드 카드 위에는 현재 노드를 강조한 전체 흐름 축소 지도를 반복한다.

| 모드 | 필수 그림 |
|---|---|
| onboarding | 실행 위치 지도, 디렉터리 지도와 대표 요청 흐름 |
| feature | 실행 위치 지도, 사용자 행동부터 반영까지의 방향 흐름 |
| file | 호출자 → 현재 파일 → 피호출자 |
| symbol | 입력 → 심볼 → 출력·부작용 |
| concept | 실제 사용 위치 비교도 |
| lesson | 단원 대상의 실행 위치 또는 호출 관계 |
