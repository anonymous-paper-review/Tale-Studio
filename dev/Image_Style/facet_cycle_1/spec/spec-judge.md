# 작업: 원본 vs 템플릿-전용 생성물의 스타일 잔차 판정 (<REF>)

첨부 이미지 3장은 순서대로 (1) 원본, (2) 보드 — 원본을 보지 않고 채워진 템플릿(`filled.json`)만으로 컴파일한 프롬프트(`prompts.md`)로 그린 중립 정물(구·천·금속컵·유리잔·과일·화분), (3) 장면 — 같은 프롬프트에 장면 요약을 더해 원본과 같은 종류의 장면을 그린 것이다. 이 실험의 목적은 "템플릿만으로 원본 **스타일**이 재현되는가"이므로, 원본과 생성물의 스타일 차이만 본다. 내용·대상·개별 배치의 차이는 무시한다(단 투영·구도 문법·시점 높이는 스타일이다).

이 폴더의 `filled.json`과 `prompts.md`를 읽고 `residuals.md`를 작성한다. 고유명사 금지. 다른 파일 수정 금지. 외부 검색 금지. 최종 메시지에 `residuals.md` 전문.

## residuals.md 형식

# 잔차 — <REF>

## 1. 축별 일치도
표 한 개: 축 × (보드 0~5 / 장면 0~5 / 한 줄 근거). 축: 매체 · 선 · 채움 · 명암/그림자 · 색(팔레트·액센트) · 형태 · 정밀도 · 질감/마감 · 조명 · 투영/시점 · 배경/지면 · 장식 · 디테일 밀도 · (인물이 있으면) 인물 방언.

## 2. 잔차 목록
원본과 생성물이 다른 점을 중요도 순으로 최소 8개. 한 항목당: `- [축] 원본: … / 보드: … / 장면: … → 원인 (a|b|c|d): 근거 — 관련 key: 경로`
원인 분류: (a) 템플릿에 그 속성을 적을 key가 없다(새 facet) · (b) key는 있는데 채워진 값이 원본과 다르다(분석 오류) · (c) 값은 맞는데 prompts.md에 반영되지 않았거나 약해졌다(컴파일 손실) · (d) 프롬프트에 있는데 생성기가 무시했다(생성기 한계). 판정은 filled.json과 prompts.md를 실제로 대조해서 한다 — 추측으로 (a)를 고르지 마라.

## 3. 새 facet 제안
(a) 항목마다: 넣을 가지 경로 · key 이름(한국어 대표어) · 이 원본에서의 값 · 주석 초안(여러 문장: 무엇을 가리키는가 / 어떻게 관찰·측정하는가 / 함정). 이 그림의 스타일을 재현하는 데 필요한데 서식에 자리가 없는 속성을 찾는 것이 이 판정의 핵심이다.

## 4. 계층·주석 수정 제안
(b) 항목에서: 주석의 관찰 지침을 어떻게 고치면 값이 맞았을지. key를 옮기기/합치기/쪼개기 제안이 있으면 함께.

## 5. 총평
보드와 장면 중 어느 쪽이 원본 스타일에 가깝고 왜인지 2문장. 이 원본에서 스타일을 결정하는 상위 3축.
