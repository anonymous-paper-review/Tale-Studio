# 2차 리뷰: 스캐폴드 v3 초안 검토 — VLM 실행자 관점

당신은 1차 리뷰(`review.md`)를 쓴 리뷰어다. 그 제안을 반영해 작성된 **v3 초안** `inputs/scaffold-v3.md`를 이번엔 **이 지침을 받아 실제로 이미지를 분석해야 하는 VLM의 입장**에서 검토하라. 결과를 이 폴더에 `review-2.md`로 쓰고 최종 메시지에도 전문을 붙여라.

## 검토 관점 (각 항목마다 구체 위치·문구·수정안 제시)

1. **실행 가능성**: 단일 이미지 1장만 보고 답할 수 없는 축·질문이 있는가(예: 다중 입력 행렬, 반복률). 그 경우 "n=1일 때의 답 형식"이 명시돼 있는가.
2. **모호성**: 두 분석자가 다르게 해석할 문구. 특히 게이트 조건(Style Vector 임계값, `[실측]` 요구), 배경 복원 규칙, 오버라이드 표의 "기본값".
3. **중복·충돌**: 24축 사이, 재질 사전과 #11/#15 사이, 게이트와 #19/#20 사이에 같은 것을 두 번 묻거나 서로 다른 답을 유도하는 곳.
4. **순서 논리**: "분석 순서"가 실제 의존 관계와 맞는가. 캡슐 조립 순서 ①~④가 생성기 프롬프트로서 자연스러운가.
5. **출력 계약 파싱 안정성**: 섹션 헤더·문단 규칙을 VLM이 어길 가능성이 큰 곳(코드블록 유혹, 표 안에 캡슐을 넣는 실수 등)과 방지 문구.
6. **길이·비용**: 이 지침이 VLM 프롬프트로 너무 긴가. 줄일 수 있는 곳(정보 손실 없이)과 절대 줄이면 안 되는 곳.
7. **1차 제안 반영 누락**: `review.md`에서 채택됐어야 하는데 v3에 빠졌거나 왜곡된 항목. 반대로 v3가 1차 제안보다 나아진 점.
8. **refer5 시뮬레이션**: 첨부 이미지(refer5, 화면 촬영 아이소 라인아트)에 대해 v3의 #1·#13·게이트를 실제로 적용하면 어떤 캡슐 문장 ①②가 나오는지 예시를 써라 — 이것이 v2 산출(`inputs/analysis-refer5-v2.md`의 CAPSULE)보다 무엇이 나은지/나쁜지.

## 규칙
- 고유명사 금지. 근거는 v3 본문·1차 리뷰·첨부 이미지·카드 실측만.
- 산출물은 `review-2.md` 하나(150~300줄, 표 위주). 다른 파일 수정 금지, 네트워크 금지.
- 수정안은 **적용 가능한 문구 단위**로("#13 두 번째 문장을 '…'로 교체").

## 출력 형식 (`review-2.md`)
```
# Scaffold v3 초안 2차 리뷰
## 1. 실행 가능성
## 2. 모호성
## 3. 중복·충돌
## 4. 순서 논리
## 5. 파싱 안정성
## 6. 길이·비용
## 7. 1차 제안 대비
## 8. refer5 시뮬레이션
## 9. 수정안 요약 (우선순위 순, 적용 문구)
```
