# Scaffold v3 초안 2차 리뷰
## 1. 실행 가능성
| 위치 | 문제 문구 | VLM 실행자 관점 리스크 | 수정안 |
|---|---|---|---|
| 머리말 2문단 | "모든 값에 신뢰도 태그 `[실측\|추정\|보정\|외삽]`를 붙인다" | 표 전체의 모든 셀에 태그를 붙이면 문장이 길어지고, 값 하나에 실측과 보정이 섞이는 #11·#13에서 태그 위치가 불안정하다. | 머리말 두 번째 문장을 "`값 셀의 첫 토큰은 `[실측]`, `[추정]`, `[보정]`, `[외삽]`, `[해당 없음]` 중 하나로 시작한다. 한 셀에 여러 근거가 있으면 `실측: … / 보정: …`처럼 분리한다.`"로 교체. |
| #4 | "1장이면 `n=1, 부재 영역: …`만 기록" | 24축 표의 #4 행에 무엇을 넣을지는 알 수 있지만 META와 특징 분류에서는 반복률을 요구하지 말아야 한다는 점이 약하다. | #4 끝에 "`n=1에서는 반복률·Core/Variation/Outlier를 계산하지 말고, #4 값은 `[해당 없음] n=1; 반복 검증 불가; 부재 영역: …`로 쓴다.`" 추가. |
| #3 | "외삽 또는 n=1인 Core 후보는 `확인 필요` 표시" | 단일 이미지에서는 거의 모든 Core가 n=1이다. 그러면 모든 Core가 확인 필요가 되어 캡슐 강도가 과도하게 약해진다. | #3 두 번째 문장을 "`표본 자체가 보이는 축은 n=1이어도 `[실측] Core`로 둘 수 있다. 단, 표본에 없는 도메인 방언·LOD·다중 반복성만 `확인 필요`로 표시한다.`"로 교체. |
| #11 | "피부색·그림자색·하이라이트색" | 인물·피부가 없는 단일 이미지에서 피부색을 억지로 외삽하게 만든다. | #11 끝에 "`피부·특정 재질 색이 이미지에 없으면 해당 색은 #14/#15/#23의 `[외삽]`으로 넘기고 #11에서는 `[해당 없음] 표본 없음`으로 둔다.`" 추가. |
| #14 | "아래 표를 전부 채운다. 표본 없는 행은 `[외삽]`" | 11행 전부 외삽하면 VLM이 실제 증거보다 상상 재질 규칙을 많이 만든다. 생성기에는 과지시가 된다. | #14 문구를 "`아래 표 11행을 유지하되, 표본 없는 행은 한 줄로 `[외삽] 표본 없음; 적용 시 #8/#9/#11의 공통 문법만 따른다`라고 쓴다.`"로 교체. |
| #15 | "표본 0이면 `[EXTRAPOLATED]`를 첫 토큰으로 + 인물 2-ref 절을 장면 절로 대체" | 실제 출력 계약에는 장면 절 슬롯이 없다. VLM이 FIGURE_RULES에 장면 절을 섞을 가능성이 크다. | #15 끝에 "`장면 절 대체 내용은 NOTES에 넣고, FIGURE_RULES는 인물 생성 요청이 있을 때만 쓰는 외삽 문단으로 유지한다.`" 추가. |
| #16 | "원경 인물·중경 소품·클로즈업" | 단일 이미지가 원경 소품만 보여주면 클로즈업 규칙은 답할 수 없다. 현재는 클로즈업 표본만 외삽으로 처리하고 원경 인물도 묻는다. | #16 두 번째 문장을 "`관찰된 스케일만 `[실측]`으로 쓰고, 관찰되지 않은 원경 인물·클로즈업·대형 오브젝트는 각각 `[외삽] 표본 없음; 최대 디테일은 관찰된 선/면 문법을 넘지 않음`으로 쓴다.`"로 교체. |
| #22 | "기본값(색=콘텐츠 우선, 나머지=스타일 우선 — 실측)" | 생성기 오버라이드 기본값은 단일 이미지에서 실측할 수 없다. 이전 프로브 기록이 있을 때만 실측이다. | #22의 괄호를 "`기본값(프로브 기록이 있으면 `[실측]`, 없으면 `[추정]`: 색=콘텐츠 우선 후보, 나머지=스타일 우선 후보)`"로 교체. |
| Style Vector | "Style Vector 불규칙성 ≥ 3" | 불규칙성은 현재 접지 후보가 없고 vision 판정이다. 게이트가 수치 조건처럼 보이지만 실제 VLM은 추정값을 만든다. | Style Vector 단락 끝에 "`미구현 축 수치는 게이트 단독 근거로 쓰지 않는다. 해당 축의 본문 행(#8/#19/#20)에 `[실측]` 관찰이 있을 때만 게이트를 통과시킨다.`" 추가. |
| 출력 계약 `## 0. META` | "확인 필요 항목" | 어떤 축이 확인 필요인지, 어떤 사유인지 파서가 안정적으로 꺼내기 어렵다. | META 형식을 "`Capture: … / Artifacts: … / Coverage: n=… / Needs confirmation: #번호 사유; #번호 사유`"로 고정. |
| 출력 계약 `## 4. 특징 분류` | "Core / Supporting / Content-bound 목록" | #1 아티팩트가 Content-bound와 섞이면 후속 누수 게이트에서 소재 누수와 촬영 오염을 같은 오류로 본다. | "`Content-bound` 아래에 `Scene-specific`과 `Artifacts` 하위 bullet을 고정한다.`" 추가. |

## 2. 모호성
| 위치 | 문제 문구 | 다르게 해석될 지점 | 수정안 |
|---|---|---|---|
| #1 | "ⓑⓒ → 촬영 속성 전부 아티팩트(제거)" | 화면 촬영본 안의 그림 자체가 종이 질감이나 회색 바탕을 의도했는지 판단할 예외가 없다. | #1 규칙을 "`ⓑⓒ → 카메라가 만든 캐스트·글레어·모아레·비네팅·흐림은 아티팩트. 다만 그림 내부의 반복 텍스처나 의도된 배경색은 #2/#18/#13에서 별도 근거가 있을 때만 유지.`"로 교체. |
| #2 | "#1의 아티팩트는 별도 목록으로 Content-bound에 넣는다" | Content-bound와 아티팩트를 같은 목록에 넣으면 NEGATIVE에서 원작 소재와 촬영 오염이 섞인다. | #2 두 번째 문장을 "#1의 아티팩트는 Content-bound가 아니라 Artifacts 하위 목록에 따로 넣는다."로 교체. |
| #3 | "`[실측]`(이미지에 직접 보임) `[추정]`(vision 해석)" | VLM은 이미지를 보고 해석하므로 직접 보임과 vision 해석의 경계가 흐리다. | #3 첫 문장을 "`[실측]은 픽셀·형태·반복 표본으로 바로 확인되는 것, `[추정]`은 의도·원인·전이 규칙처럼 해석이 필요한 것`"으로 교체. |
| #8 | "선 색(고정색인가, 면색 종속 어두운 톤인가; 검정처럼 보여도 남색/갈색인지)" | 색상 캐스트가 있는 화면 촬영본에서 검정·남색·갈색 판정이 #1 보정 전후에 흔들린다. | #8에 "`화면/인쇄 촬영본에서는 `실측 선색`과 `보정 선색 후보`를 분리하고, CAPSULE에는 보정 선색만 넣는다.`" 추가. |
| #13 | "순백 또는 의도 근거가 있을 때만 오프화이트" | "의도 근거"가 무엇인지 불명확하다. 배경이 회색인 촬영본에서 분석자마다 순백/오프화이트로 갈린다. | #13 두 번째 문장을 "`의도 근거는 피사체 내부 흰 면과 배경의 색차가 촬영 캐스트 보정 뒤에도 남거나, 배경이 선/면으로 닫혀 독립 색면임이 보일 때로 제한한다.`"로 교체. |
| #19 | "기하 정연함(균일 선·완벽 대칭·등간격)" | 균일 선과 등간격은 정연함이지만, 완벽 대칭은 많은 아이소 장면에서 구도상 성립하지 않는다. | #19 문구를 "`기하 정연함(균일 선·규칙적 간격·정확한 축 정렬)과 구성상 비대칭을 분리해 선언한다.`"로 교체. |
| #20 | "장식 모티프가 Supporting 이상" | Supporting 이상이면 무조건 "uneven irregular rhythm"을 넣으라는 게이트와 연결되어, 등간격 장식 스타일을 오판한다. | #20에 "`산포 리듬은 반드시 `등간격`, `불균일`, `판정 불가` 중 하나로 쓴다.`" 추가. |
| 조건 게이트 | "장식 불균일 산포 절 ... #20 모티프가 Supporting 이상" | 모티프 존재와 불균일 산포가 같은 조건으로 취급된다. | 게이트 조건을 "#20 모티프가 Supporting 이상 and 산포 리듬이 `[실측] 불균일`"로 교체. |
| #22 | "기본값" | 기본값이 스캐폴드 기본인지, 생성기 기본인지, 해당 스타일 기본인지 불명확하다. | #22 시작을 "오버라이드 우선순위: 생성기 일반 기본값, 이 스타일 선언, 유저 지시가 이기는 조건을 분리해 표로 쓴다."로 교체. |
| #5 | "무엇으로 만든 것처럼 보이는가" | 화면 촬영본의 표면 질감과 원래 그림의 렌더링 엔진을 혼동할 수 있다. | #5 끝에 "`#1이 ⓑ/ⓒ이면 촬영 매체가 아니라 촬영된 이미지 내부의 의도 렌더링만 답한다.`" 추가. |
| #21 | "원칙만, 원작 배치 복제 금지" | 원칙과 배치 복제의 경계가 모호하다. 큰 배치 관계를 그대로 말하면 모작 지시가 된다. | #21에 "`고유 대상명·개별 위치·개수는 쓰지 말고, 밀도 중심·여백 방향·겹침 방식만 쓴다.`" 추가. |

## 3. 중복·충돌
| 위치 | 중복·충돌 | 실행 결과 | 수정안 |
|---|---|---|---|
| #10 vs #12 | #10에 라이트 풀, #12에도 라이트 콘/풀 | 그림자·조명 답변이 반복되고 CAPSULE ②에 같은 말이 두 번 들어간다. | #10에서는 "`캐스트 섀도·폼 섀도·접지 그림자만`", #12에서는 "`발광체가 만드는 라이트 풀·콘만`"으로 범위를 나눈다. |
| #11 vs #14/#15 | #11이 피부색·재질 고정색을 묻고, #14/#15가 피부·헤어·액체를 다시 묻는다. | 표본 없는 재질 색이 팔레트 Core로 잘못 승격될 수 있다. | #11의 재질 색 문구를 "`이미지에 실제 표본이 있는 재질 고정색만`"으로 제한한다. |
| #14 vs #18 | 재질 표면 결·섬유·하이라이트와 #18 질감·마감이 겹친다. | 재질 사전과 질감 행이 서로 다른 답을 유도한다. | #18 앞에 "`#14의 재질별 질감 세부를 반복하지 말고, 화면 전체에 반복되는 마감 또는 아티팩트 제외 규칙만 쓴다.`" 추가. |
| #17 vs #16 | 디테일 밀도와 스케일 LOD가 모두 초점부/주변부·소품 디테일을 묻는다. | VLM이 같은 관찰을 두 행에 복사한다. | #17을 "`스케일과 무관한 화면 내 밀도 분포만`"으로 바꾸고, 크기별 생략은 #16으로만 보낸다. |
| #19 vs 조건 게이트 | #19는 기하 정연함을 선언하게 하고, 게이트는 불규칙성 ≥3이면 비대칭 절 삽입 | `균일 선`과 `넓은 비대칭 구도`가 함께 보이는 refer5에서 불필요한 "nothing lines up"이 삽입될 수 있다. | 비대칭 게이트를 "`#19가 선·간격·투영의 불균등을 Core/Supporting으로 판정할 때`"로 좁힌다. |
| #20 vs #24 | #20 금지 모티프와 #24 Content-bound 모티프 금지가 반복된다. | NEGATIVE가 길어지고 원작 소재를 과하게 나열할 수 있다. | #20은 금지 모티프를 "`Content-bound로 보낼 후보`"까지만 쓰고, 실제 금지문은 #24에서 1회만 쓴다. |
| 게이트 vs #19/#20 | 게이트가 `Style Vector`와 본문 행을 동시에 조건으로 쓰지만 우선순위가 없다. | 수치와 관찰이 충돌할 때 어떤 절을 넣을지 불명확하다. | 조건 게이트 위에 "`게이트 판정은 본문 행의 `[실측]` 선언이 Style Vector 추정값보다 우선한다.`" 추가. |
| #24 vs 출력 계약 NEGATIVE | #24는 4범주를 요구하고, 출력은 1문장 "Avoid …" | 4범주를 모두 넣으면 너무 긴 영어 문장이 된다. | NEGATIVE 계약을 "`영문 1문장, 35단어 이내, #24의 해당 범주만 포함`"으로 제한한다. |
| META vs #1/#3/#4 | META가 #1 아티팩트, #3 확인 필요, #4 커버리지를 다시 요약한다. | 요약과 분석표가 불일치할 수 있다. | META는 "`#1/#3/#4의 요약만, 새 판정 추가 금지`"로 제한한다. |
| CAPSULE vs NEGATIVE | CAPSULE에도 "no gradients", NEGATIVE에도 "Avoid gradients"가 들어갈 수 있다. | 같은 금지가 반복되어 프롬프트 비용이 늘고 강조 균형이 흐려진다. | CAPSULE에는 스타일의 긍정 문법을 우선 쓰고, 금지는 NEGATIVE에만 둔다. 단 배경 복원처럼 핵심 게이트 문구는 CAPSULE에 허용한다. |

## 4. 순서 논리
| 위치 | 현재 순서 | 문제 | 수정안 |
|---|---|---|---|
| 분석 순서 4~5 | 투영·형태·경계·채움 후 명암·그림자·조명·팔레트·배경 | 팔레트 보정과 배경 정규화는 #1 직후 결정되어야 #8 선색, #9 채움색, #10 그림자색이 안정된다. | 분석 순서를 "`#1 → #2 → #13/#11 보정 전제 → #3/#4 → #5~#10 → #12 → #14~#21 → #22~#24`"로 조정. |
| #13 위치 | T1 끝 | 배경 복원은 보드 안정화 전제인데 후반에 있어 앞 축들이 회색 캐스트를 스타일로 삼을 수 있다. | #13을 T0 또는 T1 첫머리로 이동하거나, #1에 "`임시 배경 복원값을 먼저 기록하고 #13에서 확정`" 문구 추가. |
| #22 위치 | T3 후반 | 색 오버라이드·strict monochrome은 #11과 캡슐 강도에 영향을 준다. | #11 끝에 "`strict monochrome 후보 여부를 임시 표시하고 #22에서 최종 확정`" 추가. |
| 게이트 판정 | 출력 조립 직전 | 게이트에 필요한 Style Vector가 출력 계약상 #3 섹션에 있다. 실제 작성 순서가 "24축→재질→Vector→분류→캡슐"인지 명시되어야 한다. | 출력 계약 앞에 "`작성 순서: META → 분석표 → 재질 사전 → Style Vector → 특징 분류 → 게이트 판정 → CAPSULE/FIGURE_RULES/NEGATIVE/OVERRIDE/NOTES`" 추가. |

## 8. refer5 시뮬레이션
| 항목 | v3 적용 결과 |
|---|---|
| #1 캡처/표현 계층 | `[실측]` 화면 촬영본. 근거는 전체 회색 캐스트, 약한 촬영 흐림, 배경 밝기 불균일이다. 촬영 속성은 아티팩트로 제거하고 의도된 그래픽 라인아트만 남긴다. |
| #13 배경·지면 정규화 | `[보정]` 보드 배경은 순백으로 복원. 첨부 이미지의 회색 바탕은 카드 실측에서 회색조 top-8 약 90%로 잡힌 촬영 캐스트이므로 틴트 배경으로 유지하지 않는다. 지면은 사실 바닥이 아니라 흰 장 위에 놓인 아이소 장면이며, 접지는 필요한 경우에만 납작한 청색 그림자 면으로 둔다. |
| 게이트: 비대칭 구조물 | 불통과가 맞다. 첨부 이미지는 큰 객체 배치가 비대칭이지만 카드 실측은 균일 얇은 선과 기하학적 클린을 시그니처로 본다. "never perfectly symmetric" 절은 넣지 않는다. |
| 게이트: 선 3단계 위계 | 불통과가 맞다. 카드 실측은 전역 균일 얇은 인디고 아웃라인이며 선 위계 없음이다. v3 문구대로라면 "`uniform line weight everywhere`"를 넣는다. |
| 게이트: 장식 불균일 산포 | 통과. 작은 방울·물결 부호가 넓은 여백에 불균일하게 흩어진다. 단, 항구 고유 조합은 Content-bound로 제외한다. |
| 게이트: strict monochrome | 보드 모드에서는 통과 후보. 색상 다양성은 낮고 액센트 위치가 물·창·선택 면에 제한된다. 유저 순수성 선택이 없으면 콘텐츠 색 지시는 유지한다. |
| 게이트: 배경 순백 복원 | 통과. 화면 촬영본이며 밝은 배경은 아티팩트/Content-bound로 판정된다. "`pure white ground — no gray photographic cast, no moiré`"가 들어가야 한다. |
| 게이트: 물리 사진 질감 유지 | 불통과. 물리 오브젝트 사진이 아니다. |
| 게이트: 인물 방언 | 원본은 무인물이다. 인물 생성 요청 시에만 `[EXTRAPOLATED]` FIGURE_RULES를 쓰고, 보드 CAPSULE에는 넣지 않는다. |

| CAPSULE 문장 | 예시 |
|---|---|
