## 3. 발견

1. **규약은 표적에서 작동했다.** 오너가 지적한 과잉 억측의 직접 원인 — 세지 않은 개수("가닥 5~12", "돌기 6~14", "20개 이상"), 종류 나열로 만든 "많음", 판독 한계 아래를 채운 장르 상식("2단 홍채·글린트 1~3"), 광륜의 어휘화 — 가 채우기에서 전부 사라졌고(검사 위반 0), 프롬프트에서도 사라졌다(캡슐 170 → 110단어, "abundant interior-lines define eyes/lashes/hair/lapels/cuffs/grids/badges" → "Detail budget: sparse; four garment lines, four hair strands"). refer4 T 장면은 원작 대비 ×3.1 과잉 → ×0.85, 명암·배경·장식 축 해소, 광륜·컨페티 0. 대조군 refer2(등급 5)의 디테일은 깎이지 않았다(×2.2 → ×0.8).
2. **세 장 모두 T 장면이 '과소' 쪽으로 넘어갔다(×0.75~0.85).** 원인 셋: ① "at most / maximum" 표현을 생성기가 목표가 아니라 '더 적게'로 읽음, ② 원작 표본(얼굴 82px)의 절대 개수를 얼굴이 3배 큰 출력에 그대로 적용해 체감 밀도가 낮아짐, ③ 등급별 단어 예산이 Core 절을 잘라 별의 형상·직교 패널·헤어 동계열 선·그라디언트 지시문이 캡슐에서 탈락(refer1). → v1.2.1: 개수는 "about N (per figure regardless of size)", Core 절은 예산 면제.
3. **참조가 붙은 프로브에서는 묘사 예산이 무시된다** — 12장 중 과잉 10 · 일치 2 · 과소 0(Codex), ×2~5. 같은 문장이 무참조 T에서는 정확히 작동했다(refer4 모발 4·상의 3, refer2 가닥 17·내부선 18). 참조 이미지 + 복잡한 콘텐츠(스쿠터 부품·코트 주름·카페 소품)가 텍스트 상한을 이기며, 비인물 대상(차량·가구·건축)에 적용할 상한 key도 없다(a). 사이클 3의 발견 "참조 채널이 이기는 축과 캡슐이 이기는 축"의 재확인 — 프로브의 묘사 밀도는 참조가 정하고, T의 묘사 밀도는 텍스트가 정한다.
4. **규약의 부작용(원인 f) 5건이 실측됐다 — 전부 v1.2.1로 반영.** ① 표본 = 가장 큰 얼굴 규칙이 감은 눈 인물을 골라 눈 값이 1로(refer4 채우기, 사이클 중 재측정) → "감은 눈이면 가장 큰 열린 눈에서 센다". ② 16항 '판독 한계 아래는 없다'가 존재하는 속눈썹을 0으로(refer2 → "no lashes" → 반실사 눈) → "판독 불가 ≠ 없음: 있음 — 개수 판독 불가". ③ 18항 단순성 편향이 세지 못한 값이 아니라 보이는 요소(60px 하이라이트 패치)까지 지움(refer1) → 편향은 세지 못한 값에만. ④ 정교화 부정 절이 Core 부호를 금지(refer1 "extra sparkles" → 별 소실) → Core·부호 목록의 부호 금지 금지, 개수로 막음(check_fill 경고 추가). ⑤ 등급 4~5에서 정교화 부정 절을 [해당 없음]으로 두게 해 원작이 쓰지 않는 종류(보케 밭·반복 타일·젖은 반사)가 새어 들어옴(refer2 프로브) → 등급 무관 채움.
5. **refer2 인물 방언 후퇴는 규약이 아니라 컴파일 손실이다.** `인물.눈.처리 = 큰 애니 눈(글린트)`와 `매체.엔진 = 디지털 페인팅 + 셀 경계 혼합`은 채우기에 그대로 있었는데, FIGURE가 "large eyes, narrow chins, three iris tones, one glint, no lashes"로, CAPSULE이 "Smooth airbrushed digital materials"로 실어 생성기가 사실적 초상으로 갔다(사이클 3 FIGURE는 "Exaggerate eyes, large long almonds"). 개수 중심 컴파일이 계열 토큰을 밀어낸 것 → §6 27(눈 처리·엔진 토큰 그대로) + `인물.계열` 신설(애니/카툰/반사실/사실, 자유 서술).
6. **누출은 전 판정에서 뚜렷 0.** 인물 정체성 복제 0/24, refer4 광륜 0/4(사이클 3: 인물 프로브 2/2) — `장식.어휘.결속 유형 = 속성형 → Content-bound + 부정 절` 경로가 작동했다. 경미는 refer1의 별·패널 배색 반복(4, 어휘로 선언된 것)과 refer4 스쿠터의 하늘·도시 배경 공식(1)뿐.
8. **개수의 정의가 판정을 가른다.** refer4 채우기는 규약대로 표본 의상의 구조선만 세어 4(격자·플리츠는 반복 무늬로 제외, proposals.md에 '모호'로 기록), Claude 판정자는 플리츠·단추·카디건 가장자리까지 ≈20으로 셌다. 컴파일은 구조선 4만 "maximum four garment lines"로 실었고 장면 요약은 '제복'을 뺐으므로 T 장면의 의상이 무지 티셔츠가 됐다 — 규약이 틀렸다기보다 반복 무늬(⑦)가 예산 절에 실리지 않은 것. → v1.2.1: ① 구조선과 ⑦ 반복 무늬 선 수를 둘 다 예산 절에 싣는다.
7. **하네스 결함 1 수정**: 정교화 값 "[해당 없음] none"이 태그를 벗긴 뒤 "ne"로 잘려 프로브·T 부정 절에 실렸다(refer2, Claude·Codex 모두 지적) — `build_probe_prompts.py`가 태그를 벗기기 전에 [해당 없음]을 제외하도록 수정. 생성에는 영향 없는 무의미 토큰.

## 6. 오너 판정 요청

- **오차의 방향**: 과잉(사이클 3)과 과소(사이클 4) 중 어느 쪽을 기본 오차로 둘지. v1.2.1은 "about N"으로 중앙을 노리지만, 스타일 재현의 관점에서 "원작보다 조금 성긴 쪽"이 "원작보다 정교한 쪽"보다 안전하다면 "at most"를 유지하고 하한만 보강하는 선택지가 있다.
- **인물 계열 한 단어**(애니/카툰/반사실/사실)를 템플릿에 두는 것 — 장르 이름은 고유명사가 아니지만 "장르 선험 금지"(§4 17항)와 긴장한다. 관찰된 계열을 적는 것과 계열의 보통 값으로 빈칸을 메우는 것은 다르다는 선에서 신설했다(자유 서술).
- refer4 T 장면의 색 악화(의상이 초록·주황·노랑)는 장면 요약이 '제복'을 버린 탓 — 장면 요약 정제 규칙(§6 25)이 고유 소품·로고만 빼야 하는데 채우기가 의상 종류까지 뺐다. 의상 종류를 장면 요약에 남길지(내용) 판단 필요.
