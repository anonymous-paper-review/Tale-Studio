# 캐릭터 facet 템플릿 v0 — 공동 작성 지침 (2026-09-07)

이 문서는 계층별 조사 담당자(서브에이전트) 전원이 따르는 규약이다. 각자 맡은 계층의 jsonc 조각과 조사 노트를 쓴다. 조각은 나중에 한 파일(`facet-character-v0.jsonc`)로 합쳐지므로 **형식을 정확히** 지켜야 합쳐진다.

## 0. 배경 — 이 템플릿이 무엇인가

- Tale-Studio의 facet 템플릿 프로그램: 그림 한 장의 시각 속성을 거의 1:1로 대응시키는 계층 jsonc를 LLM에게 주고 그림을 보고 채우게 한 뒤, 그 산출물만으로 그림을 다시 만든다. 지금까지는 **스타일** 템플릿(`.claude/skills/artist-style-anchor/scaffolds/facet-template-v1.jsonc`, 가이드 `facet-template-v1.guide.md`)만 있었다. 그 안의 `인물` 가지는 "이 스타일이 인물을 그리는 법(방언)"이지, 특정 캐릭터가 누구인지가 아니다.
- 오너의 판단: 캐릭터는 그림에서 정보 밀도가 가장 높은 개체이므로 별도 템플릿이 필요하다. 계층은 변동성 순서로 — **A 정체성(불변) → B 신체(준불변) → C 외장(교체 가능) → D 상태(순간) → E 국소 렌더링(스타일 오버라이드) → F 배치 → G 관계**. 같은 캐릭터를 다른 장면에 재현할 때 어느 층을 고정하고 어느 층을 바꿀지 그대로 쓴다.
- 오너의 조사 원문은 `dev/Image_Style/facet_character/OWNER_NOTES.md`에 있다. 그 골격을 따르되, 조사로 빈 곳을 채우고 잘못된 곳은 고친다(고친 곳은 노트에 적는다).

## 1. 스타일 템플릿과의 경계 (가장 중요)

- **스타일 템플릿 `인물` 가지 = 이 스타일의 모든 캐릭터에 공통인 값**(눈을 점으로 그리는가, 선 위계, 셀 단계 수, 등신의 스타일 기본값 등). **캐릭터 템플릿 = 특정 캐릭터에 고유한 값**(이 캐릭터의 홍채 색, 앞머리 형태, 의상, 지금의 포즈).
- 같은 이름의 속성이 양쪽에 있을 수 있다(예: 눈 하이라이트 개수 — 스타일 관습이기도 하고 캐릭터 고유이기도 하다). 이때 캐릭터 값은 `"스타일 기본값 따름"`을 값으로 쓸 수 있고, 주석에 "스타일 템플릿 `인물.눈.공막·글린트`가 기본값"처럼 경로를 적는다.
- 먼저 `facet-template-v1.jsonc`의 `인물` 가지(그리고 `재질.피부`, `재질.헤어`)를 읽고, 자기 계층에서 겹치는 항목을 조사 노트 §경계에 표로 적는다: 캐릭터 템플릿에 둘 것 / 스타일 템플릿에 둘 것 / 양쪽(캐릭터 값이 스타일 기본값을 오버라이드).

## 2. 형식 규약 (스타일 템플릿 가이드 §3·§4와 동일 + 메타 태그)

- **key** = 속성을 대표하는 한국어 단어·문구. **value** = `"ex. …"`로 시작하는 예시값(초안). **주석** = 같은 줄 끝의 `// …`.
- **모든 리프(값이 문자열인 key)에 주석 필수.** 주석은 여러 문장: 첫 문장 = 무엇을 가리키는가, 다음 = 어떻게 관찰·측정하는가(수치·척도·단위), 마지막 = 함정(있으면). 한 단어 주석 금지.
- **메타 태그 2개를 주석 맨 앞에** 고정 형식으로: `[변동성:불변|준불변|가변][기여도:상|중|하]`. 변동성 = 같은 캐릭터를 다른 장면에 그릴 때 바뀌는가. 기여도 = 사람이 "같은 캐릭터"라고 느끼는 데 얼마나 기여하는가(애니·만화풍 기준 대체로 머리(형태+색) > 눈(색+형태) > 실루엣(등신·체형·의상 실루엣) > 시그니처 액세서리 > 피부색 > 나머지). 예: `// [변동성:불변][기여도:상] 머리카락 베이스 색 hex. …`
- **선택형(enum)**: 메타 태그 바로 뒤에 `[N개 중 1개 선택: 후보1 / 후보2 / … — 분석 근거: <근거>]` (다중이면 `[N개 중 n개 선택: …]`). 후보를 전부 나열한다. **분석 근거는 외부 어휘의 출처**(예: "Danbooru tag group:hair 의 hair_length 계열 6종 + 우리 refer1·2·3 관찰")를 적는다 — 근거 없는 후보 집합은 금지. 닫히지 않은 축은 자유 서술로 두고 `참고 후보: …`만 적는다. 선택형이라도 후보 밖 값은 자유 서술 후 갱신 제안(탈출구).
- 이 템플릿은 오너 방침상 **가능한 한 닫힌 어휘(enum)** 를 쓰고, 계층(가지)마다 자유 텍스트 리프 `"기타"` 하나를 둔다(주석: 후보에 없는 관찰을 적는 곳).
- **값 규칙**: 색은 hex, 크기·길이는 기준(얼굴 높이·신장·캔버스 높이) 대비 비율 또는 등급, 개수는 정수, 각도는 도(°). 값 앞에 신뢰도 태그 `[실측|추정|외삽|해당 없음]` 허용. **작가·작품·프랜차이즈·브랜드·캐릭터 고유명사 금지**(예시값·주석 모두). Danbooru 태그 이름은 어휘로서 영문 그대로 인용 가능하되 특정 작품 전용 태그는 쓰지 않는다.
- 가지(객체)에도 `{ // …` 형태로 한 줄 설명을 붙인다.
- JSON 문법: 문자열 안에서 `"`는 쓰지 않는다(따옴표가 필요하면 ' 사용). 마지막 항목 뒤 쉼표 금지. 주석은 `//`만(`/* */` 금지). 값 문자열 안에 `//`를 넣지 않는다.

## 3. 예시 캐릭터 (전원 공통 — 예시값의 일관성을 위해)

오리지널 캐릭터(고유명사 없음): 인간, 외견 청년 여성, 원형 '기사'. 6.5등신, 마른~보통 체형. 은백색 긴 머리를 높은 포니테일로 묶고 아호게 1가닥, 일자 앞머리에 시스루 느낌, 옆머리 턱선 길이. 붉은 홍채(#c9302c)에 세로로 약간 긴 동공, 하이라이트 원형 1개 좌상. 피부 #f3d9c6. 얼굴형 계란형, 눈 크기 중간, 코는 선 하나, 입은 짧은 선. 상반신 판금 갑옷(#b8bcc4) 위에 청색 서코트(#2446d8, 금색 테두리), 하의 검은 바지, 무릎 부츠(갈색 가죽), 왼손에 흰 장갑. 액세서리: 왼귀 은귀걸이, 목에 붉은 스카프. 장검을 오른손에 쥐고 칼끝을 아래로. 포즈: 3/4 정면 서기, 체중 오른발, 머리는 뷰어 쪽, 시선 뷰어 응시, 왼손은 허리. 표정: 옅은 미소, 눈썹 중립. 배치: 캔버스 중앙, 전신, 발이 하단 8% 지점, 키가 캔버스 높이의 85%. 관계: 왼쪽 뒤에 다른 인물(더 작음)이 이 캐릭터를 보고 있음.
— 자기 계층에 해당하는 값을 이 캐릭터로 채운다. 해당 없는 속성은 `"ex. [해당 없음]"` 또는 `"ex. 없음"`.

## 4. 조사 방법

- 외부 어휘를 실제로 확인한다(가능하면 WebSearch/WebFetch — 도구가 지연 로드면 ToolSearch로 불러온다): Danbooru wiki의 tag group 페이지(hair / eyes / face / body / attire / posture / gestures / expressions / sexual 제외), OpenPose 18·25 키포인트와 COCO 17 키포인트, FACS 액션 유닛 목록, DeepFashion/DeepFashion2 어트리뷰트·카테고리, LIP(Look Into Person) 20 라벨. 웹이 안 되면 지식으로 채우되 노트에 `미검증`으로 표시한다.
- 어휘를 통째로 옮기지 말고 **템플릿용으로 압축**한다: 한 선택형의 후보는 대체로 3~12개. 수백 개짜리 어휘(예: 의상 종류)는 상위 범주를 선택형으로, 세부는 자유 서술 + 참고 후보로.
- 오너 노트의 "번들 태그"(원형·역할, 의상 세트) 개념을 살린다: 상위 번들 리프 + 하위 개별 리프(오버라이드).
- 각 리프의 기여도는 근거를 노트에 한 줄로(예: "Danbooru에서 캐릭터 식별 태그의 대부분이 hair/eyes 계열").

## 5. 산출물 (각자 2개 파일, 다른 파일은 만들거나 고치지 않는다)

1. `dev/Image_Style/facet_character/fragments/<계층>.jsonc` — 최상위가 `{ "<계층 이름>": { … } }` 하나인 객체. 계층 이름은 아래 배정표의 한국어 이름 그대로. 여러 계층을 맡았으면 최상위에 그 계층들을 나란히 둔다. **파일 전체가 주석 제거 후 유효한 JSON이어야 한다**(자체 검사: 주석 줄 끝 `//…` 제거·후행 쉼표 제거 후 json.loads). 검사 도구: `python3 .claude/skills/artist-style-anchor/bin/facet_template.py lint <file>` — 리프 주석 누락·선택형 근거 누락·JSON 오류를 잡는다. 반드시 통과시킨다.
2. `dev/Image_Style/facet_character/fragments/<계층>.research.md` — §출처(확인한 어휘와 URL·규모), §경계(스타일 템플릿 `인물`과 겹치는 항목 표), §선택형 판정(어느 축을 닫았고 왜, 어느 축을 열어 뒀고 왜), §오너 노트 수정 제안(골격에서 고친 곳·추가한 곳), §기여도 근거, §미검증 목록.

리프 수 목표(대략): A 10~14 · B 50~70 · C 40~55 · D 40~55 · E 8~12 · F 8~12 · G 8~12. 초안이므로 완벽보다 **형식 준수와 근거**가 우선이다. 최종 보고에는 리프 수, 선택형 수, lint 결과, §경계 표, §오너 노트 수정 제안만 붙인다.

## 6. 배정표

| 담당 | 계층 이름(최상위 key) | 범위 |
|---|---|---|
| A | `정체성` | 존재 유형·인간형 정도·외견 성별·외견 연령·원형/역할(번들)·고유 식별·종족 파츠 유무 + 템플릿 전체의 메타 태그 체계(변동성·기여도) 정의 초안 |
| B-1 | `신체` 중 `비율·체형`, `얼굴` | B1 등신·데포르메·체형·상대 키 / B2 얼굴형·비율·눈(형태·홍채·동공·하이라이트·속눈썹·눈썹·묘사 수준)·코·입·귀·얼굴 표식·피부 |
| B-2 | `신체` 중 `머리카락`, `파츠·표식` | B3 길이·색·형태(앞/옆/뒷머리·가르마·아호게)·질감·렌더링 / B4 비인간 파츠·손·문양·결손 |
| C | `외장` | C1 의상(레이어별 + 아이템 공통 속성 + 세트 번들) / C2 액세서리(위치별) / C3 소지품·장비 / C4 착탈 표식 |
| D | `상태` | D1 포즈(자세·몸통/머리 방향·시선·팔·다리·동세·키포인트 세미 정량) / D2 표정(감정+강도, 부위별, 만화 기호) / D3 동작 / D4 물리·생리 상태 |
| E·F·G | `국소 렌더링`, `배치`, `관계` | E 전역 스타일 오버라이드(윤곽·셰이딩·디테일 밀도·이펙트) / F 위치·앵커·크기·프레이밍·깊이·가려짐 / G 공간·접촉·주의·상대 크기·상호작용 |

B-1과 B-2는 같은 최상위 `신체` 아래 다른 하위 가지를 쓴다 — 각자 `{ "신체": { "비율·체형": {…}, "얼굴": {…} } }` / `{ "신체": { "머리카락": {…}, "파츠·표식": {…} } }` 로 쓰면 합칠 때 병합된다.
