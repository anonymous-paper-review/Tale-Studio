## 3. 발견

1. **압축 캡슐은 작동한다, 단 압축에서 버린 축이 그대로 잔차가 된다.** 세 판정자 모두 앵커 문장 그대로 결과가 바뀐 것을 확인(흰 지면·무선·무그림자·팔레트 역할·산포). 잔차는 정확히 앵커가 담지 못한 절(4단 명도·유리·곡면·구도·인물 방언)에 몰렸다 → 앵커는 고정 70단어가 아니라 **그 스타일의 Core 축 순서로 채우는 100~120단어**가 맞다.
2. **인물 프로브는 참조 이미지·앵커 어느 쪽도 못 나른다** — 원작에 인물이 없으면(refer5·6) 인물 절이 비거나 외삽이고, 콘텐츠의 어두운 스튜디오·콘텐츠 색이 스타일을 덮는다. 보드 A/B에서 보드가 이겼던 유일한 축이 이것이었다 → 인물 프로브만 보관 보드(인물 칸)를 `[원작, 보드]`로 더하는 혼합 규칙이 필요하다(SKILL.md 단계 3 조건과 일치).
3. **누출은 "프롬프트가 비워 둔 슬롯"에서만 난다** — refer1 귀걸이·신발, 배경 상단 궤적. 표면 지정 가드가 바닥 문양 누출을 막은 것이 확인됐으므로 같은 가드를 장신구·신발·배경 상단으로 확장한다. 그리고 프로브 프롬프트에서 장면 종속 부정 절을 뺀 것은 설계 실수(§4-2).
4. **T 장면은 사이클 2와 프롬프트가 같아 재생성 편차를 잰 셈** — refer5 4.3→4.5, refer1 4.1→4.0, refer6 4.8→4.3(Claude). ±0.5는 시드 편차 범위다. 세 사이클에 걸쳐 재발하는 잔차(선 굵기 절반·hue 시프트·띠 방향·키 절·돌기 절·내부선 부정 토큰)는 컴파일 규칙 미반영(18~27)이 원인이다.
5. **장식 어휘 vs 장면 종속의 경계**가 판정자 간 누출 판정을 가르고(refer6 위치 핀, refer1 별·패널), refer4에서는 채우기 단계가 원작의 정체성 표지(광륜)를 어휘로 분류해 프로브까지 새어 나갔다. 템플릿이 '어휘'로 선언한 부호를 프로브마다 반복하면 식별 표지가 된다 → 장식.어휘에 **개수·자세·반복 허용 여부** key가 필요하다.
