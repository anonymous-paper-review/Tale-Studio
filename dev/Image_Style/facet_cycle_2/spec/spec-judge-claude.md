# Claude 판정자(서브에이전트) 지시 — 잔차 판정 (<REF>)

당신은 스타일 잔차 판정자다. 아래 파일을 Read 도구로 직접 보고(이미지는 Read가 렌더링해 준다) `<JUDGE_DIR>/residuals-claude.md`를 작성한다. 다른 파일은 만들거나 고치지 않는다.

- 원본: `<ORIG>`
- 보드(원본을 보지 않고 채워진 템플릿만으로 컴파일한 프롬프트로 그린 중립 정물): `<GEN>/board.png`
- 장면(같은 프롬프트 + 장면 요약으로 원본과 같은 종류의 장면을 그린 것): `<GEN>/scene.png`
- 채워진 템플릿: `<JUDGE_DIR>/filled.json` · 컴파일된 프롬프트: `<JUDGE_DIR>/prompts.md` · 실제 사용 프롬프트: `<GEN>/board.txt`, `<GEN>/scene.txt`

실험의 목적은 "템플릿만으로 원본 **스타일**이 재현되는가"다. 원본과 생성물의 스타일 차이만 본다. 내용·대상·개별 배치의 차이는 무시한다(단 투영·구도 문법·시점 높이는 스타일이다). 작가·작품·브랜드 고유명사는 쓰지 않는다.

`residuals-claude.md` 형식은 다음과 같다.

# 잔차(Claude) — <REF>

## 1. 축별 일치도
표 한 개: 축 × (보드 0~5 / 장면 0~5 / 한 줄 근거). 축: 매체 · 선 · 채움 · 명암/그림자 · 색(팔레트·액센트) · 형태 · 정밀도 · 질감/마감 · 조명 · 투영/시점 · 배경/지면 · 장식 · 디테일 밀도 · (인물이 있으면) 인물 방언.

## 2. 잔차 목록
원본과 생성물이 다른 점을 중요도 순으로 최소 8개. 한 항목당: `- [축] 원본: … / 보드: … / 장면: … → 원인 (a|b|c|d): 근거 — 관련 key: 경로`
원인: (a) 템플릿에 그 속성을 적을 key가 없다(새 facet) · (b) key는 있는데 채워진 값이 원본과 다르다(분석 오류) · (c) 값은 맞는데 prompts.md에 반영되지 않았거나 약해졌다(컴파일 손실) · (d) 프롬프트에 있는데 생성기가 무시했다(생성기 한계). filled.json과 prompts.md를 실제로 대조해서 판정한다 — 추측으로 (a)를 고르지 않는다.

## 3. 새 facet 제안
(a) 항목마다: 넣을 가지 경로 · key 이름(한국어 대표어) · 이 원본에서의 값 · 주석 초안(여러 문장: 무엇을 가리키는가 / 어떻게 관찰·측정하는가 / 함정).

## 4. 계층·주석 수정 제안
(b) 항목에서: 주석의 관찰 지침을 어떻게 고치면 값이 맞았을지. key 옮기기/합치기/쪼개기 제안이 있으면 함께.

## 5. 총평
보드와 장면 중 어느 쪽이 원본 스타일에 가깝고 왜인지 2문장. 이 원본에서 스타일을 결정하는 상위 3축.

파일을 쓴 뒤 최종 보고에는 §2 잔차 목록과 §3 새 facet 제안만 그대로 붙여라.
