# 작업: 첨부 이미지(refer5.png)의 그림체 분석 → Style Card 작성

당신은 이미지 스타일 분석자(VLM)다. 첨부된 이미지 1장을 보고 아래 [분석 지침]에 따라 그림체를 분석하고, [출력 형식]대로 Style Card를 작성해 **이 작업 폴더에 `analysis.md`로 저장**한 뒤, 최종 메시지에도 그 전문을 그대로 붙여라.

## 고정 규칙 (하네스 제약 — 지침과 무관하게 항상 적용)

- 아래 [계산 통계]는 참고 자료다. 사용 여부와 방식은 [분석 지침]을 따른다.
- 이 폴더의 다른 파일은 읽거나 수정하지 마라. 산출물은 `analysis.md` 하나뿐이다. 외부 검색·네트워크 접근 금지.

### 조건 게이트 — 기본 절 삽입 규칙

**게이트 판정은 본문 행의 `[실측]` 선언이 Style Vector 추정값보다 우선한다.** 미구현 접지 축의 수치는 게이트 단독 근거로 쓰지 않는다. 삽입 문구는 **삽입 시에만** 쓴다.

| 절 | 삽입 조건 | 삽입 문구 (삽입 시에만) | 미충족 시 |
|---|---|---|---|
| 비대칭 구조물 | #19가 선·간격·투영의 **불균등을 Core·Supporting으로 `[실측]` 판정** | "furniture, buildings, props and garments are never perfectly symmetric — nothing lines up in a perfect grid" | 정연함이 시그니처면 "clean geometric regularity" 명시 |
| 선 3단계 위계 | #8 선 있음 **and** 위계 `[실측]` | "outer silhouettes > object interior > background interior thinnest" | 균일 선이 시그니처면 "uniform line weight everywhere" |
| 장식 불균일 산포 | #20 모티프 Supporting 이상 **and** 산포 리듬 `[실측] 불균일` | "uneven irregular rhythm, never evenly spaced" | 생략 |
| strict monochrome (보드) | #11 색상 다양성 ≤ 1.5 **and** 액센트 위치 제한 | "strict near-monochrome: only the listed accent hue" | 생략 |
| strict monochrome (콘텐츠 전이) | 유저 순수성 토글 ON | 동일 | 콘텐츠 색 지시 유지 |
| 배경 순백 복원 | #1 ⓑⓒ **and** 밝은 배경이 아티팩트 | "pure white ground — no gray photographic cast, no moiré" | #13 의도 근거 있을 때만 오프화이트/틴트 |
| 물리 사진 질감 유지 | #1 ⓓ **and** #14 실물 재료 Core | "real photographed craft materials under studio light" | 화면 촬영본엔 금지 |
| 인물 방언 절 주입 | 인물 포함 샷 **and** (#15 표본 있음 **or** 외삽 규칙 명시) | FIGURE_RULES | 무인물 장면엔 생략 |
| 인물 2-ref 절 → 장면 절 | #15 표본 0 | (하네스가 장면 절 사용, NOTES 기록) | 표준 인물 절 |

### Style Vector (0~5, 12축)

| 축 | 접지 | 축 | 접지 | 축 | 접지 |
|---|---|---|---|---|---|
| 선 두께 | 계산(강엣지 %) | 채도 | 계산(HSV) | 공간감 | 추정 |
| 선 변화 | 미구현(선폭 히스토그램) | 대비 | 계산(명도 std) | 빛의 극적 성향 | 추정 |
| 형태 단순화 | 추정 | 가장자리 경도 | 계산(강엣지 %) | 색상 다양성 | 미구현(hue 클러스터) |
| 텍스처 | 계산(플랫 블록 %) | 디테일 | 계산(플랫 블록 %)+추정 | 불규칙성 | 미구현(최근접 거리 분산) |

계산 = `style_stats.py` 현재 수치로 접지, 추정 = vision 판정 `[추정]`, 미구현 = 접지 후보(엣지 방향 분포→#6 투영, 그림자 마스크→#10 포함). 미구현 축 수치는 게이트 단독 근거 금지.

### 출력 계약 — Style Card v3

**작성 순서**: META → 분석표 → 재질 사전 → Style Vector → 특징 분류 → 게이트 판정 → CAPSULE / FIGURE_RULES / NEGATIVE / OVERRIDE / QA_CHECKS / NOTES. 헤더는 아래 제목까지만 글자 그대로 쓰고 오른쪽 형식 설명은 출력하지 않는다. **Style Card 전체를 코드블록으로 감싸지 않는다.**

| 헤더 | 형식 |
|---|---|
| `# Style Card — <run_name>` | |
| `## 0. META` | `Capture: … / Artifacts: … / Coverage: n=… / Needs confirmation: #번호 사유; #번호 사유` — #1/#3/#4의 요약만, 새 판정 금지 |
| `## 1. 분석` | 24행 표, 열 고정 `# / 축 / 값 / 등급 / 신뢰도`. 값 셀 1문장, 줄바꿈·세로줄 금지 |
| `## 2. 재질 사전` | 11행 표 |
| `## 3. Style Vector` | 12축 `축 / 값 / 접지` 표 |
| `## 4. 특징 분류` | `Core` / `Supporting` / `Content-bound` — Content-bound 아래 `Scene-specific`·`Artifacts` 하위 bullet 고정 |
| `## 5. CAPSULE` | 헤더 바로 다음 줄에 **영문 문단 하나**(2~4문장, 문장당 ~35단어). 표·목록·따옴표·코드블록 금지. 조립 순서: ① 매체 + 캡처 제거 전제 + 투영 + 경계/채움(#5 #6 #8 #9) ② "on a restored intentional ground …"로 시작 — 명암·그림자 + 팔레트·분배 + 배경(#10 #11 #13) ③ 관찰된 Core 재질 2~3개 + 표본 없는 재질의 공통 번역 규칙 1개 + 마감/정밀도(#14 #18 #19) ④ 장식이 Core면 포함, Supporting이면 "when decorative marks are used, …" 조건문으로만. 긍정 문법만 — 금지는 NEGATIVE로(배경 복원 절만 CAPSULE 허용). 게이트 통과 절만. 분위기 제외 |
| `## 6. FIGURE_RULES` | 영문 1문단 — #15 (+#16 클로즈업). 표본 0이면 첫 토큰 `[EXTRAPOLATED]` (분석표의 `[외삽]`과 구분) |
| `## 7. NEGATIVE` | 영문 **1문장, 최대 35단어, 세미콜론 금지, "Avoid"로 시작** — #24 해당 범주만 |
| `## 8. OVERRIDE` | `axis / default / style / user override` 4열 표 1개 + `Parameters:` 한 줄 |
| `## 9. QA_CHECKS` | 분석자가 **제안하는 검수 항목** `board / leakage / capture / dialect / override` 5행 표 — 각 행 "확인할 것 1개"(판정 pass/fail은 생성 후 검수자가 채운다) |
| `## 10. NOTES` | 한국어 3문장 이하 운영 메모(생성 프롬프트에 자동 주입되지 않음). 인물 표본 0이면 장면 절 대체를 여기에 1문장. 없으면 "없음" |

**금지**: 작가·프랜차이즈·작품·브랜드 고유명사 — 부정문에서도 금지(후속 생성기가 해당 명칭을 차단하거나 토큰으로 반영할 수 있음). 중립 서술어와 hex만.


## 출력 형식 (`analysis.md` — 지침의 "출력 계약" 표를 따른다. 헤더는 아래 제목까지만 글자 그대로)

```
# Style Card — refer5
## 0. META
## 1. 분석
## 2. 재질 사전
## 3. Style Vector
## 4. 특징 분류
## 5. CAPSULE
## 6. FIGURE_RULES
## 7. NEGATIVE
## 8. OVERRIDE
## 9. QA_CHECKS
## 10. NOTES
```

위 블록은 헤더 이름 예시일 뿐이다 — 실제 Style Card 전체를 코드블록으로 감싸지 않는다. CAPSULE(영문 2~4문장)·FIGURE_RULES(영문 1문단, 표본 없으면 첫 토큰 `[EXTRAPOLATED]`)·NEGATIVE(영문 1문장, 최대 35단어, "Avoid"로 시작)는 각각 헤더 바로 다음 줄에 문단 하나로 적는다 — 표·목록·따옴표·코드블록 금지(파서가 헤더 다음 문단을 그대로 프롬프트에 넣는다).
