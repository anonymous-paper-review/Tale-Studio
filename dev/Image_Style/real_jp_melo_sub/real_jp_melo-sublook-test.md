## 한 줄 결론

**보드는 preview가 파는 룩을 절반만 나른다** — 고키·부드러운 인상은 옮기지만 preview 의 근중립·다색 gamut 은

대가가 크다** — action 에서 **매체가 일러스트로 이탈**(제품 결함급), scooter 에서 구조 붕괴, **3/4 에서 벚꽃·화훼
콘텐츠 누수**(이미지 없이 **텍스트만으로**), 야간 2/2 톤 리프트. **매체 절 1문장을 더한 C 가 매체·구조를 되돌렸고
action 에서는 룩까지 유지했다.** 따라서 판정은 "보드 재제작"이 아니라 **"B 가 닫되, 매체 절과 세트로만"**이다.

## 0. 사전 진단 대조 — preview 실물이 뒤집은 것

착수 지시의 예상: *"멜로는 소프트 광·과노출 하이라이트·저대비 파스텔 서명일 것 — 실물로 확정하라."*
실측 결과 **2/4 가 반증**됐다. preview 는 저대비도 과노출도 아니다.

| 주장 | 판정 | 근거 |
|---|---|---|
| 소프트 광 | ✅ 성립 | 확산 역광 + 헐레이션. 하이라이트거칠기 11.04 (보드 6.00 보다 오히려 거칠지만 육안상 부드러운 역광) |
| **과노출 하이라이트** | ❌ **반증** | preview 과노출 **0.19%** vs **보드 2.02%**. 과노출은 **보드 쪽이 10배**다. preview 의 밝음은 blowout 이 아니라 고키 평균(163.8)이 만든다 |
| **저대비** | ❌ **반증** | preview 대비(V95−V5) **176**, 보드 **139**. preview 는 어두운 벚나무 줄기·담장 그림자를 갖고 있어 **오히려 고대비**다. 저대비인 쪽은 **보드**(그림자바닥 104 vs preview 61) |
| 파스텔 | ✅ 성립하되 **방향이 반대** | preview 채도 **8.3%** = 보드(16.1%)의 **절반**. preview 는 근중립(R−B **+7.2**), 보드는 확실히 웜(**+24.6**) |

→ **멜로의 실제 서명은 "저대비 과노출 파스텔"이 아니라 "고키 평균 + 근중립 저채도 + 다색 gamut + 역광 헐레이션 +
어두운 앵커 요소가 만드는 넓은 다이내믹 레인지"**다. 이 정정이 아래 정합 감사의 축이 된다.

`melo_sig.py`(**이 런에서 신규** — 사유는 §1.1).

### 1.1 계기를 새로 만든 이유

기존 계기(`amber_metrics.py`·`hue_spread.py`)는 **전부 색축**이다. 그런데 이 서브룩의 facet 표가 선언하는 판별축은
**대비 낮음 / 그림자 부드럽고 밝음 / 블룸·필름** — 즉 **톤 커브**다. 색 계기로는 "그림자가 들려 있는가"를 못 잰다.
그래서 `melo_sig.py` 를 새로 썼다: 그림자바닥(V 5퍼센타일) · 대비(V95−V5) · 과노출(V≥250 비율) ·
하이라이트거칠기(밝은 영역의 블러 전후 차이 — 블룸 프록시) · 명도평균.
**이 계기가 이 런의 핵심 판정 대부분을 실어 나른다.**

### 1.2 정합 감사 — preview 가 파는 룩을 anchor 가 나르는가

플레이북 §6 후단이 서브룩 6종에 권고한 유일한 작업이 이것이다. 판정: **부분 정합 (절반)**.

|---|---|---|---|
| 고키·부드러운 광 | ✅ | ✅ | **○ 옮겨짐** |
| 파스텔 인상 | ✅ | ✅ | **○ 옮겨짐** |
| 색온도 | 근중립 (+7.2) | 확실한 웜 (+24.6) | **✗ 어긋남** |

| hue 다양성 | 0.60, 쿨 11.9% | **0.34, 쿨 0.0%** | **✗ 크게 어긋남** |
| 대비·다이내믹 레인지 | 176 (어두운 앵커 있음) | 139 (바닥 104) | **✗ 어긋남** |
| 디테일 밀도 | 강엣지 12.0% / 플랫 7% | 4.1% / 36% | **✗ 어긋남** |

**보드에는 채도 있는 쿨 픽셀이 한 개도 없다(0.0%)** — `real` 보드에서 확인된 **웜 단색 gamut 병증이

**"preview 가 파는 근중립·다색을 보드가 웜 단색으로 바꿔 판다"**는 것이 문제다.

## 2. 설계 (preview arm 없음 — 상한 비교자는 preview 실물 계측)

| | T (베이스라인) | B (룩 절) | C (복구 실험, §6) |

콘텐츠 문장은 `real_3d_v2/probe_*.txt` 를 복사하고 **md5 동일을 확인**했다(런 간 비교 가능):

**T→B 는 정확히 1줄만 다르다**(`diff` 확인) — 단일 변인 설계.

### 2.1 룩 절 원문 (`LOOK_CLAUSE.txt`)

```
Grade the whole image in this look: soft diffuse light, low contrast, with soft, bright, gently lifted
shadows; a muted low-to-medium saturation pastel palette; delicate romantic bloom and halation on the
highlights; fine soft film grain. Mood: a tender, wistful flutter.
```

### 2.2 문안 판단 2건 (기록 — 결과 해석에 직결)

1. **시간대·색온도를 뺐다.** 초안은 facet 표대로 `soft diffuse daylight around 5000K` 였으나 **삭제**했다.
   야간 프로브 2장과 **정면 모순**이라 그대로 두면 야간 결과가 "룩 전이 실패"가 아니라 "텍스트 대 텍스트 충돌"이
   되어 판독 불가가 된다. real_2ref §4.3 이 이미 "씬 조명 텍스트가 보드를 이긴다"를 확정했으므로 그 축을 다시
   재는 것은 무가치하다. **대가**: "5000K 봄 주광"이라는 facet 항은 이 런이 검증하지 않는다.
2. **국적·계절·장소를 뺐다.** 원 앵커 프롬프트의 `Mood: … a gentle Japanese romance film` 대신
   `Mood: a tender, wistful flutter` 로 중립화했다. "Japanese"를 넣으면 G-figure 의 인종 강제 측정이
   선점되고(자기실현), 벚꽃·봄 콘텐츠 누수가 절 자체에서 유입된다. **이 통제 덕분에 §5.3 의 벚꽃 누수가
   "국적어 없이도 발생한다"는 강한 결과가 됐다.**

### 2.3 게이트 정의

- **G-look** — 멜로 룩 서명(고키·부드러운 광·저대비·파스텔·블룸)이 산출물에 나타나는가. **나와야 통과.**
- **G-time** — 프로브가 명시한 시간대(야간 2장, 늦은 오후 1장)가 보존되는가.
- **G-skeleton** — 사물·인체 구조가 무너지지 않는가.
- **G-figure** — 인물이 자연스러운가 + **일본인 특정 인종을 강제하는가**(별도 기록).

## 4. 게이트 판정

### G-look — **T 실패(1/4 통과) · B 통과(4/4) · C 부분(1/2)**

T 는 보드의 "따뜻하고 밝고 부드러운" 인상만 옮긴다. 그것은 `real`(기본 실사) 앵커의 거동과 **육안 구분이 어렵다** —
즉 **서브룩이 상품으로 파는 차별성이 산출물에 서지 않는다.** cafe 만 예외인데, 이는 콘텐츠(밝은 실내 창가)가
보드 구도와 겹쳐 우연히 정합한 경우로 읽는 편이 안전하다.

### G-time — **T 통과(3/3) · B 부분 실패(야간 2/2 훼손)**

- T: scooter·action 야간 유지(명도 78.3 / 89.2), cafe 늦은 오후 유지.
- B: cafe 유지. **야간 2장이 명도 140.8 / 145.1 로 리프트** — 램프가 켜져 있고 노면이 젖어 야간 단서는 남지만,
  전체 인상은 **"안개 낀 여명/황혼"에 가깝다.** 시간대가 지워지진 않았으나 **약화됐다**.
- C: **야간 복원** — scooter 87.3(T 78.3 수준), action 136.2(B 보다 −8.9, 여전히 밝음).

### G-skeleton — **T 통과(4/4) · B 실패(scooter) · C 복원(2/2)**

- `b_scooter`: 스쿠터 차체가 **뭉개져 덩어리로 융합** — 레그실드·핸들바·리어박스 경계가 소실. 헤이즈·블룸이

## 5. 관전점 — 멜로 시그니처는 야간 액션과 얼마나 싸우는가

한눈 비교: **`night_collision.png`** (T | B | C × scooter·action)

**결론: 싸운다. 그리고 룩이 이기면 매체가 진다.**

1. **T 에서는 싸움이 아예 안 일어난다** — 보드가 야간 씬에서 룩을 못 실으므로 충돌할 것이 없다.
   대신 앰버 단색 붕괴가 일어난다(`t_scooter` hue_H **0.06**, 쿨 0.0% — 젖은 노면의 하늘 반사·원경 형광 같은
   실사 야간 어휘가 통째로 없다). 이는 `real` 보드에서 확인된 병증(real_2ref §4.2)의 **서브룩 재현**이다.
2. **B 에서 싸움이 터지고, 룩이 이긴다** — 그림자바닥 +55/+57, 명도 +62/+56. 야간이 "안개 낀 파스텔 여명"이 된다.
3. **그 승리의 대가가 매체와 구조다** — `b_action` 은 실사를 잃었고(`medium_drift.png` 원해상도 확인),
   `b_scooter` 는 차체가 녹았다. 즉 **"부드러운 멜로 광이 야간 무드를 죽인다"보다 정확한 서술은
   "멜로 광을 텍스트로 강하게 밀면 live_action 매체 자체가 무너진다"**이다. 후자가 더 심각하다 —
   무드 훼손은 미학 문제지만 매체 상실은 플레이북 §7 이 `stop_motion` 에서 **제품 결함급**으로 분류한 축이다.
4. **이 서브룩의 실전 리스크는 야간 콘텐츠다.** 낮·실내 씬(cafe·character)에서는 B 가 매체를 유지하며
   룩만 얹는다. 리스크는 **어두운 씬에서 룩 절이 톤을 들어올릴 때** 집중된다.

### 5.1 철회한 주장 1건 (계기가 육안을 반증)

첫 육안 인상은 *"B action 은 모션 블러가 사라져 속도감이 죽었다"*였다. **`motion_aniso.py` 로 재면 성립하지 않는다** —
배경 띠의 수평 모션 블러 지표 `aniso(Sx/Sy)` 가 T **0.973** vs B **0.925** 로 **B 가 오히려 더 이방적**이다.
`action_pair.png` 로 재확인하니 B 도 머리카락·스카프가 강하게 뒤로 흩날리고 배경 보케가 흐른다.
**주장을 철회한다.** B action 이 정지해 보인 것은 모션 소실이 아니라 **톤 리프트 + 매체 이탈이 만든 무드 전환**이었다.
(기록 사유: 육안 인상 위에 진단을 쌓지 않기 위함.)

### 5.2 콘텐츠 누수 — **텍스트가 벚꽃을 소환한다 (3/4)**

**이 런에서 가장 예상 밖의 결과다.**

| 산출 | 화훼 요소 |
|---|---|
| t_character · t_cafe · t_scooter · t_action | **0/4 — 전무** |
| b_character | 없음 (플랫 배경) |
| **b_cafe** | 카운터에 **흰·분홍 꽃가지 화병** |
| **b_scooter** | 화면 우측 **만개한 벚나무** |
| **b_action** | 좌우 **개화한 관목**, 핑크 스쿠터·핑크 가방·핑크 스카프 |

**refs 는 T·B 동일하게 보드 1장뿐이고, 보드에는 꽃이 없다**(여린 녹색 묘목·블러시 천·로즈 유리잔이 있을 뿐).
프롬프트 차이는 **룩 절 1줄뿐**이며, 그 절에는 벚꽃·봄·일본·꽃이라는 단어가 **하나도 없다**(§2.2 에서 의도적으로 제거).
용의자는 `romantic` + `bloom` + `pastel` 의 결합이며, 특히 **`bloom`(광학 용어)이 문자 그대로 개화로 읽혔을**
가능성이 높다.

→ **real_2ref §6 의 "누수는 이미지 몫, 확정"은 서브룩에서 성립하지 않는다.**
거기서는 텍스트 절(B)이 누수 0이었고 preview **이미지**가 범인으로 확정됐다. 여기서는 **이미지 없이 텍스트만으로
콘텐츠가 새어 들어왔다.** 횡단 규칙에 단서가 필요하다: **룩을 파는 절은 그 룩의 상투적 소품을 함께 소환할 수 있다.**
운영상 함의: 룩 절을 쓸 때 `bloom` 같은 **광학 용어와 사물 명사가 동음인 단어를 피하라**(예: `highlight glow and
halation`). 이건 무비용 수정이고, 검증 1샷이면 확인된다.

## 7. 이 실험의 한계 (반증 가능성 유지)

1. **표본 각 1장.** 프로브당 n=1, C 는 2장뿐. 게이트 통과/실패 모두 확률적 요동을 배제 못 한다.
   특히 §6 의 "룩 유지 1/2" 는 재현 확인 전이다.
2. **§5.2 의 벚꽃 누수는 강하지만(3/4, T 0/4) 단일 문안 1종의 결과다.** `bloom` 단독 기여를 분리하지 않았다 —
   `bloom` 만 교체한 대조 1장이면 확정된다. **미집행.**
3. **§2.2 로 인해 이 런은 facet 표의 "5000K 봄 주광"·"일본" 항을 검증하지 않는다.** 프로덕션 절이 그 단어를
   포함한다면 결과가 달라질 수 있다(특히 인종·계절 축).
4. **preview 를 refs 에 넣지 않았다** — 설계상 preview arm 없음. 따라서 "preview 를 배선하면 gamut 이 열리는가"는
   이 런이 답하지 않는다. 다만 형제 런 5종이 **preview 배선 전부 기각**으로 수렴했으므로(플레이북 §7) 재시도 가치는 낮다.
5. **G-look 은 육안 판정이다.** `melo_sig.py` 가 접지를 주지만 "룩이 섰는가"의 최종 판단은 주관이며,
   **최종 미학 판정은 오너 몫**(스킬 규정).
6. **higgsfield / gpt_image_2 결과다.** 프로덕션(fal)에서 재현된다는 보장이 없다.

### 7.1 부수 발견 2건

- **§5.0 WebP 함정이 5번째로 재현됐다.** `hf_image.sh` 산출 **10장 전부** `file` 판정 **WebP 2048×2048**.
  `_v.png` 가 PIL 재인코딩된 진짜 PNG 1024 다. 업로드·배포에는 `_v.png` 만 쓸 것.
  래퍼 수정 제안(real_3d_v2 §6C.1)이 **여전히 미반영**이다.
- **429 는 워크스페이스 전역 제약이며 비용 0이다.** 첫 배치(4장 병렬)에서 3장이 `rate_limit_reached`
  (`concurrent_jobs_limit: 8`)로 실패했다 — 이 세션에서 형제 서브룩 에이전트 5종이 동시 생성 중이라 발생한
  **자원 경합**이며 프롬프트 문제가 아니다. **제출 단계에서 거부되므로 잡이 생성되지 않아 크레딧 소모 0**
  (로그 `log_t_cafe.txt` 확인). 직렬 실행으로 전환하니 10/10 이 1회 시도에 통과했다.

## 8. 권고

**3중 판정: "T 충분" ❌ / "B 가 닫음" ⭕ (조건부) / "보드 재제작" ❌ (지금은 아님)**

1. **T 는 충분하지 않다.** 보드는 서브룩이 파는 차별성을 야간·인물 씬에서 나르지 못하고(G-look 3/4 실패),
   산출물이 기본 `real` 앵커와 육안 구분되지 않는다. **서브룩의 상품성이 서지 않는다.**
2. **B 가 닫는다 — 단 매체 절과 반드시 세트로.** 룩 절 단독은 룩을 4/4 복원하지만 매체 상실·구조 붕괴·
   콘텐츠 누수를 함께 가져온다. **매체 절 1문장이 그 대가를 2/2 되돌렸다**(§6).
   → 프로덕션 후보는 **`룩 절 + 매체 절` 쌍**이며, 플레이북 §7 이 이미 제안한 "anchor medium 별 텍스트 절"
   자리에 같은 방식으로 주입하면 된다. **live_action 서브룩 6종 공통으로 매체 절이 필요할 가능성이 높다** —
   서브룩의 룩 절은 전부 그레이드를 세게 미는 문안이 될 것이므로 같은 매체 이탈 위험을 공유한다.
3. **룩 절 문안에서 `bloom` 을 교체하라 (무비용).** §5.2 의 벚꽃 누수 용의자다.
   `delicate romantic bloom and halation` → `delicate glow and halation on the highlights` 류로 바꾸고
   1샷 확인. 이건 이 런이 남긴 가장 값싼 개선이다.
4. **보드 재제작은 지금 권하지 않는다.** 보드는 정합이 완벽하진 않지만(§1.2) **틀리지 않았고**, 룩 실패의
   주된 원인은 보드 품질이 아니라 **I2I 이미지가 그레이드를 강제하지 못한다는 구조적 사실**이다
   (real_2ref §4.3 이 확정). 보드를 다시 구워도 텍스트가 이기는 축은 그대로다.
   **단 재제작한다면 목표는 "더 예쁜 보드"가 아니라 gamut 이다** — 쿨 0.0%·hue_H 0.34 를 preview 수준
   (쿨 11.9%·0.60)으로 여는 것. 색은 조명이 아니라 오브젝트에 넣는다(플레이북 교훈 3: 청색 소품 추가).
   우선순위는 위 2·3 아래다.
5. **야간 콘텐츠를 쓰는 프로젝트에 이 서브룩을 붙일 때 주의를 문서화하라.** 이 룩의 실전 리스크는
   야간 씬에 집중된다(§5). 낮·실내는 안전하다.
6. **fal 재검증 1샷 전에는 성공 주장 금지** (플레이북 §5-6). 특히 §6 의 매체 절 효과는 n=1×2 다.
