## 3. 발견

1. **템플릿의 측정된 가치는 양수다 — 단 생성기와 스타일에 따라 크기가 다르다.** 12건 중 10건 Δ > 0, 평균 GPT +0.63 / NB2 +0.41. 가장 큰 이득은 참조가 못 나르는 것에서 왔다: 무대막·패널 기하, 장식 부호의 어휘와 개수, 투영(얕은 포스터 레이어), 무광·무접지·성긴 디테일 같은 생성기 기본값 소거. 참조가 이미 나르는 것(선의 유무·얼굴 방언·팔레트)에는 텍스트가 거의 보태지 못했다(Δ ≈ 0).
2. **Nano Banana 2는 텍스트를 문자 그대로 사물화한다.** hex 두 색을 우상단 색 견본 2칸으로 그리고(refer4 액션), 광점 개수를 스티커 별로, 사선 파편을 기하 절단면으로 옮기며, 앵커가 길수록 참조의 렌더링을 버리고 플랫 벡터 포스터 모드로 간다(refer2 −0.33). 수치 제약(선 굵기 %·명도 단계·밀도 예산)은 무시하고 키 절만 부분 준수. → NB2용 컴파일 변형이 필요하다: hex 대신 색 이름, 개수 대신 정성어, 앵커 60~80단어, 등급 4~5 페인터리 스타일에는 앵커 최소화(R0에 부정 절만).
3. **GPT Image 2는 텍스트를 방향으로 따르되 지나치게 문자 그대로도 따른다.** 표정 개수·절대 휘도 같은 장면 사실까지 지시로 실행해 단독 캐릭터를 5인 시트로, 밤을 낮으로 바꿨다. 수치 절은 방향만 따르고 도달하지 못하며(선 굵기·근흑·5단), 천을 삼각 파셋으로 그리는 기본값이 강하다(refer2). 잔차 원인은 (d) 생성기 무시 48%, (c) 컴파일 손실 29%.
4. **참조 채널 자체의 한계(g)가 NB2에서 20%, GPT에서 7%.** NB2는 참조를 매체 수준(셀 + 선)까지만 따르고 hard 인물·soft 무선 배경의 층별 분리, 다단 페인터리를 나르지 못한다. 이 축들은 텍스트로도 못 고쳤다(refer2 채움 Δ 0~−1.0).
5. **분해 정확도 D는 8~11/11.** 불일치는 개수 정의(구조선 vs 주름 포함), 표본 지목(refer2 22개가 지목 표본이 아닌 중앙 인물 값), 판독 한계 아래 눈 요소(3 vs 5)에서 났다. C 전달률은 Core 83~100%.
6. **누출은 텍스트 때문에 난다.** R1 뚜렷 3건은 전부 앵커·인물 절이 원작의 관찰을 지시로 옮긴 것(표정 분포·군상·배경 레이아웃)이고, R0는 refer4 NB2 액션의 네온 글자꼴 1건뿐. 참조 이미지의 정체성 누출은 0.
7. **하네스**: 동시 잡 한도(8)와 503 오류로 2장 재생성, Claude 판정 1건 API 오류 재실행. 첫 컴파일의 예산 폭주(§6 23 절대 상한으로 수정).

## 5. 오너 판정 요청

- **생성기 선택**: 등급 1~3(선·셀 계열)은 두 생성기 모두 템플릿이 값을 하지만 GPT가 더 크게, 등급 4~5(페인터리)는 NB2에서 템플릿이 해를 끼친다. NB2를 계속 쓴다면 NB2 전용 컴파일 변형(#3)을 만들지, 아니면 NB2에서는 R0 + 부정 절만 쓸지.

- 다음 사이클 범위: v1.2.2 반영 후 같은 3장 × 2 생성기(≈230크레딧)로 Δ 재측정, 또는 GPT만으로 refer5·6 무인물 스타일 확장.
