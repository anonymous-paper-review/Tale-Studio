## 공통 재현·검증 방식

### 테스트 환경

- 개발 프로젝트·테스트 계정을 사용하고 실제 사용자 원본을 실험으로 덮어쓰지 않는다. 환경별 DB·키 매핑은 CLAUDE.md가 우선한다.
- 기본 fixture: 한국어 콘텐츠 프로젝트, 쿄타로·코마츠 2인, 기본 낮 학교 옥상, 새 밤 모습, 여러 씬에 나뉜 47샷. 외형 상태 검증에는 서로 구분되는 기존 테스트 이미지를 사용한다.
- 응답 순서를 통제한다: 정상, 두 번째 대상만 실패, 응답 지연 중 탭 이동, 접수 후 응답 유실, 중복 승인, 새로고침, 프로젝트 전환.
- 이미 마련된 product store/route/도메인 함수를 실행한다. 명령 배열 추출이나 소스 문자열 존재만 확인해서 전체 흐름을 검증했다고 쓰지 않는다.
- 실제 생성은 입력·저장·선택 검증이 끝난 후 대표 사례로 확인한다. 기존에 허용된 테스트/비용 범위를 적용하고 별도의 유료 대량 생성을 암묵적으로 추가하지 않는다.

### 검증 명령

```bash
# 관련 파일부터 실행한다. 아래는 첫 작업(MVP-25)의 기존 관련 테스트 예시다.

# 커밋 전 공통 확인

```

모든 묶음을 매 항목마다 반복할 필요는 없다. 관련 검증→필요한 통합 검증→커밋 전 공통 검증 순서로 진행한다. 실패는 변경 전 기준과 비교해 기존/신규를 구분하되 조용히 무시하지 않는다. CLI 의존성 문제 때문에 명령이 실행되지 않은 것을 제품 테스트 실패나 통과로 기록하지 않는다.

화면 확인은 [.claude/skills/smoke/SKILL.md](../.claude/skills/smoke/SKILL.md)의 실제 방법을 따른다. 로그인 뒤 Studio 화면을 확인해야 하며 공개 랜딩 smoke로 대체하지 않는다.

```bash
# 현재 화면의 실제 문구와 구조를 먼저 읽는다.
pnpm smoke /studio/writer --auth --tree
pnpm smoke /studio/artist --auth --tree
```

읽은 화면에만 있는 실제 문구를 `--expect`로 지정해 다시 확인하고, 탭 이동/승인 흐름은 실제 상호작용으로 검증한다. smoke의 종료 0은 전제 미충족 skip일 수도 있으므로 보고서를 확인한다. URL만 맞거나 로그인 화면만 열린 결과는 통과가 아니다. `.smoke/`의 결과는 덮어쓸 수 있으므로 항목별 증거 폴더로 복사해 보존한다.
